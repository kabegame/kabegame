# CEF patches

## Upstream

- Repository: <https://github.com/chromiumembedded/cef.git>
- Vendor base: `0d0eeb61160536e447c79335c1ee963f57eb6d60` (branch `7827`)

## Patches

- `0001-flat-subprocess-path.patch` — honors an explicit browser subprocess path for every child process type, allowing Kabegame to use one flat helper executable on all desktop platforms.
- `0002-drag-drop-client-events.patch` — extends `CefDragHandler` with `OnDragOver` / `OnDragLeave` / `OnDrop` (all `added=experimental`) so a client can observe a full external drag sequence and consume the drop. Without this, CEF only exposes `OnDragEnter`, whose sole power is cancelling the whole drag — leaving no way to get a drop notification and suppress Chromium's default handling (navigating to the dropped file). Wiring:
  - `AlloyBrowserHostImpl` overrides `content::WebContentsDelegate::PreHandleDragUpdate` / `PreHandleDragExit` → `OnDragOver` / `OnDragLeave`. The update notification carries no operations mask, so the mask captured in `CanDragEnter` is remembered in `current_drag_operations_mask_`.
  - `ChromeWebContentsViewDelegateCef` overrides `OnPerformingDrop` → `OnDrop`; returning true runs the completion callback with `std::nullopt`, which aborts the drop before it reaches the renderer. This is the equivalent of wry's `performDragOperation` returning `YES` without calling `super`.

  Scope note: `OnDrop` rides on `WebContentsViewDelegate`, which is not created for windowless (OSR) browsers — see the comment in `CefBrowserPlatformDelegateAlloy::AttachHelpers`. Kabegame uses windowed CEF Views browsers, so this is not a limitation in practice, but an OSR embedder would still get `OnDragEnter`/`OnDragOver`/`OnDragLeave` and no `OnDrop`.

  The generated C API, `libcef_dll` cpptoc/ctocpp glue and API hashes are **not** part of this patch — they are produced by `tools/version_manager.py` during `cef_create_projects.sh`, which `scripts/build-chromium.ts` runs.

- `0003-drag-source-filenames.patch` — lets a CEF client turn a renderer-initiated drag into a drag of real local files, on Linux, macOS and Windows. Chromium always clears renderer-supplied `DropData::filenames`, so the patch adds a `WebContentsViewDelegate::GetDragFilenames` hook before the platform drag payload is built. CEF exposes that hook through `CefDragHandler::OnStartDragging`, and adds `CefDragData::GetCustomData` so the client can inspect custom formats set by `DataTransfer.setData()` before adding authorized local paths.

  The platforms need different amounts of Chromium-side work. On Linux (and Windows, which shares `web_contents_view_aura.cc`) the payload is pushed into an `OSExchangeDataProvider` up front, so `WebContentsViewAura::StartDragging` only has to swap in the filenames. macOS pulls instead: `WebContentsViewMac::StartDragging` forwards `DropData` over mojo to `WebDragSource`, an `NSPasteboardWriting` object that answers flavor requests lazily — and it had no filenames path at all, so the patch also teaches it to advertise and serve `NSPasteboardTypeFileURL`. `filenames` needs no mojo change: `IPC_STRUCT_TRAITS_MEMBER(filenames)` already carries it. macOS additionally has to clear `download_metadata` and `html`, which Linux ignores but `WebDragSource` would turn into a promised-file flavor and a `public.html` flavor.

  macOS also has to drop the renderer taint. Linux keeps it in a member of `OSExchangeDataProviderNonBacked` that never crosses a process boundary; macOS writes it onto the pasteboard as `org.chromium.renderer-initiated-drag`, where a receiving Chromium reads it back as `DropData::did_originate_from_renderer` and `FilterDropData()` then drops every filename. Left on, the file reaches native apps but is invisible to Chrome, to every Electron app and to the embedder's own webview. The patch therefore stops advertising that flavor once the delegate has vouched for local files — the paths are not renderer data, and every renderer-authored payload is cleared alongside them.

  The Windows half reuses the aura hook (gate `IS_LINUX || IS_WIN`; ChromeOS stays out): `OSExchangeDataProviderWin::SetFilenames` turns the injected filenames into a plain `CF_HDROP` of the real paths, which Explorer copies on drop with no delay-rendered download or temp directory. Like macOS it must clear `html` (it becomes `CF_HTML`, which Word / Outlook / OneNote prefer over `CF_HDROP`) and `download_metadata` (it would make `PrepareDragForDownload()` add a second, delay-rendered `CF_HDROP` — the `DownloadURL` path this replaces; the reset is a no-op on Linux), and it must not mark the data with `chromium/x-renderer-taint`: `OSExchangeDataProviderWin` writes the taint as a real clipboard format that crosses process boundaries like the macOS flavor, so `PrepareDragData()` gains a `mark_renderer_tainted` parameter (default `true`) and the delegate branch passes `false` on Windows only.

  The Chromium-side patch (`patch/patches/kabegame_drag_source_filenames.patch` plus its `patch.cfg` entry) and the CEF-side API changes are two halves of the same feature and must be added or removed together.

  The generated C API, `libcef_dll` cpptoc/ctocpp glue and API hashes are **not** part of this patch — they are produced by `tools/version_manager.py` during `cef_create_projects.sh`, which `scripts/build-chromium.ts` runs.

- `0004-per-browser-file-access.patch` — lets a client turn on `WebPreferences::allow_file_access_from_file_urls` for a single browser instead of the whole process. Chromium keeps that preference per `WebContents`; the global `--allow-file-access-from-files` switch only seeds its default, and `CefBrowserSettings` does not expose it. The patch reads the bool key `kabegame.allow_file_access_from_file_urls` from the browser's creation-time `extra_info` dictionary inside `ChromeContentBrowserClientCef::OverrideWebPreferences`, right after `SetCefPrefs`. `CefBrowserHostBase::InitializeBrowser` calls `NotifyPreferencesChanged()` once the browser is attached, so the flag is in place before the first navigation commits.

  Kabegame uses it for Wallpaper Engine web wallpapers, which are loaded from their own directory as `file://` and read sibling files with `fetch` / XHR, the same way WPE loads them. Without the preference every `file://` document has an opaque origin and those reads fail. With it, the document can read **any** `file://` URL, so the embedder must confine loads itself; Kabegame cancels `file:` requests outside the wallpaper directory in `OnBeforeResourceLoad`, mirroring WPE's own resource interceptor. Cross-origin `http(s)` requests are still subject to CORS, because the network service reads `--disable-web-security` from the global command line; this patch deliberately leaves that alone.

  No public API, C API or `libcef_dll` glue changes: the key travels in the existing `extra_info` dictionary that `CefBrowserHost::CreateBrowser` / `CefBrowserView::CreateBrowserView` already accept.

- `0005-app-page-local-resources.patch` — lets a client allow one browser's app page (the non-`file:` document in the outermost main frame of a non-popup browser) to load `file:` URLs, e.g. as an `<iframe>` `src`, via the bool `extra_info` key `kabegame.allow_local_resources`. 0004 lets `file:` documents read `file:`; 0005 lets a non-`file:` page embed it. Chromium blocks that in two independent places, and the patch opens both:
  - Renderer: `SecurityOrigin::CanDisplay()` refuses `file:` for non-local origins ("Not allowed to load local resource"). `CefRenderManager::MaybeCreateBrowser` reads the key before `extra_info` is moved into `OnBrowserCreated` and keeps it on `CefBrowserImpl`; `CefRenderFrameObserver::DidCommitProvisionalLoad` calls the new `blink_glue::GrantLoadLocalResources` on every non-`file:` commit of the outermost main frame, before `OnDidCommitProvisionalLoad()` can run queued script. Blink creates a new origin per committed document, so the grant follows the document.
  - Browser: `FilterURL` in `RenderFrameHostImpl::BeginNavigation` rewrites `file:` to `about:blank#blocked` for a process without request rights. `CefBrowserInfo::MaybeCreateFrame` calls `ChildProcessSecurityPolicy::GrantRequestScheme(file)` for every outermost main frame host's process, before the "frame already known" early return, covering speculative hosts, process swaps and crash/reload. The grant is request-only, idempotent and has no revoke.

  Documents committed in popups (including DevTools, which copies the opener's `extra_info`), OOPIFs (their process also hosts a `CefBrowserImpl`, hence `IsOutermostMainFrame()`) and fenced frames are never granted. Two inheritances are Blink's own, not the patch's: same-origin `about:blank` / `srcdoc` children alias the parent's origin object, and a popup's *initial* `about:blank` document inherits `CanLoadLocalResources` from its opener (`DocumentLoader::CalculateOrigin`, the sandboxed-`about:blank` branch) — verified on Windows: `window.open("about:blank")` from a granted page can embed a `file:` iframe until the popup commits a real document, after which the `is_popup` exclusion applies. Neither adds reach beyond what the granted page already has through `parent` / `opener`, and a popup keeps the opener's `CefClient`, so the embedder's `OnBeforeResourceLoad` guard still applies. The browser-side grant is per process; a popup sharing the opener's process passes `FilterURL` but is still stopped by `CanDisplay` once it commits. `CanRequest()` is untouched, so the page's own `fetch` / XHR of `file:` still fails, and `<img src="file:...">` still fails for lack of a file URLLoaderFactory. The patch only opens the door; Kabegame confines which `file:` URLs load in `OnBeforeResourceLoad`, as with 0004. This mirrors Android WebView (`AwContents::GrantFileSchemeAccesstoChildProcess` + `grant_load_local_resources`). `//cef` only: no Chromium-side patch, public API, C API or `libcef_dll` glue changes.

- `0006-app-page-file-subresources.patch` — completes 0005 for subresources. Patch 0005 lets the app page pass `CanDisplay` and `FilterURL`, but `RenderFrameHostImpl::CommitNavigation` only hands a `file:` subresource URLLoaderFactory to documents with a `file:` precursor scheme, so `<img src="file:...">` in an `http(s)` / custom-scheme page still ends in `ERR_UNKNOWN_URL_SCHEME`. `ChromeContentBrowserClientCef::RegisterNonNetworkSubresourceURLLoaderFactories` (new override, parent called first so Chrome's IWA / extension factories stay) adds `content::CreateFileURLLoaderFactory` for the outermost main frame of a non-popup browser created with the same bool `extra_info` key `kabegame.allow_local_resources` (the key check is a private copy, so 0005 and 0006 do not depend on each other's code); workers and service workers (`kRoutingIdNone`, no `RenderFrameHost`), subframes and fenced frames get nothing, and `emplace` is a no-op for `file:` documents. `GetParentOrOuterDocument()` is used rather than `IsInPrimaryMainFrame()` because the host being committed may still be speculative. The factory is wrapped by `WillCreateURLLoaderFactory` like any other, so the client's `OnBeforeResourceLoad` still sees every request — Kabegame lets the app page's own subresources through and confines `file:` frames to their directory there. Each factory instance receives a private `SharedCorsOriginAccessList` that permits only the committing document's origin to read `file:` with CORS mode. The profile-wide list is unchanged. The client must also register `CefAddCrossOriginWhitelistEntry(origin, "file", "", true)` to pass the CEF proxy's earlier CORS check. `DownloadManagerImpl` uses the main frame's factory for `file:` downloads; Windows drag-out no longer uses `DownloadURL` (see 0003). `//cef` only; no public API, C API or `libcef_dll` glue changes.

- `0007-document-url-headers.patch` — captures the owning document URL and parent document URL when CEF creates each proxied URLLoaderFactory. A document subresource factory uses the single pending cross-document navigation, or the committed URL when none is pending; navigation factories use the current document. Ambiguous or failed navigations remain unattributed. `OnBeforeRequest` strips all incoming `Sec-Kabegame-*` headers, then writes `Sec-Kabegame-Document-Url` and `Sec-Kabegame-Parent-Document-Url` on non-http(s) requests (empty values mean unknown). The embedder can attribute IPC and `file:` requests without racing `CefFrame::GetURL()`. It also removes the unproxied `file:` factory from workers created by `file:` documents, so worker reads fail closed. Changes stay inside `//cef`; no public API, C API, or `libcef_dll` glue changes.

Apply this series manually before running CEF's `patcher.py`:

```bash
deno task patch cef
```

## Re-vendor

1. Run `deno task patch cef -r` to restore the clean vendor tree.
2. Update `third/cef` to the desired commit from the upstream repository.
3. Apply each patch with `git apply --check`, repairing context drift as needed.
4. Regenerate the numbered patch files against the new vendor base and update this README.
