# 场景壁纸：光照、反射、阴影与体积光

> [场景壁纸文档](../WPE_SCENE.md) 的一章：光照、反射、sprite 对象、阴影、体积光、雾、灯的运行时（P13）。总体形态、各阶段状态与全部章节的索引在总览里。

## 光照（`#require LightingV1`）

调查与对比数据见 [lighting-REPORT](../../../.claude/plans/wpe-import/3-scene/lighting-REPORT.md)。

- `#require` 在 WPE 里是**预处理期现场生成源码**，不是文件引用：`LIGHTING` 非 0 时按 `LIGHTS_*` 生成灯光 uniform 与 `PerformLighting_V1`，否则什么都不插。
  `genericimage4` 顶层那条无条件的 require，在 `LIGHTING=0` 时等于空行。逐灯的 PBR 计算在公开头文件 `common_pbr_2.h`，翻译器 `library.rs` 只负责遍历灯。
- **灯数不看灯对象**：`LIGHTS_*` 取 `general.lightconfig`，每种灯 4 位。灯对象只负责填数组：多的丢掉，少的槽位全 0。没有这个键的场景里灯对象不起作用，开了 `LIGHTING` 的材质只剩环境光。
- **`"light": "point"` 是遗留灯**，不进这些数组；V1 灯是 `lpoint` / `lspot` / `ltube` / `ldirectional`。
- 宿主 `compile/lights.ts` 把灯对象整理成编译期记录（`bundle.lightObjects`，绑了 `{user}` 的数值字段登记就地目标，P13f2），渲染器每帧按 `SceneState` 现组灯记录、按视线方向排序、照 WPE 写整块灯光缓冲（P13d 起，见「阴影（P13d）」与「灯的运行时（P13f2）」），宏经 `litDefines` 传给翻译器，只在最终 `LIGHTING` 非 0 时生效。
- 光照路径自己的宏只有 `LIGHTS_*`。`SHADERVERSION` 是翻译器的平台宏（69），`genericimage3` 按它选公式。
- **全局引擎宏**（[hdr-macro-REPORT](../../../.claude/plans/wpe-import/3-scene/hdr-macro-REPORT.md)）：`HDR`、`SCENE_ORTHO` 经 `engineDefines` 传给全部着色器，关闭时不写键：`common_blending.h` 用 `#ifdef HDR`，传 0 会让 LDR 场景也走 HDR 分支。`REVERSEDEPTH` 恒为 1（P13c，WPE 用反向深度；见「sprite 对象（P13c）」）。`TEX<n>FORMAT` 只给声明了 `formatcombo` 且按名字绑定的槽位定义，运行时槽位（`previous`、`bind`、passthrough）不定义。`HLSL_GS40_DISABLED` 不能定义，WPE 没有这个宏。
- **边界**：无 effect 图层直接上屏时算光；开光照或反射的普通图层走合成路径（effect、colorBlendMode 混合、被依赖、开雾）时 P13j 起走预光照（基础 pass 换成 `PRELIGHTING=1` 的变体 `SceneLayer.prelit`，渲染器写 `g_AltModelMatrix`（图层世界矩阵，instanced 乘 size / 图像尺寸）、`g_AltNormalModelMatrix`（逐行快速归一化）、`g_AltViewProjectionMatrix`（图层上屏的视图投影），四边形与正交按合成 RT 尺寸，[phase-13j-prelighting](../../../.claude/plans/wpe-import/3-scene/phase13/phase-13j-prelighting.md)）；puppet（P13j-2）的变体另带 puppet 组合键（没有 `SKINNING_ALPHA`，skinned 时加 `PRELIGHTINGDUALVERTEX`，`a_PositionC1` 读位置那一项）、`nocull`，基础 pass 画整张网格进合成 RT（原始位置定光栅位置、蒙皮后的位置算光照，画前不清 RT，同 WPE），纹理通道 + 光照仍报 `puppet:texture-channels:prelighting`；effect 自己开光照报 `lighting:effect`（点光、平行光的阴影 P13d 起支持，聚光阴影 P13i、聚光 cookie P13k 起支持），体积光报 `object:castvolumetrics`，`genericimage2` 开光照报 `uniform:g_LightsPosition`。
- 本机语料没有一张真的开 `LIGHTING`，这条路径靠 `ignore/lighting/` 的测试工程和 WPE 1:1 对比（最大差 1）。普通图层带法线图时另有 UV 内缩的差异（已知，最大 10）。
- 粒子（`genericparticle` / `genericropeparticle`）P4i 起也开光照：走同一块灯光缓冲与同一组引擎 uniform，见 [PARTICLES_SCRIPT_MODULES.md](PARTICLES_SCRIPT_MODULES.md)「粒子（P4i）」。

## 反射（P13b1：设置与「反射关」；P13b2：平面反射开；P13g：屏幕空间反射开）

读码与实测见 [rea-p13-passes](../../../.claude/plans/wpe-import/3-scene/phase13/rea-p13-passes.md) 第 1、4 节与 [p13-REPORT](../../../.claude/plans/wpe-import/3-scene/phase13/p13-REPORT.md)「P13b1 的实测」「P13b2 的实测」「P13g 的实测」，计划与走查见 [phase-13b1-reflection-off](../../../.claude/plans/wpe-import/3-scene/phase13/phase-13b1-reflection-off.md)、[phase-13b2-reflection-on](../../../.claude/plans/wpe-import/3-scene/phase13/phase-13b2-reflection-on.md)、[phase-13g-screen-reflection](../../../.claude/plans/wpe-import/3-scene/phase13/phase-13g-screen-reflection.md)。

- **设置「场景反射」**（`wpeSceneReflection`：`follow` 缺省 / `disabled` / `enabled`；宿主收父页面下发的值，见 [COMPILE.md](COMPILE.md)「场景后处理档位」的「设置来源」）：跟随时读 WPE `config.json` 的 `general.user.reflection`（缺键、读不到、不是布尔都当开，`compile/postprocess.ts` 的 `resolveReflection`）。WPE 这一个设置同时管平面反射与屏幕空间反射；值变了宿主整场重新加载。只在场景里有读者时才读 `config.json`。
- **两张运行时 RT**（`compile/bundle.ts` 的 `REFLECTION_RT` / `MIP_FRAMEBUFFER_RT` 进 `bindRuntime`，渲染图的纹理来源 `{ kind: "reflection" }` / `{ kind: "mip-framebuffer" }`，`render/graph.ts` 的 `runtimeInput` 统一翻译；RT 在 `render/reflection.ts` 的 `ReflectionTargets`）：
  - `_rt_Reflection`：只有**模型**的网格材质读它时才建（WPE 的触发条件），`bundle.reflection.planar`。场景目标尺寸（WPE 是窗口尺寸）、`rgba8unorm`（HDR 下也是），Clamp + Linear；反射关时每帧在主 pass 之前清成 `(clearcolor, 1)`（和主目标同一个清屏色：按指定尺寸画、对齐方式 1 / 3 时是 `schemecolor`，p13-REPORT「P13b2 补测」），不看 `clearenabled`，HDR 的大于 1 的清屏色在 8 位上截到 1。同一场景里图像层 / 粒子读它绑同一张。**没有模型读、只有图像层或粒子读**时 WPE 不建，那一槽绑 6×6 黄黑棋盘格占位（编译期在全部对象编完后回改成静态纹理 `checkerIndex()`）。
  - `_rt_MipMappedFrameBuffer`：任何对象读到就建，`bundle.mipFramebuffer = { update }`（`update` 是编译期解析好的「反射开」）。场景目标尺寸（WPE 是窗口尺寸）、格式跟场景目标（HDR 时 `rgba16float`），mip 数 `max(1, min(log2(npot(w)/2), log2(npot(h)/2)) − 2)`（1920×1080 为 8、1600×900 为 7），Clamp + 三线性；反射关时建好后各级清成 `(0, 0, 0, 1)` 一次、之后不动。绑它的槽的 `g_Texture<n>MipMapInfo`（float）是引擎 uniform，值为 mip 数（`features.ts` 的 `isMipMapInfoOf`），别的槽照报 `uniform:*`。
- **屏幕空间反射开**（P13g，`ReflectionTargets.encodeMipFramebuffer`）：每帧在顶层对象（含体积光的最后一次合成）画完之后、泛光快照之前（WPE 帧函数 `0x140180aa0` / `0x140180b87`，在 `_rt_FullFrameBuffer` 的拷贝之后），把场景目标整张 `copyTextureToTexture` 进 0 级，再逐级各一个 render pass 缩小（WPE 是 `ResolveSubresource` + D3D11 `GenerateMips`）。读它的对象（`generic4` 等的 `REFLECTION` 分支 `texSample2DLod(g_Texture3, …, roughness · g_Texture3MipMapInfo)`）在主 pass 与反射 pass 里读到的是**上一帧**泛光前的画面（抓帧：读者 draw 时 0 级里帧号块是上一帧，拷贝之后是本帧；HDR 下 > 1 的值保留）。开着时建好不清屏（WPE 只在关时清；新纹理两边都是 0，只影响第一帧）。运行中切换设置照旧整场重新加载（WPE 是原地改、关掉那一刻清黑）。
  - **缩小的滤波**（`MIP_DOWNSAMPLE_WGSL`，抓帧逐级反推）：`GenerateMips` 的滤波由驱动定（rea-p13-passes 4.3 只确认了调用），本机 NVIDIA 驱动是「硬件双线性 + 定点坐标」：目标纹素 j 在上一级的坐标 `(j + ½) · s/d − ½`，缩放系数先向下截到 2⁻²⁴（`mipDownsampleScale`）、乘积精确、坐标再**向下**截到 1/256（WebGPU 的采样器自己是就近取 1/256），交给硬件线性采样。偶数边就是 2×2 平均；奇数边（1080 高的 135 → 67、67 → 33，1366 宽的 683 → 341 …）上理论落在整数的那一行略小于整数、落到下一对纹素上。只用硬件采样（就近取坐标）第 4、5 级有约 1% 的分量差 1 级，只截系数还剩那一行；照上面的规则 1920×1080、1366×768、HDR（半精度）三种的各级与 WPE 逐值相同。乘法拆成高低两段免得超出 u32（`mipSourceCoord256` 是同式的 TS 实现，单测与 BigInt 精确值逐个比）。别的厂商的驱动滤波可能不同，那时 WPE 自己的画面也不同，不追。
- **照报**：没有屏幕空间反射的照报项了（P13g 之前反射开时报 `reflection:screen`）；平面反射开见下一条，只有名单里反射 pass 画不了的种类照报。
- **平面反射开**（P13b2，`compile/reflection.ts`、`render/views.ts`、`render/scene.ts` 的反射 pass）：
  - **名单**（C1，编译期定、`bundle.reflection = { planar, enabled, list }`）：可画对象里 `reflected` 不为 false、且不是「读 `_rt_Reflection` 的模型」（一个网格读就整个对象排除）的，按 `objects` 顺序；反射 pass 只画名单，不做透明排序。`reflected` 绑用户属性时登记成重编译（`layer-structure`，已定 2），对所有对象中性、不再报 `object:reflected`。
  - **支持的种类**（已定 1）：模型、直接上屏的图像层与文本层、普通粒子。名单里别的种类报 `reflection:planar:<种类>`（`reflectionKind`）：`group`（组与组里的图层）、`shape`、`perspective`（`perspective: true` 的图层 / 模型）、`effect`（带 effect）、`composite`（不带 effect 但走合成路径：colorBlendMode 混合、被依赖、组合层）、`particle-perspective`（树里有 `flags & 4` 的系统）、`particle-framebuffer`（树里有要快照的材质）。这些在反射 pass 里重跑会改合成链或快照的状态，WPE 的行为没测，本机语料 0 处。
  - **视图**（`mirroredView`，C2、C3、C7）：透视场景 `VP' = S·VP·S`（`S = diag(1, −1, 1, 1)`，透视覆盖的视图投影同样镜像，分开的 P、V 为 `S·P`、`V·S`，视差平移照常）；**正交场景视图投影不变**（读码以为同样镜像，实测反射 pass 的 MVP 与主 pass 逐值相同）。两种场景都把 `g_EyePosition`、`g_ViewRight`、`g_ViewUp` 的 y 取反，`g_ViewForward` 不变。粒子 sprite 的朝向 `g_Orientation*` 保持主视图的值（C9，WPE 在对象更新时写），拖尾宽度用本 pass 的 `g_EyePosition`（C10）。没有裁剪平面（C4）。视锥剔除用镜像后的视图投影（C8）。
  - **pass**（C5、C6）：反射 pass 在主 pass 之前、画进 `_rt_Reflection`，深度共用场景目标的深度附件；`clearenabled` 时颜色清成 `(clearcolor, 1)`（同上，对齐方式 1 / 3 时是 `schemecolor`）、深度清 0，否则两者都 load；写掩码 RGB。逐 draw 有一份反射副本（`ReflectionCopy`：自己的 uniform 缓冲与绑定组，只换 binding 0），每帧拷主块再盖相机项（`REFLECTION_CAMERA_UNIFORMS`：MVP 及逆、VP、effect 矩阵、eye、视图向量），相机项在 `refreshLayer` 里按镜像视图现算：渲染器的五个相机量收成主视图 `GpuScene.view`（`SceneView`），`uniformValues` / `viewProjectionOf` 收视图参数，主 pass 与反射 pass 走同一套规则。HDR 场景的目标是 `rgba16float`、反射图是 `rgba8unorm`，名单里的图层另备一条 `rgba8unorm` 管线（`prepareLayer`）。粒子层一帧只排一次（`arrangeParticles` 返回排好的列表，`encode` 按树缓存），反射 pass 与主 pass 画同一次排列；模型的视锥剔除两个 pass 共用 `modelCulled`，各传自己视图的 VP。不可见的名单对象不画。
  - **dev 覆盖**：`localStorage["kabegame-dev-scene-reflection"]` 为 `follow` / `disabled` / `enabled` 时宿主加载与 dev 探针都用它（`dev/reflectionOverride.ts`，生产构建摇掉），验收不改用户设置就能按反射开渲染；用完要删掉，它对同源的全部场景宿主生效。
  - **实测**（2026-11-14）：确定性工程 `ignore/p13/b2/gen_b2.py`（透视、`clearenabled: false`、正交 + 图像层、剔除、透视粒子、正交粒子 + 文本）按 WPE 抓帧时刻渲染，上屏与 WPE 逐像素相同（不清屏工程只差 RenderDoc 叠加文字，它不清屏时留在后备缓冲里），透视工程的反射图只差帧号块；arsenal、audiophile、fantasticcar 按日志逐帧回放（后处理 ultra，audiophile 带频谱录制），读反射图的地面相同，余下是孤立的单像素（每帧 > 8 的 ≤ 11 个，不在反射区域）。语料按反射开扫描：没有场景报 `reflection:planar:*`，干净数不变，读 mip 帧缓冲的 2 张仍报 `reflection:screen`（P13g 去掉）。
- **实测**：确定性工程（`ignore/p13/b1/gen_b1.py`）和 WPE 整帧逐像素相同（HDR 那张反射图与泛光前的场景目标逐值相同，最后只差泛光链的 ≤ 4 级）；arsenal、audiophile、fantasticcar 按日志逐帧回放，读反射图的地面逐像素相同，余下的是孤立的网格边像素（相机矩阵 1e-6 量级的差导致的覆盖翻转）。能渲染 +3 张（这三张）。
- **实测（P13g，2026-11-17）**：确定性工程 `ignore/p13/g/gen_g.py`（左半静态整数哈希图样、右半读者按十条横带 lod 0–7.2 读 mip 帧缓冲）在 1920×1080、1366×768、HDR 三种下，按日志回放的各级 mip 与读者画面和 WPE 逐值相同（只差读时钟的 CLK 块）。按 FINAL_CHECK 走查 `3453730450` 的复制工程（只留开 `REFLECTION` 的模型 TY / LP 与背景，`ignore/p13/g/walk/make_iso_3453.py`）反射开 10 帧整帧逐像素相同，同一帧反射开 / 关差 109 个像素（最大 57 级），反射确实进了画面。`3706286085` 唯一的读者（Sonic 的眼睛）整个被挡住，反射开关画面逐像素相同。语料：跟随（WPE 反射关）逐张不变；反射开时 `reflection:screen` 2 张去掉，`3706286085` 变干净，`3453730450` 还差 P13h。

## sprite 对象（P13c）

读码见 [rea-p13-lights](../../../.claude/plans/wpe-import/3-scene/phase13/rea-p13-lights.md) 第 4 节，实测见 [p13-REPORT](../../../.claude/plans/wpe-import/3-scene/phase13/p13-REPORT.md)「P13c 的实测」，计划与走查见 [phase-13c-sprite](../../../.claude/plans/wpe-import/3-scene/phase13/phase-13c-sprite.md)。语料里只有 ricepod 的太阳用它。

- **是什么**：WPE 的「带遮挡测试的太阳光斑」，不是图像层。对象的 `sprite` 键（字符串）是光斑材质；工厂只在值是字符串时建（`"sprite": null` 不建），绑属性等写法照报 `object:sprite`。对象的 `origin` / `angles` / `scale` / `parent` 不参与，`visible`（含父链）照常；`effects` 不读（照报 `sprite:effects`）。不进半透明名单。
- **编译**（`compile/sprite.ts`）：编成两网格的常量模型挂在 `layer.model`（`layer.sprite` 标明它是 sprite），复用模型的网格绘制路径：网格 0 光斑（sprite 材质）、网格 1 遮挡方块（WPE 的 `materials/util/occlusiontest.json`），顺序固定、不做视锥剔除。顶点格式 `0x9`（位置 + 一组 uv，步长 20），四个顶点位置都是 `(−1, 0, 1)`、uv 四角、索引 `0,1,2, 0,2,3`。
- **矩阵**：MVP = `P · V'`，V' 是场景视图去掉平移（光斑只随相机转、不随相机移），模型矩阵是单位阵（`render/sprite.ts` 的 `spriteViewProjection`）。正交场景视图本来就只有平移，去掉后是单位阵（S6）。
- **k**：`k = min(512 · ⌊n/2⌋ / Hs², 1)`，n 是上一帧遮挡方块通过深度测试的样本数，`Hs` 是场景目标高（WPE 的后备缓冲高），float32 逐步算（S1 实测逐位成立）。光斑的 `g_ViewUp` / `g_ViewRight` 乘 `2k`、`g_Alpha = k²`；遮挡方块两个轴乘 float32 的 0.2（乘 double 的 0.2 个别分量差 1 ulp，走查实测），只写 alpha（写掩码 8，S3）、测深度 GREATER、不写深度。首帧 k = 0。
- **n 自己数、k 在 GPU 上算**（`render/sprite.ts` 的 `SpriteCounter`）：Chrome 在 Windows 上的 Dawn D3D12 后端只有布尔遮挡查询，给不出个数。每帧画到 sprite 时：计算 pass 从计数缓冲读上一帧的 n、算 k，把三个 uniform 直接写进光斑的 uniform 缓冲（缓冲带 STORAGE；CPU 上传的块按 k = 0 写，在本帧命令执行前落地，计算 pass 盖在上面）→ 画光斑 → 结束场景 pass，计数 pass 清零计数、用遮挡方块同一个顶点着色器与几何光栅化（覆盖的像素逐个相同），片元读场景深度纹理（场景深度在有 sprite 时带 `TEXTURE_BINDING`）按 GREATER 自己比较、通过的 `atomicAdd` → 接着场景 pass 画遮挡方块。用的正好是上一帧的结果，和 WPE 一样（S2 实测 WPE 不闪），产品与 dev 探针的回放都确定、不读回 CPU。比较放在 sprite 这个位置做：深度是「画到 sprite 时」的深度，排在它后面的对象挡不住它。
- **`REVERSEDEPTH`**：WPE 用反向深度，引擎恒定义这个宏（`engineDefines`）。遮挡方块的顶点着色器靠它把 z 写成 1e−7（不定义时是 `0.999·w`，对任何深度都能通过、k 恒为 1）。语料的工程着色器没有用它的。
- **照报**：组里的 sprite 报 `model:passthrough:children:sprite`（遮挡测试读哪张深度没测）；反射开时 sprite 在名单里报 `reflection:planar:sprite`（WPE 在反射 pass 里也画、谁先画谁做测试，矩阵怎么镜像没查清）；sprite 材质多 pass 报 `sprite:material-passes`、读快照报 `sprite:framebuffer`。
- **拼错的深度键**：`depthtesting` / `depthwriting`（ricepod 的 `orbital_*`）中性，WPE 不读，按缺省规整（测深度，S4）。
- **实测**（2026-11-14）：确定性工程 `ignore/p13/c/gen_c.py`（不挡 / 挡一半 / 全挡、相机平移 + sprite 写变换、正交）和 WPE 整帧 0 差异，挡一半的 k = 0.737888 和抓帧逐位相同。ricepod 去掉粒子的复制工程在太阳被船体部分挡住的时段（约 110 s）按日志逐帧回放的走查差异已解释（2026-11-15 复核，P5d 把透视相机改成逐步 float32 之后）：第 2223 帧各 draw 的常量与 WPE 0 ULP（遮挡方块的轴长改成 float32 的 0.2 之后）；光斑的 k 两边都是 1，光斑在整帧上不引入差异；第 2221 帧逐像素相同，其余 4 帧剩下的都是 1 级：船体主网格（e102）8 个、喷口（e118）1 个孤立像素，归「片元的零星舍入差」（P11a 已知差异），2222 帧泛光模糊 1 个纹素差 1（P2b 已知差异）经上采样成 3 个像素，2224 帧船体 1 个像素经泛光摊成 134 个。dev 探针的结果里 `sprites` 给每个 sprite 读回帧之前那一帧数到的遮挡样本数（`previous`，读回帧的 k 由它算）、k 与读回帧自己数到的样本数（`GpuScene.spriteSamples`，计数缓冲带 `COPY_SRC`，产品不读）。

## 阴影（P13d）

读码见 [rea-p13-passes](../../../.claude/plans/wpe-import/3-scene/phase13/rea-p13-passes.md) 第 2 节与 [rea-p13-shadows](../../../.claude/plans/wpe-import/3-scene/phase13/rea-p13-shadows.md)（R1–R6），实测见 [p13-REPORT](../../../.claude/plans/wpe-import/3-scene/phase13/p13-REPORT.md)「P13d 的实测：阴影」，计划与实施记录见 [phase-13d-shadows](../../../.claude/plans/wpe-import/3-scene/phase13/phase-13d-shadows.md)。

- **设置「场景阴影」**（`wpeSceneShadows`：`follow` 缺省 / `disabled` / `low` / `medium` / `high` / `ultra`；宿主收父页面下发的值，同上）：跟随时读 WPE `config.json` 的 `general.user.shadows`，缺键或读不到按 medium（`compile/postprocess.ts` 的 `resolveShadows`）。只在 `lightconfig` 要阴影时才读 `config.json`。值变了宿主整场重新加载（档位决定投射变体、图集尺寸与宏）。dev 覆盖 `localStorage["kabegame-dev-scene-shadows"]`（`dev/shadowsOverride.ts`，生产构建摇掉），宿主加载与 dev 探针都读，验收时不改用户设置也能按任一档位渲染；用完要删掉。
- **灯光缓冲**（`compile/lights.ts` 的 `lightFrame`）：灯光数组不再进材质常量，渲染器每帧（相机与脚本之后）按 WPE 的规则排序——类型升序、`castshadow | usecookie` 降序、局部原点 · `g_ViewForward` 升序——再按 WPE 的平铺布局写整块缓冲：带阴影的灯占前几个槽，多出来的投射灯被普通灯覆盖（`p13d-over`），没有灯的槽全 0。阴影计数照 WPE：档位为 0 时只读 `spotshadowcookie`（并进 `spotcookie`），其余阴影计数不读。
- **阴影宏**：阴影计数之和非 0 时 `LIGHTS_SHADOW_MAPPING = 1`、`LIGHTS_SHADOW_MAPPING_QUALITY = 档位`（1 low … 4 ultra；1 是单次比较，2 起 9 次采样）。翻译器按 WPE 的生成器展开点光、聚光（P13i）、平行光的阴影分支，平行光的级联下标照抄 WPE 的 `B0 + k + c`（`B0 = SSC + SC + SS`；两盏以上读错，语料依赖的 WPE 缺陷照抄）；聚光的两段 cookie P13k 起展开（见下面「聚光 cookie」）。
- **阴影图集**（`render/shadows.ts` 的 `ShadowAtlas`、`render/shadowMath.ts`）：`_rt_shadowAtlas` 是 `depth32float`、每帧清 0（反向 Z），比较采样器 GREATER、线性、clamp（WebGPU 没有 BORDER，越界的边框由翻译器的 `kb_shadowCompare` 处理）。方块边长 low / medium 256、high 512、ultra 1024：点光一块 2×3 个面（S/2 × S/3），平行光三级联各一块；打包点光优先、再按大小降序，8192 宽一行，图集只在不够时变大（「够就不动」）。点光六个面的 fov 94 / 94 / 92 / 91.2°（按档位），近平面正交场景 1、透视场景 `max(0.05, lightsourcesize)`，远平面 `max(radius, near + 0.01)`；阴影 pass 的投影 `P32 −= 0.00333`，uniform 不带。平行光级联 `(a, b) = (cd0, 4cd1)`、`(cd1, 4cd1)`、`(cd2, max(1.5cd2, 4cd1))`，视图照 R3 逐步 float32（快速倒数平方根、`fmodf` 防抖），阴影 pass 的 `VP[3][2] −= 0.0005`。投影与方块变换每帧写进同一块灯光缓冲（`g_LFeature_*`）。
- **阴影 pass**（`render/scene.ts` 的 `buildShadowCasters` / `shadowCasterOf`）：每帧在反射 pass 与主 pass 之前。投射者是不透明（任一网格第一个 pass 是 normal / alphatocoverage）且 `castshadow` 不为 false 的模型（缺省开、地面也投；绑属性登记重编译）；图像层、粒子等写了 `castshadow` 也不画，键中性。每个网格的投射变体（`SceneMesh.shadow`）：着色器取基础片元首行的 `// [PASS] shadow <名>`，没有用 `shadowcaster`；COMBO 只取投射着色器声明的、值取基础程序的，基础 blending 为 alphatocoverage 时加 `ALPHATOCOVERAGE = 1`、变体也走 A2C 丢弃入口；纹理按注解的 `material` 键对槽，材质常量按名字从基础 pass 拷（投射着色器的注解没有缺省，比如 foliage 的风）。管线只写深度、剔除 NONE、`depthBiasSlopeScale −4`。`fur4` 的主 pass 按 `INSTANCECOUNT` 画多层，投射变体只画基础网格一层。WebGPU 没有视口数组：每个图集条目、每个视图单独画一次，`firstInstance` 取视图号，着色器照样按实例号取 `g_ViewportViewProjectionMatrices[i]`（翻译器去掉 `gl_ViewportIndex` 的赋值）；投射者每个条目一份 uniform 副本（`g_ModelMatrix` 按当前状态、视图投影是这一条的）。
- **空槽**：WPE 给没有灯的阴影槽写全 0，投影 `w` 是 0，坐标是 0/0 的 NaN；硬件比较采样把 NaN 坐标当 0、结果有限，乘颜色 0 没有贡献。`kb_shadowCompare` 手算双线性的权重写成 `w >= 0 ? w : 0`，否则 NaN 会进整个光照和、画面全黑（`p13d-hide` 运行中隐藏一盏）。
- **聚光阴影**（P13i，[phase-13i-spot-shadow](../../../.claude/plans/wpe-import/3-scene/phase13/phase-13i-spot-shadow.md)）：
  - **槽位**：聚光按 `flags & (档位 ≠ 0 ? 3 : 2)`（bit0 `castshadow`、bit1 `usecookie`）选四段之一写 `LSpot_*`：阴影 + cookie（槽 0 起）、cookie、阴影（`SSC + SC` 起）、普通（`SSC + SC + SS` 起）；带阴影或 cookie、且 N 还有余量时占一个投影槽（同段的投影指针；N 余量和平行光共用，灯按类型排序，聚光先用），带阴影的进图集。锥角余弦照 WPE 按单精度算（`f32(角度 · 0.017453292f)` 再 `cosf`，和双精度差 1 ulp）。
  - **投影**：P13e 的 `spotViewProjection`（灯的世界矩阵做视图、外锥 ×2 当竖直 fov、宽高比 1、近平面正交 1 / 透视 0.05、远平面取半径），写 `ShadowProjection[槽]`；阴影 pass 同平行光 `[3][2] − 0.0005`。
  - **图集**：每条一块，边长同档位；不是点光，和级联同边长、按生成顺序排在级联之前。
  - **着色器**：锥角衰减之后 `CalculateProjectedCoords`（透视除法，没有越界判定）+ `PerformShadowMapping`。
  - **WPE 的阴影 draw**：每个投射者一次 draw，把它看得到的视图压紧成实例数组；我们按条目逐视图画，结果相同。
  - **实测**（2026-11-18）：确定性工程 `ignore/p13/i/gen_i.py`（朝下 / 斜照 / 正交 / 点光 + 两盏聚光 + 平行光，low 与 high）：灯光缓冲、投影、方块变换、阴影视图与 WPE 逐位相同（`render/p13i-spot.test.ts`），整帧只有 1–17 个孤立像素差 1（同 P13d）；`3455121165` 复制工程 5 帧每帧 1 个像素差 1。
- **聚光 cookie**（P13k，[phase-13k-spot-cookie](../../../.claude/plans/wpe-import/3-scene/phase13/phase-13k-spot-cookie.md)，读码 R1–R7）：
  - **纹理**：`usecookie` 的聚光加载时读 JSON 键 `cookie`（只认非空字符串，`{user}` 不认、运行中不能改），否则缺省 `cookie/flashlight1`；按纹理名进纹理表（`SceneLightObject.cookie`，`compile/lights.ts` 的 `lightCookieName`）。名字指向不存在的文件时 WPE 绑 6×6 棋盘格、不退回缺省，我们同样绑棋盘格并报 `texture:missing:*`。运行中建的 cookie 灯（片段）同样加载，纹理随片段的纹理增量带出。
  - **表面着色**：聚光四段的前两段（阴影 + cookie、cookie）**不乘锥角**，`CalculateProjectedCoords` 的坐标采 `COOKIE_SAMPLER`、颜色乘它的 rgb，前者再乘阴影因子（翻译器 `library.rs`）；`LIGHTS_COOKIE = 1` ⇔ `spotcookie + spotshadowcookie ≠ 0`（`litDefines`），着色器在它下面把 `COOKIE_SAMPLER` 定义成缺省 `_alias_lightCookie` 的槽（`generic4` / `genericimage4` 等 `g_Texture7`，`genericparticle` / `genericropeparticle` `g_Texture5`）。档位 0 时 `spotshadowcookie` 并进 cookie 段。
  - **别名** `_alias_lightCookie`（`TextureRef` 的 `light-cookie`，`GpuScene.lightCookieBinding`）：所有 cookie 段共用一张，每帧取排序后最后一盏可见、分到聚光槽的 cookie 聚光的 cookie（`LightFrame.cookie`）；那一帧没有时保持上一次绑的（WPE 一开始是 `error` 棋盘格，那时 cookie 段的灯颜色都是 0，我们给空纹理）。绑它的 draw 的 bind group 按别名当前的纹理缓存。
  - **投影**：只开 cookie 的聚光占投影槽、不进图集，`ShadowProjection[槽]` 写不偏的 `spotViewProjection`、方块变换不写（`writeCookieProjections`）；阴影 + cookie 的照聚光阴影走条目。
  - **采样器**：WPE 的别名是钳到黑色边框 + 三线性、无各向异性（`p13k-surf-two` 实测）；WebGPU 没有边框寻址，用钳边。内置 cookie 的 0–2 级 mip 最外一圈都是 0，最多差一级；作者自己的 cookie 边缘不黑时会不同（语料 0），记为已知差异。
  - **实测**（2026-11-21）：确定性工程 `ignore/p13/k/gen_k.py` 的 `p13k-surf`（cookie，地面、立方体、`genericimage4` 图层）、`-surf-shadow`（阴影 + cookie，low 与 disabled 两档）、`-surf-two`（两盏 cookie 灯 + 一盏普通聚光，别名取排后的那盏）和 WPE 整帧比，排除帧号角后只有 1–3 个像素差 1。
- **已知差别**：WPE 运行中隐藏投射灯时图集不缩；我们 `visible` 绑属性是整场重编译，按新的灯数建图集，方块变换的分母不同，画面相同（`p13d-hide` 2 个像素差 1）。
- **A2C 阈值**：单采样 A2C 在 alpha ≥ 0.5 + 2⁻¹² 时才覆盖（见 [IMAGE_LAYERS.md](IMAGE_LAYERS.md)「写入状态（步骤 5）」表里「A2C 的覆盖」一行）；投射变体同样适用，阴影图集逐纹素和 WPE 相同。
- **实测**（2026-11-15）：确定性工程 `ignore/p13/d/gen_d0.py`、`gen_d8.py`、`gen_d9.py`、`gen_d10.py` 共 29 次抓帧（五个档位 × 点光正交 / 透视 / 平行光、多灯、投射者判定、剔除、改级联距离、相机微移、两盏平行光、投射灯超配、运行中隐藏、毛发层数、三种专用投射者），按抓帧时刻渲染，每张最多 32 个孤立像素、都只差 1 级；`p13d-who` 另有一个粒子方块，是屏外探针不步进粒子，与阴影无关。

## 体积光（P13e）

读码见 [rea-p13-passes](../../../.claude/plans/wpe-import/3-scene/phase13/rea-p13-passes.md) 第 3 节与 [rea-p13-volumetrics](../../../.claude/plans/wpe-import/3-scene/phase13/rea-p13-volumetrics.md)（V1–V11），计划、实测与实施记录见 [phase-13e-volumetrics](../../../.claude/plans/wpe-import/3-scene/phase13/phase-13e-volumetrics.md)。

- **档位**：WPE 的 `general.user.volumetrics`（`disabled` / `low` / `medium` / `high` / `ultra`，缺键或不认识的值按 medium，与阴影共用档位枚举）。编译选项 `volumetrics`（`compile/postprocess.ts` 的 `resolveVolumetrics` / `readWpeVolumetrics`）缺省跟随 WPE，只在场景有会画的灯时才读 `config.json`。设置「场景体积光」（`wpeSceneVolumetrics`：`follow` 缺省 / `disabled` / `low` / `medium` / `high` / `ultra`；预览设置的 `volumetrics` 默认 `medium`）在 WPE 设置字段组里、排在阴影后面，同阴影一样由父页面下发（见 [COMPILE.md](COMPILE.md)「场景后处理档位」的「设置来源」），值变了宿主整场重新加载（`recompiled` 的键 `volumetrics`）。dev 覆盖 `localStorage["kabegame-dev-scene-volumetrics"]`（`dev/volumetricsOverride.ts`），宿主加载与 dev 探针都读，探针结果带 `volumetrics`（档位与会画的灯）；用完要删掉。
- **谁画**（`compile/volumetrics.ts`）：自己可见且 `castvolumetrics` 的 `lpoint` / `lspot`，不看 `lightconfig`。管光、平行光 WPE 也建组、清屏、合成，但灯体矩阵是没初始化的值（实测 NaN），什么都画不出、合成一片 0，所以不收；灯对象本来就不触发合成，不影响分组。
- **一盏灯**（`render/volumetrics.ts`，插在主 pass 里灯在 `objects` 中的位置）：场景深度 → `_rt_volumetricsBack`（全分辨率）；1/d 的 Single 深度清 0，画灯体背面（GREATER、写深度、剔正面）；组内第一盏把 LightBuffer 清成 (0, 0, 0, 1)；画灯体正面（剔背面、不测深度、SrcAlpha / One、只写 RGB），着色器沿视线从正面走到「背面与场景深度较近的那个」累加。d：low / medium 8、high / ultra 4；步数 2 / 3 / 5 / 8，带阴影 12 / 24 / 32 / 64（着色器按 `QUALITY`）。WebGPU 的深度纹理不能线性过滤，WPE 读 Back 用的是 Linear + Wrap：每次拷贝改成一个小 pass 把深度写进 `r32float`（Single 同样），要 `float32-filterable`，没有时退回（`render:volumetrics`）。场景深度附件在有体积光时总建。
- **合成时机**：连续几盏灯共用一次清屏；下一个可见的非灯对象画之前（不可见的不触发）、或顶层列表末尾（泛光之前）合成：low / medium 先 `blur_h`（LightBuffer → B）、`blur_v`（B → LightBuffer）各一次，再 `passthrough` 加法画回场景目标。LightBuffer 在 LDR 下是 `rgba8unorm`（一段灯的累加在合成前就钳到 1）、HDR 下 `rgba16float`，没有 HDR 系数。反射 pass 里没有体积光。
- **灯体与矩阵**：点光是单位球（两极 + 23 圈 × 25 点，`sinf` / `cosf` 照 MSVC 的 double 求值再舍入），`g_AltViewProjectionMatrix` = diag(r) + 位置，r 是原始 `radius`，灯的 scale / angles 不参与；聚光是 NDC 里的 32 段圆柱，经 `inverse(聚光 VP)` 变回世界（看向局部 +X，fov = 2·outercone，近平面正交 1、透视 0.05，不读 `lightsourcesize`，远平面 `max(radius, near + 0.01)`，视图用快速倒数平方根归一化），`g_RenderVar3` = 世界矩阵第 0 行原值；开 cookie 的聚光（P13k）换成 NDC 立方体（8 点 36 索引，`spotLightCube`）。常量：`g_RenderVar1` = (r·0.99, cos inner, cos outer, intensity)、`g_RenderVar2` = (位置, density)、`g_RenderVar4` = (color, volumetricsexponent)，缺省 density 2、volumetricsexponent 1。`g_EffectModelMatrix` 每帧是本次绘制 VP 的 GLM 逆（float32 标量，连正负零都和抓帧相同）。网格、求逆、聚光矩阵都和抓帧逐位相同（`compile/p13e.test.ts`）。
- **相机在灯体内**（`insideLightVolume`）：`p = eye + 0.2·F`，点光 `r² > |p − 灯心|²`，聚光沿轴投影 `0 < t ≤ radius` 且离轴距离在锥内；开 cookie 的聚光（P13k）改用 `eye + 0.1·F` 在灯视锥六个平面内侧（float32）；成立时正面换成全屏三角形（`FULLSCREEN = 1`），背面照画。正交场景照样判。
- **阴影**：`SHADOW` = castshadow ∧ 用户的阴影档 ≠ 0，**不看** `lightconfig` 有没有阴影计数（`p13e-pns`）；带阴影的点光每帧取自己阴影条目的方块变换与点光投影（`g_RenderVar0` / `g_RenderVar3`），`LIGHTS_SHADOW_MAPPING_QUALITY` = 阴影档、只给点光；带阴影的聚光（P13k）取自己聚光阴影条目的方块变换（`g_RenderVar0`，P13i 已算好）。
- **cookie**（P13k）：`COOKIE = 1` ⇔ `usecookie`，正面与全屏的槽 2 绑这盏灯的 cookie（纹理自己的采样状态），着色器沿视线采 `uvs.xy · (0.525, −0.525) + 0.5`、累加量变成 rgb、步数 12 / 24 / 32 / 64。确定性工程 `p13k-vol*` 与 WPE 整帧逐像素相同，`3839619935` 的复制工程最大差 5（背景纹理解码的已知差异）。
- **照报**（WPE 读的是残留或没初始化的值，语料都没有）：带阴影的点光分不到阴影条目（`volumetrics:shadow-unassigned`，个数超过 `min(pointshadow, point)`）、聚光分不到聚光槽（`volumetrics:spot-unassigned`）、灯在组里（`volumetrics:group`）；另有点光开 cookie（`volumetrics:cookie:point`，WPE 不分类型也加 `COOKIE`，坐标取残留的点光阴影投影）、透视场景的透明排序（`volumetrics:transparentsorting`，没测灯在两轮里落在哪）。灯是编译期常量（同 P13d），挂父对象、关键帧、脚本照报，等 P13f。
- **实测与走查**（2026-11-15，按 `FINAL_CHECK.md` 逐 pass 对齐、逐值解释，记录在 `phase-13e-volumetrics.md`「走查」）：
  - 确定性工程 `ignore/p13/e/gen_e0.py`（正交 / 透视点光、带阴影、分组、相机在灯内、聚光、四类灯、缩放旋转），low 档 9 个与 medium / high / ultra / disabled 共 21 次抓帧：体积光链（正面、`blur_h`、`blur_v`、合成）的 RGB 和 WPE 逐位相同，只有 2 处各一个纹素差 1（`in-low` (202, 11)、`po-high` (303 / 346, 37)），上采样后是最终帧里那 64 / 32 个像素；其余差异全在体积光之前的场景 draw（地面 / 立方体的 `LIGHTING`，P13a），各档都是同一批像素。每一处都按 WPE 的 DXBC 用 float64 复算到值，都落在「硬件写 8 位的取整阈值」上，见下方已知差异「片元的零星舍入差」。
  - 语料 `3837478759` 隔离出背景与三盏灯，五档都和 WPE 逐像素相同。
  - `3287715210`（HDR）重新复制成只留渐变背景与灯（`ignore/p13/e/real/3287715210-iso2`：人物层的 `iris_follow_cursor` 跟光标、抓帧时光标没录，且图像层不影响体积光，按原则第 5 条去掉）：LightBuffer（`rgba16float`）正面只有 1 个纹素差 1 个半精度 ulp（SHADOW 变体，没逐值复算），合成加上的量其余像素逐位相同；合成之前的差异来自背景的渐进式 JPEG（4:2:0），是已登记的「JPEG 色度上采样」；最终 8 位帧最大差 3（背景差异经泛光摊开）。

## 雾（P13f1）

读码见 [rea-p13-lights](../../../.claude/plans/wpe-import/3-scene/phase13/rea-p13-lights.md) 第 2 节，计划与实施记录见 [phase-13f-fog-lights](../../../.claude/plans/wpe-import/3-scene/phase13/phase-13f-fog-lights.md)，实测见 [p13-REPORT](../../../.claude/plans/wpe-import/3-scene/phase13/p13-REPORT.md)「P13f 的实测」F1–F7。

- **字段**：`general.fog*` 的 14 个字段在 `GENERAL_FIELDS` 里（缺省照 WPE：距离 1 → 5、高度 1 → −3、起止密度 0 → 1、颜色黑），属性、关键帧、字段脚本、`thisScene.fog*` 都走 general 目标、就地生效。
- **宏**（`compile/fog.ts` 的 `fogDefines`）：加载时开关为真才给翻译请求 `fogDefines`（`FOG_DIST` / `FOG_HEIGHT`），翻译器只在最终组合表里 `FOG` 非 0 时并进（着色器注解缺省值算；`FOG: 0`、不声明 `FOG` 的不上雾）。运行中改开关只改字段、不重编，WPE 画面也逐像素不变（F3）。
- **uniform**（`fogUniforms`）：`g_FogDistanceColor` / `g_FogHeightColor` 原值，`g_FogDistanceParams` / `g_FogHeightParams` = `(start, end − start, startdensity, enddensity − startdensity)`，差值按 float32 减法；每次按 `SceneState.general` 现算，进 `staticBuiltins`（图层、文本、粒子、网格共用），数值字段写入置灯光脏位、`refreshLights` 刷新。
- **图像层也上雾**（F7）：任一开关为真时 WPE 的渲染标志 `0x1800000` 给每个图像层与文本层置 passthrough 标志，没有 effect 的也走「基础 pass → 合成 RT → passthrough 上屏」，雾在上屏 pass 里算（`SceneLayer.fogPassthrough`，`render/graph.ts` 并进合成路径）。上屏的 `FOG_COMPUTED`：图像层取基础材质最终的 `FOG`，文本层是 1。组合层、全屏层实测过；带子层的组、形状层、puppet 照报 `fog:<种类>`，开雾的图层带光照照报 `lighting:prelighting`。
- **`ADDITIVE`**：材质混合是 `additive` 时编译期加 `ADDITIVE = 1`（WPE 加载时加，运行中改混合不加），只有 `generic4` / `chroma4` / `foliage4` / `fur4` 的雾分支读它（雾因子乘进 alpha）。粒子组合键白名单放行它。
- **照报**：开雾又有体积光报 `volumetrics:fog`（`volumetricsfront` 声明 `FOG`，体积光的 uniform 没接雾，语料 0）。
- **实测**（2026-11-15，`ignore/p13/f/gen_f0.py`）：透视 / 正交 / 粒子 / 各种图像层与文本 / 组合层与全屏层 7 个工程和 WPE 整帧比，最多 12 个像素、都只差 1 级，两个关雾的工程 0 差异。

## 灯的运行时（P13f2）

读码见 [rea-p13-lights](../../../.claude/plans/wpe-import/3-scene/phase13/rea-p13-lights.md) 第 1、3 节，实测见 [p13-REPORT](../../../.claude/plans/wpe-import/3-scene/phase13/p13-REPORT.md)「P13f 的实测」L1–L4。WPE 的灯字段都没有改值回调、逐帧读，所以灯是运行时状态，不再是编译期常量。

- **编译期**（`compile/lights.ts` 的 `compileLightObjects` → `bundle.lightObjects`）：每个 `light` 是字符串的对象一条（类型、遗留槽、`castshadow` / `usecookie` / `castvolumetrics`、12 个数值字段的初值，`LIGHT_FIELDS`）。数值字段绑属性登记就地目标 `{ kind: "light" }`；颜色、变换、可见性是图层字段（灯的 `color` 缺省黑）。`light`、`castshadow`、`usecookie`、`castvolumetrics` 运行中变 WPE 会重建灯的资源，挂属性 / 脚本 / 关键帧照报 `light:runtime:<键>`。
- **状态与写入**：`SceneState.lights`（float32，同 L2 的脚本读回）；属性、关键帧（P10a 的运行时，`value:animation:light` 去掉）、字段脚本（`targetOf`）、脚本对象（`installLight`：12 个数值字段可读写，`light` 读出类型字符串，三个开关只读，写入只告警一次）都写这张表。
- **每帧**（`render/lights.ts`）：V1 灯按本帧（动画、脚本之后）的状态组记录，世界矩阵与可见性沿父链（`worldMatrixOf` / `effectiveVisible`），排序键取局部 origin（L2′）；遗留灯三个数组按**上一帧末**的状态写（WPE 在动画与脚本之前写，L1：晚一帧；`GpuScene` 按帧时刻换代，探针同一帧多次 `update` 不错位）。阴影图集按加载时的灯记录定尺寸。
- **选灯的「带阴影」**：看用户阴影档 ∧ `castshadow`，不看 `lightconfig` 有没有阴影计数（L3，同 P13e 的 `SHADOW`）；没有阴影计数时带 `castshadow` 的灯先写槽 0、被后面的普通灯覆盖，照 WPE。
- **体积光**：每盏 `castvolumetrics` 的点光 / 聚光都预建绘制，每帧按可见性决定画不画、重新分段（L4：隐藏的灯不画也不开一段，隐藏中间的立方体两段并成一段），几何与常量（`volumetricGeometry`：位置与聚光方向取世界矩阵、字段取状态）每帧写。残留值配置（聚光超槽、点光没分到阴影条目）按全部可见照报。
- **实测**（2026-11-16）：`p13f-light` 按 WPE 日志确定性回放第 153 帧，灯光数组与遗留灯数组全部对上（最大差 2e-6，日志只记 6 位小数）；`p13f-vol` 四种状态与 WPE 整帧 0 差异；`p13f-sort` 两种状态各差 2 个像素 1 级。
