# 界面截图标注

保留截图中的真实 UI，只叠加少量辅助标注。除非用户明确要求重绘，否则不要使用生成式图像编辑：它可能改变控件、文字或数据，使文档失真。

## 工作方式

1. 先查看原图，确认用户要讲清楚的动作与视觉焦点。
2. 每张图优先保留 2–4 个标注。标签用动作短语，不复述整段说明；箭头终点必须落在实际控件或结果上。
3. 使用 `scripts/annotate.py` 生成新文件，默认文件名带 `-annotated` 后缀，保留未标注原图。
4. 查看输出图，重点检查箭头指向、遮挡、文字可读性，以及是否覆盖敏感信息。位置不准确时修改 spec 后重新生成。
5. 如果截图用于文档，更新图片引用，并删减与图内标注重复的按钮表格、步骤或状态说明；不要删掉行为边界、安全提示和平台差异。
6. 最后验证输出尺寸与输入一致、文档引用存在、旧文件名引用已按需求清理。

## 默认视觉语言

- 标签：紫色半透明圆角胶囊 `#7c3aedE8`，白字，细白边。
- 引导：粉色箭头 `#ff4fa3`，与 Kabegame 的粉紫视觉保持一致。
- 字号：在 2400×1536 截图上通常使用 32–36 px；其他尺寸按比例调整。
- 标签尽量放在留白区，不遮挡关键控件、正文、账号信息、Cookie 或下载结果。
- 同一组截图保持相同颜色、字号、圆角和箭头粗细。

如果目标项目已有视觉规范，优先沿用项目颜色和字体，但继续遵守“少而准、真实 UI 不重绘”的原则。

## 标注脚本

脚本依赖 ImageMagick 的 `magick` 命令，坐标均使用原图像素。示例 spec：

```json
{
  "style": {
    "point_size": 34,
    "radius": 24,
    "stroke_width": 6
  },
  "labels": [
    {
      "text": "① 选择入口",
      "box": [610, 430, 1010, 500],
      "text_at": [645, 475],
      "arrow": {
        "from": [820, 500],
        "to": [930, 535]
      }
    }
  ]
}
```

运行：

```bash
python3 <skill-dir>/scripts/annotate.py screenshot.png --spec annotations.json
```

默认输出 `screenshot-annotated.png`。可用 `--output` 指定路径，字体自动探测失败时用 `--font /path/to/font`。脚本不会覆盖输入文件，并会校验坐标和输出尺寸。

`box` 是标签矩形，`text_at` 是文本左侧基线位置；`arrow.from` 和 `arrow.to` 分别是箭头起点与目标控件。可在 `style` 覆盖 `label_fill`、`label_border`、`text_fill`、`arrow_fill`、`point_size`、`border_width`、`stroke_width`、`radius`、`arrowhead_length` 和 `arrowhead_width`。

## 完成标准

- 用户不看正文也能从截图理解主要操作顺序。
- 标注没有盖住要解释的控件，箭头终点没有歧义。
- 原始 UI、文字、数据和比例没有被生成式修改。
- 文档正文比标注前更短，而关键限制与风险仍然完整。
- 输出文件名能直接识别为已标注版本。
