# readme-translate — Markdown 文档翻译方法论

把**一份中文源文档**翻成**一种目标语言**的可复用规则。只负责「怎么译得对、译得地道」;**不负责**决定生成哪些文件、文件叫什么名、语言切换行怎么写——那些是调用方(或 `readme-translator` 代理)的项目契约,本 skill 不碰。

输入:中文源内容 + 目标语言(如 `en-US` / `ja` / `ko`)+(可选)已存在的旧译文。
输出:该语言的译文文本。

## 铁律

### 1. 中文源只读,是唯一真源
译文是产物。若发现**源文档本身**有笔误/病句/结构问题,**不要自行修正**,记进回执让人工确认——擅改会让各语言版本悄悄发散。

### 2. 结构必须与源 1:1 对齐
标题层级、章节顺序与数量、列表、表格行列、代码块、`:::note`/`:::caution`/`> [!IMPORTANT]` 等指令、图片、徽章(badge)、内嵌 HTML(`<div>`/`<table>`/`<img>`…)——**数量与位置逐一对应,不增不删不合并章节**。表格逐行对齐,代码块整段照抄。

### 3. 绝不翻译,原样保留
- 代码块(```` ``` ````)与行内 `code`、命令、shell 片段。
- 路径、文件名、目录名。
- 标识符:函数/变量/crate/包名、配置键、CLI flag、环境变量、错误码。
  例:`deno task dev`、`.kgpg`、`Tauri`、`Dokan`、`macFUSE`、`Rhai`、`PathQL`、`CEF_PATH`。
- URL、锚点(`#anchor`)、Markdown 链接**目标**(`](...)` 括号内)、HTML 属性(`src`/`alt`/`width`/`align`…)。
- 徽章、`<img>`、shields.io 之类。
- 产品名与专有名词:保持**原大小写**,**不音译**。

### 4. 只翻译人类可读文本
即:正文散文、标题文字、表格里的**说明文案**、链接/图片的**显示文字**(`[显示文字](target)` 的显示文字、`<small>` 里的说明)、`alt` 之外的可见注解。其余一律照搬。

### 5. 译文要地道,语气照搬源文
- 用目标语言技术文档的习惯表达,不做生硬直译、不加「本文将…」这类废话。
- **语气/调性与中文源一致**:源文轻松、二次元向、带梗,译文就保留同等轻松与玩梗感,不要擅自“正经化”或删掉俏皮话/颜文字。
- 目标语言里已成惯例的外来技术词照习惯处理(该用片假名/原文时用原文)。

### 6. 不串味
目标语言文件里不得混入其它自然语言的散文(韩文页里别冒出日文句子,反之亦然);代码/标识符/产品名除外。

### 7. 增量优先
给了旧译文时:仍准确的段落**保留**,只改源文变动的部分;结构大改才整篇重写。别为了“重译”而推翻能用的译文。

## 流程

1. 通读中文源,在心里标出所有「不译区」(铁律 3)。
2. 逐段翻译:锁死不译区,只碰可读文本(铁律 4);表格逐行、代码块整段照抄。
3. 有旧译文则做增量对齐(铁律 7)。
4. 通读一遍自查:结构对齐?有无漏译/串味/误译标识符?语气是否照搬?
5. 产出该语言译文文本,交回调用方。

## 回执

≤60 词:译了哪个语言、是新建/整篇重写/增量、以及任何 `Gaps`(源文疑似笔误、结构对不上、术语拿不准需人工确认的点)。不要把整篇译文复述进回执。
