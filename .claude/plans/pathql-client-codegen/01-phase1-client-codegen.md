## §1 客户端 API 规格(生成物的对外形状)

### 1.1 根与链式节点

```ts
import { pql } from "<生成物>";

pql.gallery                    // scheme → 根节点(schemas 表自省)
pql["fail-images"]             // scheme 名非法标识符时用带引号属性
pql.gallery.all                // list 静态项 → getter,返回目标节点类型
pql.gallery.all.$path()        // → "gallery://all"
```

- 节点**不可变**:每步返回新对象;节点内部状态只有「已累积的段序列(已转义)」。
- 客户端**只产路径**,无 invoke;唯一出口 `$path(): string`。

### 1.2 保留方法面(全部 `$` 前缀,与数据键隔离)

| 方法 | 签名 | 语义 |
|---|---|---|
| `$path()` | `(): string` | 产出完整路径 |
| `$raw(seg)` | `(seg: string): AnyProviderNode` | 追加任意字面段(自动转义);逃生口 |
| `$resolve{Alias}(seg)` | `(seg: string): <目标节点>` | 带 `alias` 的 resolve 项;**函数体与 `$raw` 完全相同**,只有返回类型不同 |
| `$child(name)` | `(name: string): <目标节点>` | 动态 SQL list 项(目标 provider 静态可知);同 provider 多个动态项时用其 `alias` 区分:`$child{Alias}` |
| `$any(cb)` | `(cb: (b: this) => Node \| Node[]): this` | OR 组;回调根 = 当前节点类型(组入口),返回值的相对段成为分支 |
| `$not(cb)` | `(cb: (b: this) => Node): this` | 取非组,单分支 |

- `$any`/`$not` 返回 `this` 类型——与引擎「`~end` 后游标回组入口」语义一致;嵌套组
  由回调里继续 `$any`/`$not` 天然支持。
- list 静态项的 key 若与保留面冲突(以 `$` 开头)或非法标识符,生成带引号属性;
  以 `~` 开头的 key(如测试里的 `~weird`)由转义层处理,类型名照常生成。

```ts
pql.gallery.all
  .$any(b => [b.plugins.$resolvePlugin("pixiv"), b.albums.$resolveAlbum("收藏")])
  .$not(b => b.plugins.$resolvePlugin("yande"))
  .$resolvePageSize("x500x")
  .$raw("1")
  .$path()
// → "gallery://all/~any/plugins/pixiv/~or/albums/收藏/~end/~not/plugins/yande/~end/x500x/1"
```

### 1.3 段转义(生成 runtime 内嵌,与引擎同构)

```ts
const encodeSeg = (s: string) =>
  encodeURIComponent(s.startsWith("~") ? "~" + s : s);
```

- 与 Rust `where_group.rs::escape_path_segment` + `normalize_segments`(percent-decode)
  往返同构;组合器记号(`~any`/`~or`/`~not`/`~end`,由 `$any`/`$not` 内部产生)**不**过
  此函数。
- 静态 getter 的字面 key 同样过 `encodeSeg`(键 `~weird` → 段 `~~weird`)。

## §2 `alias` 注解字段(DSL schema 追加)

```json5
resolve: {
    "x[1-9][0-9]*x": {
        provider: "gallery_paginate_router",
        alias: "page_size",         // ← 新增字段,可选;snake_case
    },
}
```

- 位置:resolve 项与动态 list 项均接受可选 `alias`(引擎查询语义完全忽略)。
- 格式:**snake_case**,`^[a-z][a-z0-9_]*$`(与 DSL SimpleName 命名风格一致);
  加载期校验格式 + **同 provider 内唯一**(按原始 snake_case 值判重)。
- 生成(**目标语言各自做命名转换**;TypeScript 转驼峰):resolve 项 →
  `$resolve{Pascal(alias)}`(`page_size` → `$resolvePageSize`);动态 list 项 →
  `$child{Pascal(alias)}`(单个动态项且无 alias 时就叫 `$child`)。
- 无 alias 的 resolve 正则**不生成方法**(用户 `$raw` 手动);不从 provider 名推导。

## §3 类型命名(占位命名为用户委托 Claude 设计的方案)

### 3.1 可具体化节点

- FQN → PascalCase + `Node` 后缀;`.`/`_`/`-` 都作分段符,段首大写:
  `kabegame.gallery_route` → `KabegameGalleryRouteNode`;
  `plugins.pixiv-rank.entry_provider` → `PluginsPixivRankEntryProviderNode`。
- 归一后撞名(理论可能):按 FQN 字典序,第二个起追加 `$2`、`$3`(生成注释标注原 FQN)。

### 3.2 占位类型(不可具体化)

- 基型 **`AnyProviderNode`**:拥有全部 `$` 保留面,索引访问**返回 `AnyProviderNode`
  自身**(不是 `any`)——链式无摩擦继续,每一步仍是「节点」:有 `$path()`/`$raw`/
  `$any`/`$not` 补全,组合器回调也有类型;只是子节点结构无保证。
  ```ts
  // 索引签名与方法面共存用交叉类型绕过一致性检查(TS 惯用法):
  type AnyProviderNode = AnyProviderMethods & { readonly [key: string]: AnyProviderNode };
  ```
- 每来源一个命名别名(`type X = AnyProviderNode`,注释标注来源),别名键设计:
  - **程序化 provider**:有 FQN → `Opaque` + FQN PascalCase + `Node`
    (`OpaqueKabegameLocalImportEntryNode`)。
  - **动态 delegate / 模板 provider 边**(如 `plugin_entry_provider` 的
    `provider: "${extend.provider}"`):用 **宿主 FQN + child_var** 命名 →
    `KabegamePluginEntryProviderExtendNode`。
    > 选 child_var 而非序号/模板串:child_var 是作者起的语义名、同 provider 内
    > 天然唯一,且 list 与 resolve 常共用同一 child_var(如 `extend` 两处)——
    > 语义相同,共享同一个占位别名恰好正确。
  - 无 child_var 的兜底(理论罕见):宿主 FQN + `List`/`Resolve` + 声明序号。

## §4 生成物结构(单文件、自包含、不入库)

```
// AUTO-GENERATED by `kabegame-cli pathql generate` — DO NOT EDIT. (头部含生成参数)
// ① runtime 基座:encodeSeg、NodeBase(段缓冲 + $path/$raw/$any/$not 实现)、AnyProviderNode
// ② 每个可具体化 provider 一个 class extends NodeBase(只加类型化边方法,方法体全是
//    一行 this._seg(...))
// ③ 占位别名 type X = AnyProviderNode
// ④ export const pql = { gallery: ..., albums: ..., ... }(schemas 表)
```

- 零 import、单文件,gitignore;`--out` 任意路径(Phase 3 前端接线再定默认值与 alias)。
- 组合器实现:`$any(cb)` 用一个空段缓冲的同型节点跑回调,取分支的相对段序列,
  emit `~any/…/~or/…/~end` 后拼回入口缓冲。

## §5 pathql-rs 侧实施(Phase 1 的代码改动)

### 现状锚点

- resolve 项 / 动态 list 项的 AST 在 `src/ast/resolve.rs` / `src/ast/list.rs`
  (`deny_unknown_fields`,加字段需同步 schema.json5 与 validate)。
- registry 可迭代:`ProviderRegistry::iter()`(DSL + 程序化条目)、`iter_dsl()`
  ([registry.rs:192-203](src-tauri/pathql-rs/src/registry.rs#L192-L203))。
- schemas 表在 `ProviderRuntime.schemas`(scheme → SchemaRoot),同 crate 可见。
- 转义对照实现:`provider/where_group.rs::escape_path_segment`。

### 点 1 — AST + schema:`alias` 字段

- **修改**:resolve 项与动态 list 项结构加 `alias: Option<String>`(serde default;
  引擎运行语义不读它);`kabegame-core/src/providers/dsl/schema.json5` 对应位置加字段。
- **新增**:validate 规则——alias 格式 `^[a-z][a-z0-9_]*$`(snake_case)、同 provider 内唯一;
  错误进现有 ValidateError 体系。

### 点 2 — `client_codegen` 模块(feature `client-codegen`)

- **新增** `src/client_codegen/mod.rs` + `typescript.rs`:
  - `CodegenTarget` 枚举(当前仅 `TypeScript`);
  - `ProviderRuntime::client_codegen(&self, target) -> Result<String, EngineError>`:
    walk schemas + registry,构建节点表(可具体化 / 占位)→ emitter 产出 §4 结构;
  - 命名实现按 §3;输出**决定性**(所有遍历按 FQN / 声明序排序)。
- **不引入模板引擎**:固定骨架(runtime 基座 TS)用 `include_str!("runtime.ts")` 内嵌,
  动态部分 `write!` 直拼;只封装三个小 helper——缩进 writer、TS 字符串字面量转义、
  合法标识符判定(决定裸属性 vs 带引号属性)。转义同构测试直接对 runtime.ts 文件断言。
- 不触碰查询执行路径;feature 关闭时零开销。

### 点 3 — 测试

- **新增** `tests/client_codegen_snapshot.rs`:
  - 小型内建 DSL 集(静态 list / alias resolve / 无 alias resolve / 动态 SQL list /
    动态 delegate / 程序化 provider / `~` 开头静态 key)→ 生成快照断言;
  - 命名单测:FQN→PascalCase、child_var 占位、撞名 `$2`;
  - alias 校验单测:非法格式 / 重复 alias 拒绝;
  - 转义同构:Rust `escape_path_segment` 与生成 TS 里 `encodeSeg` 的字符串字面量
    一致性(对生成文本断言包含该实现)。

### 验收

- `cargo test -p pathql-rs --features client-codegen` 全绿;
- 快照里肉眼核对 §1 示例集的类型形状(gallery 链、$any 回调根类型、Opaque 别名);
- 生成 TS 的**编译**验证留到 Phase 2(有 CLI 后 `deno check` 真实产物)。
