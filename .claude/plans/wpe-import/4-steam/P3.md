# P3 创意工坊订阅（思路总纲）

## 总体设计思路

「从 Steam 导入」的主角从「下载 Wallpaper Engine 本体」换成「拿用户的 Steam 凭证下载壁纸」。对话框里登录始终在最前面；
登录之后是「要导入什么」，第一个来源是「我的订阅」，以后的收藏、浏览 / 搜索都排在这里。Wallpaper Engine 本体退成顺带的一步：
设置里没有 WPE 目录时，任务先照 P1 下载一份 Kabegame 管理的 WPE（场景壁纸要用它的 `assets`，工坊壁纸也要放在它下面），
有就直接用；任务不再导入官方默认壁纸，要导入默认壁纸走「本机」来源。

**不替用户把订阅全拉下来，而是让用户在对话框里挑。** 订阅动辄几百条、十几 GB（本机 225 条、18.6 GB），所以「我的订阅」是一个
服务端分页的列表：每页一次 `PublishedFile.GetUserFiles#1`（`type = "mysubscriptions"`），排序（最近更新 / 最近订阅）与分级筛选
（`excludedtags` / `requiredtags` 传 `Everyone` / `Questionable` / `Mature`）都交给 Steam 做，前端只持有当前页，不在本地缓存全量。
每条显示预览图（响应里的 `preview_url`，Steam 的图片 CDN）、标题、类型、大小、分级、本地是否已有 / 有更新。用户勾选条目后提交，
任务参数只带账号名和选中的条目 id；另给一个「选中当前筛选下的全部」，这时参数带筛选条件而不是 id 列表，任务运行时按同样的条件
重新列一次（订阅可能在打开对话框之后变化）。

浏览要连 CM，而连一次 CM 要几秒、偶尔超时，所以后端按账号缓存一条 CM 连接（翻页、换筛选都复用，空闲几分钟后断开、失效时重连一次），
不是每翻一页就重新登录。

下载的工坊壁纸一律放进 WPE 目录的 `projects/myprojects/<条目 id>/`：不管 WPE 是 Kabegame 下载的还是用户自己的 Steam 安装，
都不碰 `defaultprojects`，也不写 Steam 客户端管理的 `steamapps/workshop/content/431960`。`myprojects` 本来就是一种 WPE 来源，
本机导入与文件夹发现不用改。

任务里每个条目是一次「比对 → 下载 → 入库」：条目的 `hcontent_file` 就是工坊 depot 的 manifest id，depot 取 PICS 里 431960 的
`workshopdepot`（431960，照 DepotDownloader 的 `isUgc` 分支）。之后取密钥、request code、CDN token、manifest、chunk 全部复用 P1 的
`cm` / `cdn` / `install` 下载核心，只是把「本体 depot + 安装目录」换成「工坊 depot + 条目目录」。下载完一个条目就立即调
`ingest_wpe_dir` 入库，任务中途取消也保留已完成的条目，进度按字节走。增量的依据是 manifest id：记一份「条目 id → 已装 manifest id」，
没变就跳过（连 CDN 都不用连），变了按新旧 manifest 只补变化的文件，和 P1 更新本体同一套计划逻辑。取消订阅的条目不删除、不动入库的行。

## 已定（2026-11-15 实测，`ignore/steam-p0 subs <参数>`）

- `GetUserFiles` 经 CM 走得通，不需要 Web API key；每条带标题、标签（类型 / 题材 / 分辨率 / 分级）、大小、更新时间、订阅时间、
  `hcontent_file`、`preview_url`；本机 225 条全部 `file_type = 0`、`file_url` 为空。
- **分页**：`numperpage` + `page`（从 1 起），响应带 `total` 与 `startindex`；`numperpage = 500` 也一次返回全部 225 条；
  `totalonly = true` 只回 `total`、不回条目。
- **排序** `sortmethod`：缺省即 `lastupdated`（条目更新时间倒序）；`subscriptiondate` 按订阅时间倒序；`title`、`creationorder`
  与不认识的值都落到同一个顺序（看起来是条目 id 倒序），没有按标题排序。
- **分级筛选**：分级是 WPE 的标签 `Everyone` / `Questionable` / `Mature`，每条恰有一个（165 + 5 + 55 = 225）。`excludedtags = [Mature]`
  得 170、`excludedtags = [Mature, Questionable]` 与 `requiredtags = [Everyone]` 都得 165、`requiredtags = [Mature]` 得 55，
  `total` 跟着变，分页在筛选之后。多个 `requiredtags` 是「都要有」（`Scene` + `Mature` 得 55）；类型标签（`Scene` / `Web` / `Video`）同样能筛。
  `excluded_content_descriptors`（1 / 5）只去掉 24 条，作者自己声明的、不全，不用它。
- 工坊 depot 431960 的密钥、request code（`app_branch` 留空）、CDN 403 后按 host 申请 token、manifest 解密、chunk（VSZa/zstd）
  解压与 SHA-1 校验，和本体完全同一流程（`depot 431960 <hcontent>`）。
- 落盘位置：`<WPE>/projects/myprojects/<条目 id>/`（用户定）。
- 「从 Steam」任务不再导入官方默认壁纸（用户定）。
- 不替用户全量拉取，列表分页、由用户勾选（用户定）。

## 待定（2026-11-15 已定）

1. 列表形态：行列表，每页 20 条（用户同意）。
2. 分级筛选缺省「全部」（用户同意）；至少留一个分级。
3. Application 与预设照显示、不能勾选，任务里记日志跳过（用户同意；本机订阅里没有，实测不到）。
4. 预览图：主窗口 CSP 是 `img-src * data: blob: file:`，直接用 `preview_url`。
5. 「已有」：`myprojects/<id>/project.json` 在且记录的 manifest 等于 `hcontent_file` 为「已下载」，目录在但不一致为「有更新」；记录放 `<WPE>/projects/myprojects/kabegame_workshop.json`（用户同意）。
6. 条目更新后的入库：按路径命中已有行只补画册成员，哈希 / 大小 / metadata 不重算，记为已知限制（文件夹同步同样的缺口），等「刷新已有行」的入口。
7. 标签：用 `GetUserFiles` / `GetDetails` 给的 Steam 标签，记进状态文件，`read_workshop_tags` 先读它、再由 WPE 的工坊缓存覆盖同一条。
8. CM 连接：**改为每个账号一条共享连接**，浏览与任务共用。实测发现 steam-vent 的 login id 固定为 0，同账号再登录一条会把前一条踢下线（S5：任务与浏览互踢，86 s）；还有人持有时不回收，空闲 5 分钟断开，失败时作废重连；连 CM 加 20 s 超时。

## 实施结果（2026-11-15）

- P3a / P3b 完成，`cocs/wpe/WPE_STEAM.md` 已更新；回归见 `versions/latest/regression.md`「从 Steam 导入」的 S0–S11（S0–S6 通过）。
- **新发现的缺口**：依赖别的工坊条目的场景（`effects/workshop/<id>/…`），依赖条目没下载，渲染器也不解析这类路径（Steam 本机装的同类壁纸一样缺）。下一步先查 WPE 怎么把这类路径解析到依赖条目，再定依赖条目下载到哪（`GetDetails` 的 `includechildren` 给依赖清单）。
- 未测：「全部 N 个」、条目有更新、dry-run 与取消、没有 WPE 时顺带下载本体再导入条目。

## P3c 工坊发现（2026-11-15，用户要求）

在「我的订阅」旁边加「工坊发现」：浏览 / 搜索整个创意工坊，勾选后与订阅一起导入。两个页签共用一份已选条目 id；「全部 N 个」只在订阅里有。
任务不用改协议：发现里选的条目照样进 `steamItems`，任务按 id 查详情再下载；`steamAllSubscriptions` 与 `steamItems` 同时有时取并集。

实测（`ignore/steam-p0 query <参数>`，`PublishedFile.QueryFiles#1`，经 CM，0.4–2.3 s / 页）：

- 431960 共约 328 万条；`page` + `numperpage` 分页，`page = 2000` 也能直接取。
- `query_type` 实测含义：0 按评分（score）、1 最新发布、3 趋势（配 `days` 时间窗，7 / 365 都生效）、9 总订阅数、11 好评数、12 搜索相关度、21 最近更新；19 只回 2.3 万条、含义不明，不用。
- `search_text` 中英文都行，能叠加任何排序（同一个 `total`）。
- 标签：`excludedtags` 与订阅一样；`requiredtags` 多个时由 `match_all_tags` 决定「都要有 / 有一个」。分级与类型都用「排除没选的」表达，组内是「或」、组间是「与」。
- 类型：Preset 14 万多条、Application 只有 1 条，发现里固定排除这两类。

实施（2026-11-15）：`workshop::discover_page` + `DiscoverSort` / `DiscoverQuery`、命令 `wpe_steam_workshop_query`（与订阅共用 `commands::wpe::workshop_page` 的「共享连接 + 失败重连一次 + 补本地状态」）；任务的 `SteamSelection` 改为 `{ ids, all_subscriptions }` 取并集；前端 `WpeSteamSubscriptions.vue` 改成通用的 `WpeSteamWorkshopList.vue`（`source`），对话框两个页签共用已选 id。回归 S12–S14。
