# WPE 2.8.42 P4j 发射器 `layerimage` 与粒子 `dependencies` 静态逆向

**概括**
- **发射器的键（`FUN_1401b9930` 缺省，解析段 `0x1401c6ad2`–`0x1401c6fda`）：** 公共字段（rea-p4b A0）之外只有 4 个键：`speedmin`（0.1）、`speedmax`（0.2）、`offsetmin` / `offsetmax`（正交 `"-5 -5 0"` / `"5 5 0"`，透视全 0），另有 `flags` 的缺省值 **0x10000**（不是 0）。`origin`、`directions`、`controlpoint`、`distance*`、`sign`、`cone` 都不读【确】。
- **`flags` 的 4 个新位：** `0x10000` 粒子颜色乘像素颜色（缺省就开着）；`0x20000` 每 1 秒（按 `dt'` 累计）重建一次候选表；`0x40000` 出生速度取「像素点随图层移动的速度 × 随机速率」；`0x80000` 出生点加三轴抖动。公共位 bit1 / bit2 / bit31 照旧，bit0（`sign`）不读【确】。
- **记录（类型 3，长度 0x100）：** `+0x78` 依赖槽号（不是 JSON 的 `index`）、`+0x7c` 刷新计时、`+0x80` / `+0x84` 速率最小值 / 范围、`+0x88..+0x90` 抖动最小值、`+0x94..+0x9c` 抖动范围、`+0xa0` puppet 骨骼矩阵缓存（每项 0x84）、`+0xb8..+0xf7` **上一次发射时的图层矩阵**（解析时是单位阵）【确】。
- **粒子对象的 `dependencies`（`FUN_14022af30` `0x14022afae` 起）：** 元素 `{id, type, index, mask}`；`id` 必须是无符号整数且非 0，`index` 必须是 32 位无符号整数（缺了就整条丢掉），`type` 只认 `"emitterimage"`（1）、`"collisionmodel"`（3），`mask` 是**纹理路径**字符串（可缺）。`id` 同时插进对象 `+0x1f8` 的依赖集合，所以被引用的图层在场景构造时就被置 `0x1010`（推翻 rea-p8-render「这种元素不进集合」的说法）【确】。
- **`index` 的含义（`FUN_14022cfa0`）：** 同一个粒子系统里**同类型的第几个槽**。`layerimage` 每个发射器在解析时按流顺序登记一个类型 1 的槽（`sys+0x1c8`），第 k 个 `layerimage` 发射器绑 `index == k` 的那条依赖；子系统、事件实例各自从 0 数，用的是同一份对象级 `dependencies`【确】。
- **候选表从哪来（`FUN_1401d3ae0`）：** **GPU 读回**，不是解码纹理文件。把依赖图层的合成 RT 0（`L+0x2c8`，即 `_rt_imageLayerComposite_<id>_a`，带全部 effect）用 WPE 自带的 `materials/util/downsample_quarter.json`（组合键 `WRITEALPHA=1`，有 `mask` 时再 `OPACITYMASK=1`）画进一张约 1/4 尺寸的 RGBA8 RT（先把大于 3840×2160 的按比例压进 3840×2160，再除以 4、至少 2），拷进 staging，下一次调用时 Map 读回。**alpha 字节 ≥ 127 的每个像素一项，等权**；按 **x 外层、y 内层**的顺序入表【确】。
- **表项 8 字节：** 字节 0–2 = 降采样后的 R、G、B，字节 3 = 0xff（puppet 时改成骨骼号），`+4` / `+6` 两个 `int16` 是相对图层中心、以合成 RT 像素计、y 向下的坐标：`x' = trunc((s·x − (W >> 1)) + s·0.5)`，`y' = trunc((s·y − (H >> 1)) + s·0.5)`，`s = W / w4`，**y 也用 x 方向的 `s`**【确】。
- **时机：** 每次调用是一步状态机，加上「同一帧不连做两步」的门。最快在**第 3 个要发射的帧**才有表，前两帧要发的粒子直接丢掉（`acc` 已扣，不欠账）；`starttime` 预热整段在同一帧里，**预热永远发不出 `layerimage` 粒子**【确】。表建好后不再更新，除非合成 RT 尺寸变了或开了 `0x20000`；更新期间旧表照用、不断发射【确】。
- **每颗粒子：** 先用 MSVC `uniform_int_distribution` 的 Lemire 乘法加拒绝从 MT19937 取下标（`FUN_14007d8f0`），再（`0x80000` 时）按 x、y、z 抽三个 `uA` 作抖动，得 `p = (x' + jx, −y' + jy, jz)`；出生点 `P = A·p`，`A = M⁻¹·L`（本地系统）或 `L`（世界系统），`M` 是粒子的模型栈顶、`L` 是图层的绘制矩阵（虚函数 `+0x80`，含父链、`scale`、`alignment` 偏移，**每个发射帧现取**）。速度缺省是 0；传给 initializer 的 `M3` 本地为单位阵、世界为 `mat3(M)`【确】。
- **随机数：** 场景只有一个 MT19937（`ctx+0x1cd0`，每个渲染器即每个窗口一份），「取下一个 u32」只有两份**一模一样的**实现：`FUN_14007f5b0(rcx = 状态指针)` 与 `FUN_14007d8f0(rcx = 指向状态指针的指针)`，返回 `eax`；全 `.text` 里 MT 的 tempering 常量只出现在这两个函数里，`ctx+0x1cd0` 的引用全是把地址传给它们，**没有内联副本**【确】。种子在渲染器构造 `FUN_14017c6d0`：先 5489，再 `0x14017d6bc` 用「1970 年起的毫秒数」截成 32 位重播种；场景重载（`0x465`）不重播种【确】。
- **顺带的更正：** rea-p4c-sim「`FUN_1401a27f0` 是单位阵为推」→ 它是 `diag(s)`，这里传 1.0，【确】；rea-p12-mdl 179 行把 `FUN_1401d6d30` 所在任务推断成「光标命中」，实际是本节的候选表任务（puppet 的部件号分配）【确】。

## 1. 解析

### 1.1 发射器记录【确】

`FUN_1401c5490` 的发射器链里 `0x1401c6add` 把名字与 `0x14048fde0`（`"layerimage"`）比较，相等走 `0x1401c6af1`：
- 容量检查 `+0xf0`，分配 `FUN_1401d8490`：类型字节 3、长度字 0x100、返回 `rec+0x10`。
- 缺省值 `FUN_1401b9930(json, 正交开关)`（`0x1401c6b1a`）：先调公共的 `FUN_1401b8df0`，再补本节的键。只在键不存在时补。
- `rec+0x70`（8 字节）与 `rec+0x7c` 清 0（`0x1401c6b2f` / `0x1401c6b33`）；`rec+0x70` 之后再没人读。
- `rec+0xb8..+0xf7` = `FUN_14005f680(·, xmm10)`（`0x1401c6ba2`）。`FUN_14005f680(m, s)` 写 `diag(s, s, s, s)`，`xmm10` 在整个发射器链里是常量 1.0（`0x1401c5769`、`0x1401c6377` 都把它装回 `0x140492704` = 1.0）→ 单位阵。
- 之后 `FUN_1401c1c70(rec+0x10, json)` 解析公共字段（含 `flags` → `rec+0x4c`），`FUN_14000dd50(rec+0xa0)` 初始化骨骼缓存 vector，`FUN_1401c1e20(rec+0x50, json)` 解析 `audioprocessing*`（rea-p4e：乘到 `rate`）。
- 末尾 `0x1401c6fba`：`rec+0x78 = FUN_1401d91b0(def+0x1b0)`（当前槽数），再 `FUN_1401d84b0(def+0x1b0, &{1})` 追加一个类型 1 的槽（0x18 字节：`+0` 类型，`+8` / `+0x10` 指针）。`def+0x1b0` 复制进系统后是 `sys+0x1c8`（定义偏移 + 0x18，同 rea-framework Q4）。所以 **`rec+0x78` 是本系统槽表里的绝对下标**，槽表里也有 `collisionmodel` 的槽（类型 3）。
- `instanceoverride` 绑定：`rate` 乘 `count`（类型 2，`0x1401c6e67`）、`maxtoemitperperiod` 乘 `count`（类型 1，`0x1401c6ed6`），粒子 `flags & 0x20` 时不登记；`speedmin` / `speedmax` 乘 `speed`（类型 6，`0x1401c6f1b`，字段 `rec+0x80` / `+0x84`），粒子 `flags & 0x10` 时不登记。同 rea-p4b 的条目规则。

### 1.4 粒子对象的 `dependencies`（`FUN_14022af30`，`0x14022afae`–`0x14022b36f`）【确】

基类构造 `FUN_1401ddbb0` 也读同名键，但只收能转成整数的元素（rea-p8-render 第 1 节），对象形式的元素在那里被丢掉。`FUN_14022af30` 再读一遍，逐个元素（jsoncpp 迭代，数组按下标序）：
1. `id = v["id"]`、`type = v["type"]`、`index = v["index"]`、`mask = v["mask"]`（`operator[]`，缺了就是 null）。
2. 三个门（不过就跳过这条，`0x14022b089` / `0x14022b099` / `0x14022b0a5`）：
   - `FUN_140088800(id)` = `isUInt64`：非负 int、uint、或 `[0, 2⁶⁴)` 里的整数实数；
   - `FUN_140088760(index)` = `isUInt`：`[0, 2³²)` 的整数（int / uint / 整数实数）。**`index` 缺失（null）不通过**；
   - `type` 是字符串。
3. `id64 = asUInt64(id)`（`FUN_140086000`）；有效位 = `id64 != 0`（`0x14022b126`）。
4. `index` 转 32 位：int / uint 取低 32 位、实数 `cvttsd2si`、bool 0/1（`0x14022b0da`–`0x14022b11b`）。
5. `mask` 是字符串就拷出来，否则空串（`0x14022b12a`）。
6. `type`：`"emitterimage"`（`0x140491418`）→ 1，`"collisionmodel"`（`0x14048fcc8`）→ 3，其它跳过（`0x14022b1d9`–`0x14022b204`）。大小写敏感（`strcmp`）。
7. 追加到 `obj+0x940` 的 vector，每项 0x38：`+0` 有效位（0/1，绑定后改 2）、`+4` `index`、`+8` 类型、`+0x10` `id64`、`+0x18` `mask`（std::string）。
8. **`FUN_140078250(obj+0x1f8, …, &id64)`（`0x14022b277`）：把 `id` 插进对象的依赖集合**——就是基类构造用的那个 `unordered_set`（`+0x1f8`，rea-p8-render 1）。所以场景构造的依赖段（`FUN_140186c90`，所有对象加载之后）会给这个图层置 `L+0x304 |= 0x1010`，图像层 / 文本层强制走合成路径、不可见也画进独占 RT。rea-p8-render 说「对象形式的元素不进集合」只对基类构造成立，这里要更正。

读完以后：`FUN_14022c3c0(sys, 粒子文件, 0)` 加载粒子定义（建槽表），紧接着 `FUN_14022cfa0(sys, obj+0x940)` 绑定（`0x14022b413`）。

### 1.5 绑定：`index` 与槽号（`FUN_14022cfa0`）【确】

```
cnt[0..3] = 0
for slot in sys.slots (sys+0x1c8，0x18 一项，解析顺序):
    for d in obj.deps (obj+0x940，JSON 顺序):
        if d.type == slot.type && d.valid ∈ {1, 2} && d.index == cnt[slot.type]:
            d.valid = 2
            类型 1：slot+8  = 找或建记录(id, mask)       // 1.6
            类型 3：slot+0x10 = 找或建碰撞记录(id)
            // 不 break：同一个槽匹配到多条依赖时，后面的覆盖前面的
    cnt[slot.type] += 1
```
- **`index` = 本系统里同类型槽的序号**：第 0 个 `layerimage` 发射器配 `index 0`，第 1 个配 `index 1`，和 `collisionmodel` 的序号各数各的；与 `rec+0x78`（绝对槽号）不是一个数。
- 没有匹配的槽，`slot+8` 保持 0：发射时表为空，`cnt = 0`，永远不发（3.1）。
- `id == 0` 的依赖有效位为 0，永远绑不上。
- **子系统与事件实例：** 静态子系统（`0x14022f055`）、事件实例（模拟里 `0x1402374d2`、发射里 `0x14023aff3`）创建后都调 `FUN_14022cfa0(子 sys, [父 sys+8]+0x940)`，即用**同一个粒子对象**的 `dependencies`，子系统的计数从 0 重新数【确：调用；推：`[sys+8]` 是所属粒子对象】。

### 1.6 依赖记录（服务 `svc`）【确】

- 找：遍历 `svc+0xa0`（`ctx+0x1b00`）链表，`rec.id == id` 且 `mask` 字符串逐字节相同 → 引用计数 `+0` 加一、`+4` 记当前帧号，复用。所以**同一场景里 `(id, mask)` 相同的依赖共享一张表**（跨发射器、跨粒子对象）。
- 建（`0x14022e1e0` 起，0xd8 字节）：引用计数 1，`+0x10 = id`，`+0x18 = mask`，`+4` = 帧号，`+0x58 = 1.0`，其余 0；`mask` 非空时 `+0x40 = FUN_14014cf90(ctx+0x1520, mask, 0)`（按名字取纹理）。新建前若引用计数为 0 的旧记录超过 3 条，先全部释放。
- 记录布局（下文用到的）：

| 偏移 | 含义 |
|---|---|
| `+0x00` | 引用计数 |
| `+0x08` | 状态：0 待渲染、1 待读回、2 有表（2.1） |
| `+0x10` | 图层 id |

### 1.7 依赖的图层不存在 / 类型不对【确】

## 2. 候选表（`FUN_1401d3ae0(svc, dep, &out)`）

### 2.1 状态机与「同帧不连做」的门【确】

每次调用（每个发射器每个发射帧一次）：
```
if dep.layer == null: 解析图层（1.7）；仍为空 → return false
elif dep.state == 2:                               // 0x1401d3b10
    out = &dep.table
    dep.L = L.vfunc_0x80()                         // 刷新图层矩阵，见 4
    if RT(L).w != dep.w || RT(L).h != dep.h:       // 合成 RT 尺寸变了
        释放 staging；dep.state = 0
    return dep.table 非空
if !(L+0x304 & 0x1000):                            // 0x1401d3c0d
    L+0x304 |= 0x1010；原来没有 0x10 时调 L.vfunc_0x110（重建资源）
    return false
if !(L.vfunc_0x68() || 父链可见(L)) || L+0x2c8 == null: return false
if dep+0x48 == 0 || dep+0x4c == ctx.frame:         // 0x1401d3c72
    dep+0x48 = 1；dep+0x4c = ctx.frame；return false
if dep.state == 0: 渲染 + 拷贝（2.2）；dep.state = 1
elif dep.state == 1: 读回 + 建表（2.3）；dep.L = L.vfunc_0x80()；记 w、h；puppet 处理（2.6）；dep.state = 2
out = &dep.table；return dep.table 非空
```
- `L.vfunc_0x68` 对图像层是 `FUN_1401ea2d0`：`(可见 && 父链可见) || (+0x304 & 0x1100)`（rea-p8-render）。因为上一步保证了 `0x1000`，这里恒真：**被依赖图层隐藏了也照样出表**（它照常画进独占 RT，只是不上屏）。
- 门：`+0x48` 一旦置 1 就不再清，所以它只挡「第一次」和「与第一次同一帧」。帧号 `ctx+0x144` 只在帧函数里加，预热期间不变。
- **一张新表的时间线**（被依赖图层在场景构造时已有 `0x1000`，1.4 第 8 条）：
  1. 第 1 个发射帧：解析图层 → 门记帧号 → 假；
  2. 第 2 个发射帧：状态 0 → 渲染、拷进 staging → 状态 1，表仍空 → 假；
  3. 第 3 个发射帧：状态 1 → 读回、建表 → 状态 2 → **真，开始发射**。
  - 如果图层不是在场景构造时置的 `0x1000`（运行中才建的粒子对象等），前面再多一个「置 `0x1010`」的假帧。
  - 读回的是第 2 帧更新阶段拷的内容，即第 1 帧渲染结束后合成 RT 里的画面。
- **预热：** 整段预热在加载的同一帧里，最多走到「门记帧号」，**一颗 `layerimage` 粒子都不出**。
- 两个发射器共享一条记录时，同一帧里后一个会接着推进状态（例如 0 → 1 之后马上 1 → 2，此时 Map 会等 GPU 完成刚提交的拷贝）【推】。

### 2.2 状态 0：降采样渲染（`0x1401d3caa`–`0x1401d4065`）【确】

尺寸（`W`、`H` = 合成 RT 的 `u16` 宽高 `RT+0x14` / `+0x16`）：
```
if W > 3840 || H > 2160:
    a = f32(W) / f32(H)                       // cvtdq2ps，divss
    if a >= 1.7777778:  W' = 3840；H' = cvttss2si(3840.0 / a)
    else:               W' = cvttss2si(a · 2160.0)；H' = 2160
else: W' = W；H' = H
w4 = max(2, W' / 4)；h4 = max(2, H' / 4)      // 有符号整除（向 0 截断）
dep.s = f32(W) / f32(w4)                      // 只算 x 方向
```
- 降采样 RT：设备虚函数 `+0x70`（`FUN_14009ada0`）`(w4, h4, 1, 名字 0, 颜色格式 0, 深度 0x1b, 2, 1)`。颜色格式 0 经 `FUN_1400d2a20` 映射成 DXGI 0x1c = `R8G8B8A8_UNORM`，深度 0x1b = 无。staging（`dep+0x50`，第一次时建）：同尺寸，参数 `(…, 0, 0x1b, 0x10000002, 5)`。
- 材质：`materials/util/downsample_quarter.json`（`FUN_140150110(ctx+0x1630, …)`），组合键 `WRITEALPHA = 1`；`dep+0x40`（`mask` 纹理）非空时再 `OPACITYMASK = 1`。两种各缓存一份（`svc+0x88` 无 `mask`、`svc+0x90` 有）。材质纹理槽：`mat+0xd0 = RT(L)+0x20`（合成 RT 的颜色纹理），`mat+0xd8 = dep+0x40`【推：两个槽是 `g_Texture0` / `g_Texture1`】。
- 画：压入降采样 RT → 绑定材质 → 设备 `+0xd8(1)` → `(*(ctx+0x48))->+8` 画全屏四边形 → 设备 `+0xd8(1, 0)` → 解绑 → 弹出；`staging->+0x18(RT)` 拷贝（CopyResource）；`FUN_1401ab5f0(ctx+0x16c0, RT)` 归还 RT【推：`+0xd8` 是混合 / 写掩码状态，四边形覆盖整张 RT】。
- 着色器（WPE `assets/shaders/downsample_quarter.*`，原样）：
  ```glsl
  // vert：a_TexCoord 是全屏四边形的 UV；g_Texture0Texel = 1 / 合成 RT 尺寸
  v_TexCoord[0] = a_TexCoord - g_Texture0Texel.xy * 2;
  v_TexCoord[1] = a_TexCoord + g_Texture0Texel.xy * 2;
  v_TexCoord[2] = a_TexCoord + vec2(-g_Texture0Texel.x, g_Texture0Texel.y) * 2;
  v_TexCoord[3] = a_TexCoord + vec2(g_Texture0Texel.x, -g_Texture0Texel.y) * 2;
  v_TexCoordBase = a_TexCoord;
  // frag
  albedo = (tex0(v0) + tex0(v1) + tex0(v2) + tex0(v3)) * 0.25;
  #if OPACITYMASK  albedo.a *= tex1(v_TexCoordBase).r;  #endif
  #if WRITEALPHA   gl_FragColor = albedo;  #else  gl_FragColor = vec4(albedo.rgb, 1.0);  #endif
  ```
  即每个输出像素取四个对角双线性样本的平均；`mask` 的 R 通道按整个图层的 UV 乘到 alpha 上。合成 RT 的采样器跟着它自己的纹理标志（双线性 / 点采样）【推】。`w4 ≠ W/4` 时（大于 3840×2160 被压过的图层）四个样本盖不全源像素。
- 写进 RGBA8 时按 UNORM 量化（`round(v·255)`）【推：D3D 规则】。

### 2.3 状态 1：读回与建表（`0x1401d4073`–`0x1401d4249`）【确】

```
w = staging.w；h = staging.h                    // [tex+0x20] / [tex+0x24]，即 w4、h4
buf = 读回(staging)                              // tex->vfunc_0x40(buf, 0)，w·h·4 字节
hs = dep.s · 0.5
dep.table.clear()
for x in 0 .. w−1:                               // 外层 x（esi）
    for y in 0 .. h−1:                           // 内层 y（edi）
        i = (y·w + x)·4
        if buf[i+3] < 0x7f: continue             // 0x1401d411d：alpha ≥ 127 才收
        e.r = buf[i]；e.g = buf[i+1]；e.b = buf[i+2]；e.bone = 0xff
        e.x = (i16) cvttss2si((dep.s · f32(x) − f32(W >> 1)) + hs)
        e.y = (i16) cvttss2si((dep.s · f32(y) − f32(H >> 1)) + hs)
        dep.table.push(e)
```
- **入表顺序是列优先**（x 外层），注入随机数逐粒子对照时下标 → 像素的映射要照这个顺序。
- 只看 alpha，阈值 127（8 位），不按亮度、不按权重重复，一个像素一项。
- `f32(x)` 是 `cvtsi2ss` 64 位无符号转浮点；`W >> 1`、`H >> 1` 是整数右移（奇数宽高丢掉 0.5）；`y` 也乘 x 方向的 `s`。
- 坐标单位是合成 RT 像素，原点在 RT 中心，**y 向下**（发射时取负，3.5）【推：RT 第 0 行是图层图像的上边】。
- 建完：`dep.L = L.vfunc_0x80()`（4）；`FUN_1401d6d30(svc, dep)`（puppet，2.6）；`dep+0x5c/+0x60 = W/H`；状态 2。

### 2.4 雨景 `3834803915` 的算例（`example.py`，float32）

被依赖图层 229 的合成 RT 按 `size` 4025×2460（P5 的规则）：`a = 1.6361789 < 1.7777778` → `W' = 3534`、`H' = 2160` → `w4 = 883`、`h4 = 540`，`s = 4.558324`；`x' ∈ [−2009, 2010]`、`y' ∈ [−1227, 1229]`。发射器 JSON 只有 `rate 500`，所以 `flags = 0x10000`：颜色乘像素、无抖动、速度 0、不刷新。

### 2.5 `0x20000`：定时重建（`0x140238d4f`–`0x140238d90`）【确】

每个发射帧（`n > 0` 才进分支，`0x140237c0b`），在取表之前：
```
rec+0x7c = dt' + rec+0x7c                       // addss，dt' = 发射函数的第 2 参数
if rec+0x7c > 1.0:                              // comiss，严格大于
    rec+0x7c = fmodf(rec+0x7c, 1.0)             // FUN_14041d0c0 = CRT fmodf
    FUN_1401d42b0(svc, dep)                     // 链表里这条记录状态不是 1 就置 0
```
- 计时按 `dt'`（含实例 `rate`），只在要发射的帧累加；记录是共享的，任何一个带 `0x20000` 的发射器都会让共享表重建。
- 重建不断发射：状态 0 那次照常返回旧表（表 vector 要到状态 1 才清空重填），下一个发射帧换成新表。

### 2.6 puppet 图层（`FUN_1401d42e0` / `4330` / `4360` / `4400` / `FUN_1401d6d30`）

- `FUN_1401d42e0(dep)`：图层类型 1 且 `P = L+0x4b8` 非空、`P+8`（mdl）非空 → puppet【确】。
- `FUN_1401d4330(dep)`：骨骼数 = `P+0x38` vector（每根 0xf0）的长度【确】。
- 建表后 `FUN_1401d6d30`【确：结构；推：几何细节】：
  - 每根骨骼的绑定姿势：有 MDLE（`P+0x68` 非空）取它，否则取骨骼局部矩阵（`bone+0x20`），沿父链（`bone+0x60`）相乘；`dep+0x68[b] = inverse(绑定姿势[b])`（`FUN_14005f730`，0x40 一根）。
  - 给每个表项定骨骼号（写字节 3）：遍历 mdl 的命中盒（`P+0x1a8`，每根骨骼一项 0x4c：半边长 vec3 + 矩阵，rea-p12-mdl）。把盒子按绑定姿势变成表坐标里的矩形，表项（`(x', −y')`）落在矩形里就记这根骨骼；落在多个盒子里的记为「有歧义」；一个盒子都不在的取「出界量最小」的盒子。最后有歧义的取最近的无歧义表项的骨骼号（平方距离，表坐标）。
- 发射时（3.8）：`K[b] = Pose_cur[b] · dep+0x68[b]`（`FUN_1401d4360`，`Pose_cur = P+0x2c8`，骨骼号越界或 puppet 失效时用单位阵 `0x1404e10b0`），即这根骨骼的蒙皮矩阵，出生点跟着变形走。
- 本次没逐行核对的：命中盒的矩形换算（乘法顺序、半边长取哪两个分量）、「出界量」的定义（各轴越界量取最大）。雨景不涉及 puppet。

## 3. 每颗粒子（`FUN_1402378a0` 类型 3 分支，`0x140238c45`–`0x14023ae1f`）

### 3.1 数量与丢失【确】

```
cnt = min(sys+0x348 − sys+0x344, n)              // 0x140238c4d，无符号
… 取表（2.1）…
if 表为空或取表失败: cnt = 0                      // 0x140238dc4
```
- `n` 已经在 A1 段从 `acc` 扣掉（rea-p4b A1），所以取不到表的帧要发的粒子**直接丢掉，没有欠账**；周期发射、`duration` 照常走。
- 发射以外的分支状态（`rec+0x7c` 计时、`rec+0xb8` 写回、骨骼缓存清标志）都只在 `n > 0` 的帧发生。

### 3.2 矩阵准备【确】

```
M3   = I3                                         // FUN_1401a27f0(·, 1.0)，0x140238c75
A    = I4                                         // rbp+0x70
Ap   = I4                                         // rbp+0x410
if sys+0x20 bit0（世界空间）:
    M3 = mat3(M)                                  // FUN_1400dd7d0(*(ctx+0x30))
else:
    A = Ap = inverse(M)                           // FUN_14005f730，GLM 的 4×4 求逆
Bprev = Ap · rec[0xb8]                            // FUN_14005ecb0(左, 右) = 左·右，0x140238d3a
slot = sys.slots[rec+0x78]；dep = slot+8
（0x20000 计时，2.5）
if dep && FUN_1401d3ae0(svc, dep, &tbl): A = A · dep.L    // FUN_1401842d0，0x140238dbd
A3 = mat3(A)；t = A 的第 3 列                      // 0x140238dd6 / 0x140238de4
```
- `M` = 模型栈顶。本地系统 `A = M⁻¹ · L`（把图层上的点搬进粒子对象的本地空间），世界系统 `A = L`。
- `L = dep.L` = 图层虚函数 `+0x80`：图像层 `FUN_1401fd3f0` = 世界矩阵（`FUN_1401850a0`，含父链、`angles`、`scale`），`+0x4b1` 置位时再右乘 `T(L+0x2f8, +0x2fc, +0x300)`（`alignment` 偏移，rea-p8）；文本层 `FUN_140256e10` 总是乘偏移。`size` 不在矩阵里（坐标已经是像素）。
- `M3` 传给 initializer（`FUN_14023b340` 的第 3 参数，`velocityrandom` 等用）：本地系统是单位阵，世界系统是 `mat3(M)`。和 `sphererandom` / `boxrandom`（传 `mat3(cp)`）不同。
- 不读控制点（同 rea-p4c-sim 第 3 节）。

### 3.3 抽表项：`uniform_int_distribution(0, N−1)`（`0x140238f0a`–`0x140238f8d`）【确】

`N = 表长`，`r13 = N − 1`（64 位），状态指针 `q = ctx+0x1cd0` 放在栈上，传 `&q`：
```
if (u32)r13 == 0xffffffff: idx = next()           // N 不可能为 0（表空时 cnt = 0），实际走不到
else:
    R = N                                         // 32 位
    m = (u64)next() · R
    if (u32)m < R:
        t = (~(N − 1)) mod R                      // = 2³² mod N，div 一次
        while (u32)m < t: m = (u64)next() · R
    idx = m >> 32
e = tbl[idx]
```
- `next()` = `FUN_14007d8f0(&q)`。和 `colorlist` 的 `FUN_14024f410` 是同一个算法（rea-p4g）。通常 1 个 u32，`N` 不是 2 的幂时以 `(2³² mod N)/2³²` 的概率多抽。
- 表项读法：`ix = (i32)(i16)(e >> 32)`、`iy = −(i32)(i16)(e >> 48)`（先符号扩展再取负，`0x140238f9c` / `0x140238fab`），各自 `cvtdq2ps`。

### 3.4 抖动（`0x140238fad`–`0x14023901b`）【确】

```
jx = jy = jz = 0
if flags & 0x80000:
    jx = uA · rec[0x94] + rec[0x88]               // 先 x
    jy = uA · rec[0x98] + rec[0x8c]               // 再 y
    jz = uA · rec[0x9c] + rec[0x90]               // 最后 z
px = f32(ix) + jx；py = f32(iy) + jy；pz = jz + 0.0
```
`uA` 是 `FUN_1401f4bc0(ctx)`，每次 1 个 u32。抖动加在表坐标（合成 RT 像素、y 向上）上，之后才乘 `A`。

### 3.5 出生点（非 puppet，`0x1402396d4`–`0x14023975f`）【确】

`a_ij` 为 `A3` 第 i 列第 j 个分量，`t` 为平移：
```
X = tx + ((a10·py + a00·px) + a20·pz)
Y = ty + ((a11·py + a01·px) + a21·pz)
Z = tz + ((a02·px + a12·py) + a22·pz)
```
括号就是 `mulss` / `addss` 的实际顺序（float32，无 FMA）。写进位置列（`sys+0x2b0/0x2b8/0x2c0`）。没有按子帧错开出生时间，同帧出生的粒子不随时间分散。

雨景（本地系统，粒子对象与图层 229 的 `origin` 都是 2560 1080、无旋转缩放）：`A = M⁻¹·L = I`，出生点就是 `(x', −y', 0)`（对象本地）【推：两个对象都没有父】。

### 3.6 颜色：`0x10000`（`0x140239765`–`0x1402397cb`）【确】

```
保存 sys+0x3e0..0x3ef（实例颜色与 alpha，每颗粒子开头 0x140238ef3）
if flags & 0x10000:
    sys+0x3e0 = (f32(e.r) / 255.0) · sys+0x3e0    // divss 再 mulss
    sys+0x3e4 = (f32(e.g) / 255.0) · sys+0x3e4
    sys+0x3e8 = (f32(e.b) / 255.0) · sys+0x3e8
… initializer 用 sys+0x3e0.. 作 rgb0 的初值（rea-framework Q5）…
恢复 sys+0x3e0..0x3ef（0x14023ab9b）
```
所以 `rgb0 = 像素 RGB / 255 × 实例颜色`，之后 `colorrandom` 等再乘。alpha 不动。像素颜色是降采样（四样本平均）之后、8 位量化的值。

### 3.7 速度：`0x40000`（`0x1402397d3`–`0x14023ab0d`）【确】

```
v = (0, 0, 0)
if flags & 0x40000:
    p4   = (f32(ix) + jx, f32(iy) + jy, pz, 1.0)          // FUN_14019d450(·, ·, 1.0)
    prev = (c3·1 + c2·p4.z) + (c1·p4.y + c0·p4.x)          // c_k = Bprev 的第 k 列（非 puppet）
    d    = ctx+0x14c                                       // 本帧 dt，不含实例 rate
    dv   = ((X − prev.x) / d, (Y − prev.y) / d, (Z − prev.z) / d)
    k    = uA · rec[0x84] + rec[0x80]                       // speedmin + u·(max − min)，都已乘 instanceoverride.speed
    v    = (k · dv.x, k · dv.y, k · dv.z)
写速度列（sys+0x2c8/0x2d0/0x2d8）
```
- 含义：出生点在这一帧里随图层（或 puppet 骨骼）移动的速度，乘一个随机倍数。图层不动时速度为 0。
- `Bprev = Ap · rec[0xb8]`，而 `rec[0xb8]` 在每个**取到表的发射帧**末尾写成本帧的 `dep.L`（`0x14023adef`–`0x14023ae17`）。所以它是「上一次取到表时的图层矩阵」；**解析时是单位阵**，第一次取到表的那一帧 `prev` 用的是 `I`，速度是 `(A − Ap)·p / d`，图层不在原点时会很大（WPE 的行为，开了 `0x40000` 才有）。
- 本地系统 `prev` 用的是**本帧**的 `M⁻¹`，粒子对象自己的移动不计入速度。
- `directions`、`speed` 等键不读；不开 `0x40000` 时 `speedmin` / `speedmax` 不起作用，速度恒为 0。

### 3.8 puppet 路径（`0x140239050`–`0x140239596`、`0x140239818` 起）【确：反编译；未逐条核对浮点顺序】

- 每个发射帧取表后：骨骼缓存 `rec+0xa0` 扩到骨骼数（`FUN_140251e60`），每项 0x84 = 当前矩阵（`+0`）、上一帧矩阵（`+0x40`）、两个有效标志（`+0x80`、`+0x81`），标志全部清 0（`0x140238e70`）。
- 每颗粒子：`b = e.bone`；缓存 `b` 当前无效时算 `C[b] = A · K[b]`（`K` 见 2.6）并置有效；出生点 `= C[b] · (px, py, pz, 1)`。
- `0x40000`：缓存 `b` 上一帧无效时算 `Cp[b] = Ap · (Wprev[b] · dep+0x68[b])`（`FUN_1401d4400`，`Wprev = P+0x348`，`P+0x340` 为空时用单位阵 `0x1404e10f0`），`prev = Cp[b] · (p, 1)`。puppet 路径**不用 `rec[0xb8]`**。
- `e.bone = 0xff`（没分到骨骼）时缓存下标越界（`0xff · 0x84`），`FUN_1401d4360` 不写，读到的是越界内存【推：WPE 缺陷；`FUN_1401d6d30` 在至少有一个命中盒时会给每项分骨骼，正常走不到】。

### 3.9 出生之后【确】

写位置、速度 → `FUN_14023b340(sys, 槽, &M3)`（initializer：先抽 `R = uA`，写缺省值，按 JSON 顺序执行）→ 恢复实例颜色 → 存活数加一 → 槽号等于高水位时高水位加一 → 两张新粒子槽号表照 `sphererandom` 同样追加：`sys+0x408`（`sys+0x41 & 0xc` 时，发射函数尾 `0x14023aefa` 起按它抽 `eventspawn` / `eventfollow` 的概率）、`sys+0x218`（`sys+0x208` 非空时【推：rope 索引表】）。全部粒子出完后写回 `rec[0xb8]`（3.7）。

## 5. 随机数（为注入做准备）

### 5.1 生成器【确】

- 状态 `ctx+0x1cd0`：`u32 idx`，之后 `u32 x[1248]`（MSVC `std::mt19937` 的双倍缓冲：`idx == 624` 时生成后半 `x[624..1247]`，`idx ≥ 1248` 时 `FUN_14007fa20` 生成前半并把 `idx` 归 0），输出就是标准 MT19937（tempering `y ^= y>>11; y ^= (y & 0xff3a58ad)<<7; y ^= (y & 0xffffdf8c)<<15; y ^= y>>18`）。
- 两个「取下一个 u32」：
  - `FUN_14007f5b0`（`0x14007f5b0`）：`rcx` = 状态指针（`ctx+0x1cd0`），返回 `eax`；入口 `push rbx; sub rsp, 0x20; mov eax, [rcx]`，前 0x20 字节没有分支目标，可以直接挂钩。
  - `FUN_14007d8f0`（`0x14007d8f0`）：`rcx` = 指向状态指针的指针（`std::uniform_int_distribution` 内部调引擎的形状），入口 `push rbx; sub rsp, 0x20; mov rbx, [rcx]`，其余与上一个逐条相同。
- **没有内联副本：** tempering 常量 `0xff3a58ad` / `0xffffdf8c` 在全文汇编里只出现在这两个函数（`0x14007da80`、`0x14007f73d` 两处各一对）；扭转常量 `0x9908b0df` 另外只在 `FUN_14007fa20`（被这两个函数调用）里；`ctx+0x1cd0` 的全部 57 处引用里，构造函数的 2 处是写 `idx = 624`，其余 55 处都是 `lea` / `add` 算出地址传给这两个函数或它们的包装；构造函数之外没有指令直接读写 `ctx+0x1cd4` 起的状态数组。
- `FUN_14007d8f0` **还被别的引擎用**：`FUN_140075a90`（`0x140076ac6` 起）用的是 `0x1404dfd20` 处的静态 `mt19937`（按时间加计数器播种，主线程，【推：播放列表】）。挂钩必须按状态指针或线程过滤。

### 5.3 一个场景一份、在哪条线程【确，引 rea-p6a-sound 9.4–9.6】

- `ctx = R+0x10`，`R` 由场景渲染线程在建渲染器时构造（`FUN_14017c6d0`，调用点 `0x140110ae8`），**每条渲染线程一个，每个窗口一条渲染线程**；桌面壁纸、各个测试窗口各有自己的 `ctx` 与引擎。视频壁纸的渲染器（`0x14012b8c2`）另有一份，与场景无关。
- 场景加载（`FUN_140113c80`，`0x140110c5a` 在建完渲染器后、帧循环之前直接调）、`starttime` 预热（加载里）、每帧更新与发射、`FUN_1401d3ae0` 的 GPU 渲染与 Map 都在这条渲染线程上。
- 同一窗口的重载（`0x465`）复用渲染器，**不重新播种**，引擎状态接着走。

### 5.4 播种【确】

构造 `FUN_14017c6d0`（`rdi = ctx`）：
1. `0x14017d4e7`–`0x14017d523`：先按 5489 初始化（`x[0] = 5489；x[i] = 1812433253·(x[i−1] ^ (x[i−1] >> 30)) + i`，`idx = 624`）。
2. `0x14017d699`–`0x14017d6f8`：无条件重播种。`_Xtime_get_ticks()`（`0x140291420`，`GetSystemTimePreciseAsFileTime − 0x19DB1DED53E8000`，1970 年起的 100 ns 数）除以 10000（魔数 `0x346dc5d63886594b`，`sar 0xb`）得毫秒，**`0x14017d6bc` `mov [rdi+0x1cd4], edx` 截成 32 位作种子**，再按同一递推填满 624 个字、`idx = 624`。
- 等价于 `std::mt19937(ms_since_epoch & 0xffffffff)`；我们这边用同一个种子跑标准 MT19937 就得到逐位相同的 u32 串。

### 5.5 注入的可行性【推：静态判断，没跑】

可行，有三种落点，按稳妥程度：
1. **改种子 / 写状态（推荐）：** 在 `0x14017d6bc` 把 `edx` 换成约定种子，或在 `FUN_14017c6d0` 返回时把 `ctx+0x1cd0..` 整块写成 `mt19937(S)` 的初始状态（`idx = 624`，`x[0..623]`）。之后 WPE 这边不用每次调用都进钩子，我们用 `SeededRandom` 的 MT19937 源跑同一个 `S`。时机在加载之前，所以预热、加载时的声音 / 相机随机也都在同一串上。
2. **逐次顶替：** `Interceptor.attach` 两个函数的 `onLeave` 改 `eax`。过滤：`FUN_14007f5b0` 看 `rcx`，`FUN_14007d8f0` 看 `[rcx]`，等于目标 `ctx+0x1cd0` 才换（可用 `ctx+0x20/0x24 = 0, 1`、`ctx+0x28/0x2c = 1e-5, 1` 校验是渲染上下文）；或按线程号过滤（同 `frida_input` 用 `ScreenToClient` 认渲染线程的做法）。顺便记 `this.returnAddress`，就得到 WPE 实际的抽取顺序，可直接和我们的顺序逐条对。
3. **只读状态：** 在某帧开头（例如帧函数 `FUN_14017fa70` 入口，或目标线程上第一次调用时）读出 `idx` 与 1248 个字，我们这边从同一状态继续。不改 WPE，但要先实现「从任意状态起跑」的 MT19937。

风险：
- **线程与时机：** `frida_input` 是窗口出来之后才认线程，而渲染器构造、加载、预热紧跟在建线程之后，等认出线程时这些已经抽过了。要覆盖加载，钩子得在 `open_wallpaper` 之前装好，挂 `FUN_14017c6d0`（或 `0x14017d6bc`）认「新建的渲染器」，事后用窗口句柄的线程号（`GetWindowThreadProcessId`）核对是不是自己的窗口，防止别的会话同时开窗。
- **所有消费者共用一串：** 5.2 的任何一个用到了，两边都要按同样的顺序抽。测试工程最好只放被测的粒子系统，不放声音 `random`、相机路径 `random`、别的随机发射器；`eventspawn` 的概率即使是 1 也照抽（雨景就有）。
- **`FUN_14007d8f0` 的别的使用者**（主线程静态引擎）必须过滤掉，否则会改坏 WPE 的播放列表随机。
- **逐次挂钩的开销：** 发射多的场景每帧几千到几万次调用，JS 的 `onLeave` 会拉长帧时间、改变 `dt`；用 CModule 或方案 1 避免。
- **拒绝抽样：** 下标多抽一次的情况两边都要实现（3.3），用非 2 的幂的表长时尤其要测。
- **表本身要一致：** 逐粒子对照的前提是表项顺序与坐标相同（2.3 的列优先、截断、`s`），而表来自 GPU 降采样 + 8 位量化。确定性工程应让 alpha 只取 0 / 255、按 4 像素对齐成块，避开四样本平均落在阈值附近；或者用 Frida 直接读 WPE 内存里的表（`svc+0xa0` 链表 → 记录 `+0x80..+0x88`）和我们的表逐项比。
- **前两个发射帧不发：** 两边的启动延迟要一致（2.1），否则从第 3 帧起抽取次数就错开。
- `hsvcolorrandom` 走 CRT `rand()`，这条注入管不到。

## 6. 对实现的含义

1. **解析：** 发射器补 `speedmin` / `speedmax` / `offsetmin` / `offsetmax`、`flags` 缺省 0x10000；粒子对象的 `dependencies` 按 1.4 的门过滤、按 1.5 用「同类型槽序号」配 `index`，子系统同样用对象级的列表；`mask` 是纹理路径。
2. **表：** 运行时建（要用合成 RT 的实际画面，包括 effect）：在 GPU 上照 `downsample_quarter`（四个对角双线性样本平均、`mask.r` 乘 alpha）画到 `w4 × h4` 的 RGBA8，读回后按列优先收 alpha ≥ 127 的像素，坐标照 2.3 的截断公式。被依赖图层要走独占 RT（P8 已有），隐藏也画。
3. **时机：** 照 2.1 的三步延迟（读回本来就是异步的，可以自然地「第 3 个发射帧才有表」）；表没好的帧丢掉要发的粒子；预热不发。
4. **每颗：** Lemire 下标 → 抖动 → `A = M⁻¹·L`（`L` 是绘制矩阵、每帧现取）→ 颜色乘像素 → 可选速度（`rec[0xb8]` 从单位阵起）→ initializer（`M3` 本地单位阵）。
5. **刷新：** `0x20000` 按 `dt'` 每秒一次，旧表照用到新表出来。
6. **puppet：** 照 2.6 / 3.8，语料暂不需要，可先照报。

## 7. 仍未知 / 没查

- 读回函数（staging 纹理虚函数 `+0x40`）是否按 `RowPitch` 逐行拷成紧凑的 `w·4` 字节：建表循环按紧凑布局取下标，【推】是。
- 设备 `+0xd8` 的两次调用具体设了什么状态、降采样前 RT 是否清屏（全屏四边形覆盖整张 RT 时不影响结果）。
- 合成 RT 的第 0 行是不是图层图像的上边（决定 y 的符号是否需要再翻一次）：按 D3D 约定和 WPE 画合成 RT 的 UV【推】是。
- 文本层作依赖时 `L+0x2c8` 是不是它的独占 RT（文本层的 `+0x110` 建 RT 没读，rea-p8-render 同样留了这一条）。

- `collisionmodel` 的使用（operator 26）。

## 8. 建议的确定性实验

全部用正交场景、本地系统、`rate` 固定、`lifetimerandom` 等收成 min = max；遮罩图自己生成。

1. **单块像素定位：** 依赖图层 64×64、只有一个 4×4 对齐块 alpha 255（其余 0），`flags 0x10000`。读码预测降采样后恰好 1 项，`x' = trunc(s·x − 32 + s/2)`（`s = 4`），出生点钉死；再把块移到图像各角，核对 y 取负与列优先。
2. **启动延迟与预热：** 同一工程看第几帧出第一颗（预测第 3 个发射帧）；加 `starttime 2` 预测预热不出粒子，开场同样延迟两帧。
3. **阈值：** 块的 alpha 取 126 / 127 / 128（整块同值，降采样后仍是该值），预测 ≥ 127 才出。
4. **大图压缩与 `s`：** 图层 4025×2460（同雨景）与 3840×2160、4000×1000，核对 `w4`、`h4` 与 y 用 x 方向的 `s`（统计出生点的 y 范围）。
5. **矩阵：** 图层平移 / 旋转 / 缩放 / `alignment` / 有父对象，粒子对象平移；世界系统对照。脚本运行中移动图层，预测出生点当帧跟上。
6. **隐藏：** 依赖图层 `visible false`，预测照常发射。
7. **刷新：** 依赖图层的纹理用帧表或脚本换纹理，`flags 0x10000` 与 `0x30000` 对照：前者表不变，后者每秒更新一次且不断发。
8. **抖动与速度：** `0x80000`（`offsetmin/max` 各轴不同）看分布范围；`0x40000` + 图层匀速移动，预测速度 = 移动速度 × `[speedmin, speedmax)`，第一次取表那帧速度异常大（`rec[0xb8]` 是单位阵）。
9. **颜色：** 遮罩块涂纯红 / 半灰，`flags` 带不带 0x10000，看粒子颜色。
10. **依赖绑定：** 一个粒子定义里放两个 `layerimage`，`dependencies` 给 `index 0` 与 `index 1` 指向不同图层；再给一条缺 `index` 的、一条 `type` 拼错的、一条 `id` 不存在的，预测只有前两条生效、其余不发。
11. **随机数注入（0b）：** 先按 5.5 方案 1 在 `sphererandom` 工程上验证逐粒子相同，再用实验 1 的多块版本（每块一个表项、块数取非 2 的幂以触发拒绝抽样）验证下标映射。
