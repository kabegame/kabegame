# WPE 2.8.42 P4h 粒子 operator `boids` 静态逆向

**概括**
- **键与缺省（`FUN_1401bf700`）：** 共 7 个键。`separationthreshold`（正交 20 / 透视 0.02）、`neighborthreshold`（正交 50 / 透视 0.2）、`maxspeed`（正交 500 / 透视 1）、`separationfactor`（15）、`alignmentfactor`（1）、`cohesionfactor`（2）、`flags`（**1**）。三个阈值的缺省按场景是否正交投影切换（`FUN_14010daa0`，`ctx+0x118` bit10）。没有邻居数上限、没有任何钳制；`flags` 只读 bit0【确】。
- **记录：** 类型 0x11、长度 0x50，负载从 `rec+0x10` 起：`+0x10` 分离阈值 ×4、`+0x20` 邻居阈值 ×4、`+0x30` `maxspeed` ×4、`+0x40` 分离系数、`+0x44` 对齐系数、`+0x48` 聚合系数、`+0x4c` `flags`（u32）。operator 不写回记录，不登记 `instanceoverride` 绑定【确】。
- **`flags` bit0 = 限速：** 置位时（缺省就是置位）新速度 `v'` 满足 `|v'|² > max(|v|², maxspeed²)` 才缩放成 `v'·rsqrt(|v'|²)·maxspeed`；也就是旧速度已超过上限时，只要新速度没变得更快就不管，变快了就一下压回 `maxspeed`。语料 `flags 0`，不限速【确】。
- **系数乘的是 `k`，不是 `h`：** 三个系数各乘 `S·k`（`S` 见下，通常为 1），`k` 是解释器的第二个参数 `k0 = pow(min(1, 0.025/ctx.dt), 0.7)·dt'`（两遍模式各为 `k0/2`），即 `movement` 里给 `drag` 用的那个量。帧时间 ≤ 0.025 s 时 `k = dt'`；30 fps 时只有 `0.8176·dt'`【确】。
- **每粒子公式（写到速度，不动位置）：**
  - 邻居条件：`d < neighborthreshold`，分离条件：`d2 ≠ 0 且 d < separationthreshold`，**都是严格 `<`**，比的是近似距离 `d = d2·rsqrtps(d2)`，不是开方【确】。
  - 自己（`d2 = 0`）因为 `rsqrtps(0) = +∞`、`∞·0 = NaN`，两项都不算；任何与自己重合的粒子同样不算【确】。
  - `Δv = (平均邻居速度 − v)·A' + rcpps(nS)·Sep'·Σ(sepT·rsqrtps(d2) − 1)·(p − p_j) + (平均邻居位置 − p)·C'`，平均值用 `rcpps(n)` 作 1/n，`A' = S·A·k` 等；三项按「对齐 + 分离」再「+ 聚合」相加，最后 `v += Δv`【确】。
- **邻居遍历：** SIMD 四粒子一组，对每个组 `i` 全遍历其它组 `j`（组序升序），组内用 4 次车轮式移位比完 16 对。没有网格，也没有邻居数上限【确】。
- **WPE 的缺陷——邻居存活位不随移位：** 判「邻居活着」用的是 `life[4j + l] ≠ 0`（`l` 是被更新粒子所在的 lane），**而不是那个邻居 `4j + ((l − k) mod 4)` 自己的 `life`**。结果：死槽（保留最后的位置、速度，且 `movement` 照常在死槽上积分）与尚未出生的槽，只要同组里与被更新粒子同 lane 的那颗活着，就会被算作邻居【确】。被更新粒子自己是否活着不检查（死槽的速度也照改）。
- **写回：组级的「边算边写」：** 一个组的 4 颗算完立即写回速度，后面的组读到前面组已改过的速度（只影响对齐项；位置不变，聚合、分离不受影响）；同一组的 4 颗彼此读到的都是旧值【确】。
- **大系统分帧：** `S = floor(hw/200) + 1`（`hw` = 高水位 `sys+0x340`）。`S > 1` 时一帧只更新 `1/S` 的组、每组只看 `1/S` 的组，系数乘 `S` 补偿，起点按帧计数器 `ctx+0x144` 轮转。语料 `maxcount 16`，`S` 恒为 1【确】。
- **空间：** 直接读写位置 / 速度列，不用任何矩阵、不读控制点，所以在模拟空间里算（本地系统是本地坐标，世界系统是世界坐标），阈值也在那个空间里比；每个 `sys`（顶层、static 子系统、事件实例）只在自己的列里找邻居【确】。
- **速度与时间系数：** 不乘 `instanceoverride.speed`；`instanceoverride.rate` 经 `dt'` 进 `k`；场景 `rate` 经 `ctx.dt` 进 `dt'`，`0.025/ctx.dt` 里看的是不乘实例 `rate` 的帧时间【确】。

### 1.1 名字与记录【确】

- 缺省值函数 `FUN_1401bf700(模块 JSON, dl = [rbp+0x2238])`（`0x1401ce438`），`[rbp+0x2238]` 是 `FUN_14010daa0` 的返回值（`0x1401c5b7e`）：`ctx+0x118` bit10 = 场景正交投影（rea-p4a）。只在键不存在时补。

## 2. 每帧公式

入口：operator 跳转表 `0x14024bb58` 第 16 项（类型 − 1）= `0x140244121`，下一项（capvelocity）`0x1402446fd`。段尾 `jmp 0x140240ef1` 回到通用的「下一条记录」（`0x140240272` → `0x140240279`）。

### 2.1 进入时的寄存器【确】

- `rsi = sys`（`0x14023fc05`），`[rbp+0x2000]` 是 `rcx` 的 home 槽，同为 `sys`，循环中用来恢复 `rsi`。
- `xmm8 = broadcast(k)`：`0x14023fbfa`–`0x14023fc0c` 由第三参数 `xmm2` 铺满，每条记录结束在 `0x140240290` 从 `[rbp+0x5f0]` 恢复；分发器到 `0x140244121` 之间不写 `xmm8`。`h`（`[rbp+0xf0]`）在 boids 段里**没有被读**。
- `k` 的来源（`FUN_140236cd0`，`0x140237720`–`0x140237793`，本次复核）：`k0 = powf(min(1, 0.025/[ctx+0x14c]), 0.7) · dt'`（`0x140492630` = 0.025、`0x1404926c8` = 0.7，`FUN_14041e350` 是 powf【推】）；`1 ≤ fps ≤ 20` 时 `h, k` 各乘 0.5（`0x1404926c0`）并调两遍，否则一遍。

### 2.2 准备（`0x140244121`–`0x140244221`）【确】

```
hw  = sys+0x340
S   = floor(hw / 200) + 1          // mul 0x51eb851f; shr edx, 6  → /200
c   = [ctx+0x144]                  // 帧计数器，见 2.7
i0  = 4 · (c mod S)                // r12
stride = 4·S                       // r15
Sep' = broadcast((float)S · Sep) · k   // [rbp+0x250]，先 mulss 再 mulps
A'   = broadcast((float)S · A)   · k   // [rbp+0x260]
C'   = broadcast((float)S · C)   · k   // [rbp+0x90]
sepT = rec+0x10 ×4   → [rbp+0xc0]
nbT  = rec+0x20 ×4   → [rbp+0x200]
maxS = rec+0x30 ×4   → [rbp+0xa0]，maxS² → [rbp+0x80]
if i0 >= hw: 整条跳过
```

`S = 1` 时 `Sep' = Sep·k`，逐位等于 `Sep·k`（`1.0·Sep` 精确）。

### 2.3 遍历结构【确】

```
for (i = i0; i < hw; i += 4S):            // 组 i：槽 i..i+3，SIMD 四个 lane 一起算
    清零 10 个累加器（见 2.4）
    for (j = 4·((c + i) mod S); j < hw; j += 4S):   // 0x140244257–0x14024426c；S=1 时 j 从 0 起
        alive[l] = (life[j+l] != 0)                 // 0x1402442f4，只算一次，不移位
        for (k4 = 0; k4 < 4; k4++):                 // edx，0x140244310–0x14024450a
            邻居 lane：q(l) = (l − k4) mod 4        // k4=1 shufps 0x93，k4=2 0x4e，k4=3 0x39
            对 lane l：配对 (i+l, j+q(l))，有效位用 alive[l]
    算 Δv 并写回组 i 的速度（2.5、2.6）
```

- 每个组对**全部**组 `j`（含自己）比 16 对，所以 `S = 1` 时是完整的 O(n²) 全遍历，没有网格、没有上限。
- `j` 的上界是 `hw`，组按 4 对齐，所以 `[hw, ⌈hw/4⌉·4)` 里从没出生的槽也参与（列在分配时清零，`FUN_1401d3780` 调 `FUN_1404217a0(ptr, 0, size)`【推：memset】；而 `movement` 的循环也到 `⌈hw/4⌉·4`，这些槽会被重力积分出非零位置，rea-framework Q5「operator 在死槽上照跑」）。
- 每个 lane 的邻居求和顺序：`j` 升序，每组内依次是 lane `l, l−1, l−2, l−3`（模 4）。float 累加按这个顺序。

### 2.4 一对的计算（`0x140244396`–`0x1402444df`）【确】

对 lane `l`，记 `p = 本粒子位置`、`pj = 邻居位置`、`vj = 邻居速度`：

```
dx = px − pjx;  dy = py − pjy;  dz = pz − pjz
d2 = (dy·dy + dx·dx) + dz·dz            // 0x1402443c3 / 0x1402443c9：先 y² + x²，再 + z²
r  = rsqrtps(d2)                        // 0x1402443cc，近似 1/sqrt
d  = r · d2                             // 0x1402443d9，近似距离
mS = (d2 != 0) & alive[l] & (d < sepT)  // cmpneqps / cmpltps
mN = (d < nbT) & alive[l]
w  = (r · sepT − 1.0) & mS              // 0x1402443d2 / 0x1402443e7 / 0x14024440b
nS += mS ? 1 : 0                        // [rbp]
sepX += w·dx;  sepY += w·dy;  sepZ += w·dz          // [rbp+0x10] / +0x30 / +0xe0
nN += mN ? 1 : 0                        // [rbp+0x70]
sVx += mN ? vjx : 0;  sVy …;  sVz …     // [rbp+0x60] / +0x40 / +0x20
sPx += mN ? pjx : 0;  sPy …;  sPz …     // [rbp+0x100] / +0x170 / +0xd0
```

- **距离用平方后再乘 `rsqrtps`，不开方**；阈值比较是**严格 `<`**，比的是近似值 `d`，所以「正好等于阈值」的判定取决于硬件 `rsqrtps` 的表（Intel 与 AMD 不同）。
- **自己不算：** 自配对 `d2 = 0`，`rsqrtps(+0) = +∞`，`d = ∞·0 = NaN`，`NaN < 阈值` 为假，`mN`、`mS` 都是 0；分离另有 `d2 != 0`。与自己位置完全相同的粒子同样两项都不算。
- **分离权重：** `w = sepT/d − 1`（近似），`d → sepT` 时趋于 0、越近越大；方向 `p − pj` 指离邻居。乘的是位移向量本身，所以 `w·|p − pj| = sepT − d`（近似）。
- **存活判定的缺陷：** `alive` 来自 `life[j + l]`（`0x1402442df` / `0x1402442f4`，存进 `[rbp+0x1e0]`），在 `k4` 循环里不移位，而位置、速度六个向量都移了位（`0x140244338`–`0x140244391`）。所以配对 `(i+l, j+q(l))` 的有效性看的是槽 `j+l`：
  - `k4 = 0` 时 `q(l) = l`，判定正确；
  - `k4 ≠ 0` 时看的是「`j` 组里与本粒子同 lane 的那颗」；`j = i` 时就是本粒子自己。
  - 邻居自己的 `life` 从不检查，死槽保留的旧位置、旧速度（以及死后 `movement` 继续积分出的值）照样进均值。
- 被更新的粒子自己是死槽也照算、照写（没有对 `life[i+l]` 的门）。

### 2.5 合成 Δv（`0x140244583`–`0x140244630`）【确】

```
invS = rcpps(nS) · Sep' & (nS != 0)            // 0x140244583 / 0x14024458a / 0x140244594
invN = rcpps(nN)        & (nN != 0)            // 0x140244591 / 0x14024459b
A'' = A' & (nN != 0);  C'' = C' & (nN != 0)    // 0x1402445c9 / 0x1402445d0

Δx = ((invN·sVx − vx)·A'' + invS·sepX) + (invN·sPx − px)·C''
Δy = ((invN·sVy − vy)·A'' + invS·sepY) + (invN·sPy − py)·C''
Δz = ((invN·sVz − vz)·A'' + invS·sepZ) + (invN·sPz − pz)·C''
```

- 对齐：邻居平均速度减自己的速度；聚合：邻居平均位置减自己的位置；分离：分离向量之和除以分离邻居数。三者都是「平均」，**不按距离加权**（分离的 `w` 除外），**不归一化方向**。
- 1/n 用 `rcpps`（12 位近似）。即使 `n = 1`，Intel 上 `rcpps(1.0) = 0.99975586`，不是 1。
- 没有邻居时 `A''`、`C''`、`invN` 都是 0，对齐与聚合项为 ±0，不影响结果；分离同理。
- float 运算顺序：`invN·sVx` → 减 `vx` → 乘 `A''`；`invS` 是 `rcp·Sep'` 再与掩码 `and`，再乘 `sepX`；加法先「对齐 + 分离」再加聚合。
- 位置不改，`Δv` 不乘 `h`（`k` 已在系数里）。效果要等下一遍或下一帧的 `movement` 才进位置。

### 2.6 写回与限速（`0x140244633`–`0x1402446e0`）【确】

```
if !(flags & 1):                                   // 0x1402446be
    v' = v + Δv                                    // vx + Δx（addps，交换律下与另一分支同值）
else:
    v' = Δv + v
    old2 = (vy·vy + vx·vx) + vz·vz                 // 用 Δ 之前的速度
    new2 = (v'y·v'y + v'x·v'x) + v'z·v'z
    if new2 > max(old2, maxS²):                    // maxps / cmpltps，严格 >
        v' = v' · (rsqrtps(new2) · maxS)           // blendvps，否则乘 1.0
写 vx/vy/vz[i..i+3] ← v'                            // 0x1402446d6–0x1402446e0
```

- 限速的门是 `max(旧速度², maxS²)`，但压回去的目标是 `maxS`：旧速度已超上限时，新速度只要不比旧速度快就保留原样；一旦更快，直接压到约 `maxS`（会骤降）。
- 缩放因子 `rsqrtps(new2)·maxS` 是近似值，压完的速度约等于 `maxS`。

### 2.7 帧计数器 `ctx+0x144`

- `ctx = R+0x10`，`ctx+0x144 = R+0x154`；帧函数 `FUN_14017fa70` 在 `0x14017fca7` 每帧 `inc dword ptr [R+0x154]`【确】。在对象更新之前加【推：同一函数里位置靠前】；初值【未知】（`0x14017c81e` 有一处把某结构的 `+0x154` 写成 `0x3f800000`，没确认是不是 `R`）。
- 只在 `S > 1`（`hw ≥ 200`）时影响结果。两遍模式同一帧两遍用同一个 `c`，相位相同【确】。

| 快照还是边算边写 | 组级边算边写：组 `i` 的 4 颗算完立即写速度；后面的组读到前面组的新速度。组内 4 颗互相读旧值 | 【确】 |
| 受影响的项 | 只有对齐（读邻居速度）。位置在 boids 里不变，聚合、分离只读位置 | 【确】 |
| 遍历顺序 | 槽序（组 `i` 升序），不是存活表、不是年龄序；死槽、未出生槽都在里面 | 【确】 |
| 两遍模式 | 整个 operator 流跑两遍（rea-framework Q1），boids 每遍完整跑一次，系数用减半后的 `k`；第二遍的 `movement` 先用第一遍 boids 改过的速度推进位置，第二遍 boids 再读这些新值 | 【确】 |
| 与其它 operator 的先后 | 按 JSON 顺序；语料 `movement, alphafade, sizechange, boids`，所以本遍 boids 改的速度在下一遍（或下一帧）的 `movement` 里才进位置 | 【确】 |
| 模块状态 | 不写记录、没有逐粒子私有列 | 【确】 |

对模拟器的含义：要逐粒子对上 WPE，需要
1. operator 在 `[0, ⌈hw/4⌉·4)` 全部槽上跑（含死槽、未出生槽），死槽保留并继续积分位置、速度；
2. boids 按 4 槽一组、组升序、组内移位顺序遍历，写回按组；
3. 照抄存活位不移位的缺陷（是否照抄按「语料依赖的 WPE 缺陷才复现」决定：滴水 `maxcount 16`、粒子有寿命，死槽必然出现，**画面依赖它**的可能性很高，建议照抄，以实测为准）；
4. `rsqrtps` / `rcpps` 的近似按以往惯例不复刻，验收放宽。

## 4. 空间【确】

- boids 段只读 `life`、位置、速度六列，不读 `sys+0x400` 控制点表、不读任何矩阵、不读 `obj`，所以在列所在的空间里算：本地系统是系统本地坐标，世界系统（粒子 `flags` bit0）是世界坐标。阈值、`maxspeed` 都在这个空间里比。
- 对象 `scale`：本地系统里位置不含对象矩阵，`scale` 不影响 boids 的距离；世界系统里位置是世界坐标，发射时控制点已乘模型矩阵（rea-p4a 粒子 flags 表），所以距离里含 `scale` 的效果【推，由列的空间推出】。
- 语料粒子系统 `flags 1` = 世界空间，阈值 150 按世界坐标（场景像素）比。
- 每个 `sys` 一套列：顶层系统、static 子系统、每个事件实例各自独立，boids 只在自己的 `sys` 里找邻居，跨实例没有交互。

## 5. 与 `speed`、`rate`、`timescale` 的关系【确】

- 解析段没有绑定登记，`FUN_14022bd40` 的实例覆盖重算碰不到 boids 记录：**不乘 `instanceoverride.speed`**；`maxspeed` 也不随 `speed` 缩放。`speed` 只经发射速度、`velocityrandom`、`gravity` 等间接改变对齐项读到的速度。
- `instanceoverride.rate`（`obj+0x854`）进 `dt' = dt·rate`，再进 `k`，所以三个系数都随 `rate` 线性变化；但 `0.025/ctx.dt` 用的是不含实例 `rate` 的帧时间，`rate` 不改变那个衰减系数。
- 场景 `rate`（`session+0x190`）已经乘进 `ctx.dt`（rea-framework Q2），两处都受影响。
- boids 没有 `timescale` 键，不用场景时间、不用随机数 `R`。
- 预热（`starttime`）：同一条模拟路径，`dt'` 是固定步长（0.05 / 0.2），但 `0.025/ctx.dt` 读的是当帧的 `ctx+0x14c`，不是预热步长【推】。

## 6. 语料用例的取值

`{ alignmentfactor 5, cohesionfactor 5, separationfactor 0, neighborthreshold 150, flags 0 }`，正交场景：
- `separationthreshold` 缺省 20，`maxspeed` 缺省 500（不限速，不用）。
- `S = 1`；60 fps 一遍时 `k = dt'`：`Δv = 5·k·(v̄ − v) + 5·k·(p̄ − p)`；分离系数 0，`invS·sepX = 0`。
- 若用户 fps ≤ 20，两遍各 `k = k0/2`。
- `maxcount 16` → 最多 4 组；存活位缺陷在有粒子死掉后生效。

## 8. 建议的确定性实验

所有工程关掉发射随机（min = max、固定间隔），无重力或固定重力，`drag 0`，输出逐粒子轨迹。用 fps 60（一遍、`k = dt`）为主，fps 20 只用来区分 `h` / `k`。

1. **乘 `k` 还是 `h`：** 两颗粒子、只开对齐 `A = 5`、`flags 0`，一颗静止一颗匀速，fps 20（`dt ≈ 0.05`，两遍）。按 `k` 读法每遍系数 `5·0.5·0.6156·0.05`，按 `h` 读法 `5·0.025`，相差约 1.6 倍，一帧就分得开。
2. **对齐 / 聚合 / 分离的量：** 各单开一项，两颗粒子：
   - 对齐 `A`：`Δv = A·k·(rcp(1)·vj − v)`；
   - 聚合 `C`：`Δv = C·k·(pj − p)`，距离 100 与 50 各一组，验证与距离成正比（不归一化）；
   - 分离 `Sep`、`sepT = 100`，距离 50：`Δv = Sep·k·(100/50 − 1)·(p − pj)`，换距离 25 验证 `(sepT/d − 1)` 的形状。
3. **阈值严格 `<` 与近似距离：** 两颗粒子距离分别取 `nbT − 0.5`、`nbT`、`nbT + 0.5`（`nbT = 150`）。前者有作用、后者没有；正好等于时取决于 `rsqrtps(22500)·22500` 是否小于 150，记录结果作硬件参照。
4. **自己与重合：** 两颗粒子同一位置出生、不同速度、只开对齐：按读码两颗互不影响（`d2 = 0`）。
5. **存活位缺陷（关键）：** `maxcount 4`，同一帧发 4 颗、寿命按槽号不同（槽 3 最短），位置分开、都在 `nbT` 内，只开聚合。槽 3 死后：读码预测槽 0 仍被槽 3 的死尸（继续按 `movement` 移动的位置）吸引（`k4 = 1` 时 lane 0 配 lane 3、看 `life[0]`），而槽 3 不再被算的只有那些用到 `alive[3]` 的配对。按快照（正确）读法槽 0 只受槽 1、2 影响。两种读法的轨迹在槽 3 死后立刻分叉。
6. **组级边算边写：** `maxcount 8`，两组各 4 颗，只开对齐。组 0 速度为 0、组 1 速度为 `u`，相距在阈值内：组 1 读到的是组 0 本遍新速度（按读码），组 0 读到组 1 的旧速度。与「全快照」读法第一帧就差 `A·k·Δ` 量级。
7. **限速：** `flags 1`、`maxspeed 100`：(a) 初速 200、对齐让速度减小 → 不压；(b) 初速 200、对齐让速度增大 → 压到约 100；(c) 初速 50、加速超过 100 → 压到约 100。区分「门是 `max(旧, maxS)`、目标是 `maxS`」与普通的 `min(|v|, maxS)`。
8. **缺省值与正交 / 透视：** 正交工程 JSON 只写 `name: boids`：`flags` 缺省 1（限速 500）、`separationfactor 15`、`sepT 20`、`nbT 50`；同一组粒子放到透视场景，阈值变成 0.02 / 0.2，在像素尺度下几乎无作用。
9. **空间与 `scale`、`rate`、`speed`：** 同一组粒子分别放在本地系统、世界系统，对象 `scale 2`：本地组的作用范围按本地坐标、世界组按世界坐标；`instanceoverride.rate 2` 让系数翻倍（同时整体时间加速），`speed 2` 只改初速、不改系数。
10. **`S > 1`（可选）：** `maxcount 400`、同时存活 ≥ 200：一帧只有一半的组改速度，交替的相位跟帧计数器；只验证存在，不做逐粒子。
