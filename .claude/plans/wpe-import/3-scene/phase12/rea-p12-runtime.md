  - 矩阵一律是 glm 的列主序、列向量约定（`v' = M·v`）。

**对 Kabegame 的直接含义**（推断，供 P12a 子计划参考）：
- 时钟直接复用 P10 的 float32 时钟（同一个推进函数），从**第 1 帧**就用该帧的 dt 推进；动画层只是 `rate` 不经包装对象、模式来自 mdl。
- 姿势用「静止姿势 → 逐层覆盖 / 混合 / 加法」的 SoA 流程，静止姿势必须照 WPE 用快速倒数平方根分解，否则 `blend < 1` 的层逐位对不上。
- 帧里放在粒子同一步（对象 +0x48 更新）、脚本之前；对象不可见照样推进。
- `g_Bones` 上传 `K` 的前三行，绑定到 `g_bufAnimation`。

## 1. 骨骼运行时与 `animationlayers` 的加载

### 1.1 建运行时（静态确认）

图像层加载 `FUN_1401fbae0`（虚表 +0x40）读模型 JSON 的 `puppet`（`0x1401fbb81`，字符串 `0x140490c54`）：
- 不是字符串，或 `(L+0x304) & 0x22`（fullscreen / 组合层），跳过（rea-p5-modelflags 已记）。
- 文件名后面能找到同名 `.json` 并且 `ctx+0x3058` 置位时走另一条（`FUN_14027a260` / `FUN_14017d9b0`，按 `PUED0002` 读）——这是编辑器的 puppet 导出，没深读【未知】。
- 否则 `new` 0x448 字节的 P，各字段清零，`P+0x390 = −1`，`[L+0x4b8] = P`；`P+0 = 资源`、`FUN_140261880(资源数据, 大小, P+8)` 解析 mdl（`0x1401fbedd`）。
- 第一个带网格标志 bit1 的网格下标写 `P+0x390`（`0x1401fbf3d`）。
- 第一个网格有变形目标时建变形纹理（格式 0x13，`P+0x418`）——归 P12b / mdl 代理。
- **逆绑定矩阵**（`0x1401fc292`–`0x1401fc468`、`0x1401fc640`–`0x1401fc68f`）：
  ```text
  for i in 0..骨骼数-1:                       // 按下标一遍
      Lb = bone[i] + 0x20                     // MDLS 局部矩阵（列主序 4×4）
      P+0x2b0[i] = parent < 0 ? Lb : P+0x2b0[parent] · Lb      // 完整 4×4：((A0·b0 + A1·b1) + A2·b2) + A3·b3
  if P+0x110 非空: P+0x328 = P+0x2b0 的拷贝     // 物理用，求逆之前
  for i: P+0x2b0[i] = glm::inverse(P+0x2b0[i])  // FUN_14005f730，标量 compute_inverse
  ```
  - 父骨骼下标比自己大时会读到还没算的矩阵（新分配的是零）。语料 129 个带 MDLS 的 mdl 全部父在前（`parent_order.py`）。

**加载期的轨道转换**（`0x140263f84`–`0x14026431e`，静态确认）：
- mask：每条轨道 flags bit0 为 0 时置 `0xFFFFFFFF`。加载时（`0x140263b1d`）骨骼文件 flags（`bone+0x64`）bit1 置位且 `bone+0xd4 == −1` 的骨骼，轨道 flags 被或上 1（和 2）：这类骨骼不被动画驱动，每帧改走 `0x1402006dc` 的物理路径。语料骨骼的文件 flags 只有 0 和 1（`corpus_feat.py`），这条一次都不触发；语料里开物理的骨骼走的是另一个门（`bone+0x68 & 0x3000`，6.1）。
- 每帧每骨骼文件里 9 个 float `d[0..8]`：
  ```text
  T = (d0, d1, d2)；S = (d6, d7, d8)
  hx = d3·0.5，hy = d4·0.5，hz = d5·0.5          // 0x1404926c0；弧度
  cz=cosf(hz) cy=cosf(hy) cx=cosf(hx) sz=sinf(hz) sy=sinf(hy) sx=sinf(hx)
  sxsy = sy·sx；cxcy = cy·cx；sxcy = sx·cy；sycx = sy·cx
  w = sxsy·sz + cxcy·cz
  z = cxcy·sz − sxsy·cz
  x = sxcy·cz − sycx·sz
  y = sxcy·sz + sycx·cz                            // 不归一化
  ```
  这就是 `glm::quat(eulerAngles)`，`q = qz·qy·qx`，矩阵 `R = Rz·Ry·Rx`（和对象 `angles` 同一个约定）。记录（`0x1402644da` 起）同一个转换。

## 2. 每帧更新入口与帧里的位置

### 结论（静态确认；实测吻合）

- 入口：图像层虚表 +0x48 = `FUN_1401fdf90(L, dt)`（模型对象是 `FUN_14021c480`，P13）。
- 调用者：帧函数 `FUN_14017fa70` 在 `0x14017fd26` 调 `FUN_1401891a0(scene, dt)`，它按 `scene+0x158` 的对象表顺序对每个对象调虚函数 +0x48（`0x1401891f0` 循环），之后才是相机（`0x140189205` 起）。粒子模拟也在这个循环里，所以 **puppet 与粒子按对象顺序交错更新**，都在相机之前。
- 之后（P10 第 1 节的顺序）：`0x14017fd50` 正交投影乘 zoom → `0x1401802e5` `FUN_140171440`（媒体事件、P10 属性关键帧、`engine.Tick`、脚本 `update`）→ 渲染（`0x14018031a`，图像层绘制在这里上传 `g_Bones`）→ `0x140180d0c` 排队的用户属性改值。
- **门控**：`FUN_1401fdf90` 第一件事是虚函数 +0xd0 `FUN_1402076e0`：P 存在、mdl 存在、第一个网格格式带 `0x800000`（`a_BlendIndices`）、骨骼表非空才继续；否则整段 puppet 逻辑跳过（直接去后面的视频纹理部分 `0x140205681`）。所以只有 MDLS 没有蒙皮属性的静态 puppet 每帧不做事。
- **可见性**：`FUN_1401fdf90` 里没有任何 `L+0x120` / 父链可见性判断（全函数 grep），**图像层不可见时动画照常推进**，事件、播完回调照常发。对照：模型对象的 `FUN_14021c480` 开头查 `obj+0x120 bit0` 与父链（`FUN_140185010`），不可见就返回。
- **暂停**：壁纸暂停时帧函数不调用，时钟冻结；淡出期间 dt 按暂停淡变缩小（P10 第 12 节、rea-framework Q2）。
- **dt**：就是帧函数参数，`clamp(场景 rate × 暂停淡变 × 原始帧时间, 0.0001, 0.25)`，即 `g_Frametime`。没有 dt = 0 的更新路径（下限 0.0001）。只重画不更新的「补画帧」没找到【未知】。
- **首帧**：时钟在构造时为 0，第 1 帧的更新就用第 1 帧的 dt 推进（实测：第 1 帧起累加完全吻合，从第 2 帧起累加差到 5e−3，第 8 节）。
- **惰性初始化**：每帧开头比较「骨骼数」与 `P+0x2c8` 的大小（`0x1401fe01e`–`0x1401fe038`），不等就重建全部每帧缓冲和静止姿势（第一次更新时一定走一次）。

### 帧内时序（推断，依据是地址先后）

- 粒子、相机在 puppet 之后的同一步或之后，挂点子对象的粒子用的是本帧的骨骼（挂点归别的代理）。
- 脚本 / 关键帧对 `rate`、`blend`、`visible` 的写入在本帧 puppet 更新之后，**下一帧生效**；`animationEvent` 与播完回调在 puppet 更新内部发（第 3.4 节），比脚本 `update` 早。
- 场景空间骨骼矩阵 `P+0x340 = W · B` 用的是更新时刻的图层世界矩阵 `W`（虚函数 +0x80），脚本之后再移动图层的话，挂点会晚一帧（推断，挂点代理核）。

## 3. 动画层时钟

### 3.1 推进（静态确认；实测吻合）

每帧逐层（`0x1401fed50` 起，遍历 `P+0x3d0`）：
```c
if (!(AL.flags & 1)) continue;                      // visible 为假：时钟不走、不参与（0x1401fed54）
old = K.flags; t_old = K.t;
FUN_1401a9f60(dt * AL.rate, &K, &events);           // 0x1401fed7d：movaps xmm0, dt；mulss xmm0, rate
FUN_140170580(&K, &lo, &hi, &frac);                 // 帧号
// 「播完」检测（0x1401fedb0）
if (!(old & 0x62000000)) {                          // 之前没暂停、没结束、本帧没 setFrame
    if (K.flags & 2)      ended = K.flags & 0x40000000;          // single：刚结束
    else if (K.flags & 1) ended = (old ^ K.flags) & 0x80000000;  // mirror：换向（到 D 或到 0）
    else                  ended = t_old > K.t;                    // loop：回绕
    if (ended) { K.flags |= 0x4000000; 本帧有层播完 = true; }
}
K.flags &= ~0x2000000;
w = FUN_14026c8b0(AL);                               // 权重，见第 5 节
```
- `FUN_1401a9f60` 与 P10 完全是同一个函数：`flags & 0x60000000` 时不走；single 播完 `t = D`；loop `fmodf`；mirror 反射。帧号 `FUN_140170580`：
  ```text
  frac = fmodf(t, spf) / spf
  fi   = trunc(t / spf)                    // cvttss2si
  lo   = (min(fi, len−1) > 0) ? min(fi, len−1) : 0
  hi   = min(lo + 1, len)
  ```
  与 P10 内联的帧间插值逐条一致。帧号是 `t / spf`，不是 `t × fps`。
- 时间：每层自己的 float32 `K.t`，从 0 开始，`t += dt × rate`。和 P10 一样不读 `g_Time`。语料里 `rate` 有 55 项不是 1（含用户属性绑定）。
- **和 P10 的差别**：`rate` 直接是 AL 的字段（P10 要经 `getAnimation` 包装对象），没有 `startpaused` / `random` / `wraploop`（`FUN_1401a8c10` 的两个布尔参数传 0，wraploop 只在 P10 的加载函数里做），模式从 mdl 来；`setFrame` 写法不同（3.3）。
- 模式统计（192 条动画）：loop 167、single 22、mirror 3；fps 有非整数（19.8、19.9、27.27…），`spf = 1/fps` 的 float32 舍入照 P10。

### 3.2 `visible` 与模式的交互

- 不可见的层整层跳过：不推进、不采样、不算淡入淡出，对姿势完全没有贡献（等于从层表里拿掉）。重新可见时从原来的 `t` 接着走。
- 非 single 层的 blendin 位在第一次淡入完成时清掉（第 5 节），所以隐藏后再显示**不会再淡入**。
- 播完的 single 层（`0x40000000`）时钟停在 `t = D`，但仍在每帧采样（停在最后一帧附近）、仍参与混合，除非被销毁（3.4）。

### 3.3 播放状态（脚本方法的原生实现，静态确认；脚本接线交给脚本代理）

| 方法 | 地址 | 动作 |
|---|---|---|
| `play()` | `0x14026c420` | `if (flags & 0x40000000) t = 0；flags &= 0x9fffffff`（同 P10） |
| `pause()` | `0x14026c450` | `flags |= 0x20000000` |
| `stop()` | `0x14026c460` | `flags |= 0x20000000；t = 0；flags &= 0x3fffffff`（同 P10） |
| `isPlaying()` | `0x14026c480` | `(flags & 0x60000000) == 0` |
| `setFrame(f)` | `0x14026c4a0` | `t = spf × f`（float32 乘法；P10 是 `f / fps`）；`flags |= 0x2000000`（本帧不做「播完」检测） |
| `getFrame()` | `0x14026c4d0` | `t / spf` |
| `addEndedCallback(fn)` | `0x14026c4f0` | 追加到 `AL+0x130` |

暂停时 `FUN_1401a9f60` 第一行就返回，时间不走，但**每帧照样采样、照样参与混合**（同 P10 的 `startpaused`）。

### 3.4 事件与播完（静态确认）

- 每层推进时收集事件（P10 第 8 节的规则，事件时间是秒），全部层处理完后（`0x1402001de`）逐个 `FUN_140177ad0(脚本管理器, L, L, 6, json)`：`animationEvent` 回调，接收者是**图像层对象**上的脚本。语料只有 `3253330537` 一条动画带事件（`{"frame":30,"name":"事件1"}`，文件里存的时间是 1.0）。
- 本帧有层播完时（`0x14020023c`）：对每个带 `0x4000000` 的层清掉这一位；带 `0x8000000` 的置 `0x10000000`；`AL+0x130` 非空就调 `FUN_140177bf0` 执行播完回调。然后把带 `0x10000000` 的层析构并从 `P+0x3d0` 删掉（`0x14020035d`）。`0x8000000` 是谁置的没追（推断是 `playSingleAnimation`，语料 0 处）。
- 「播完」对 loop 是每次回绕，对 mirror 是每次换向，对 single 是到头一次。

## 4. 采样

### 结论（静态确认；实测吻合）

- 三个采样函数共享同一套 SoA 指针算法（`symb.py` 跟踪）：帧块 `F + f·10·N4`，平面 k 在 `+k·N4`，mask 每骨骼一个 float。
- 设 `a` = 第 `lo` 帧、`b` = 第 `hi` 帧、`f = frac`、`g = 1 − f`（调用前各自 splat 成 4 份，`0x1401feea2`）：
  ```text
  T = g·a.T + f·b.T                         // 每分量：xmm = g*a；xmm += f*b
  S = g·a.S + f·b.S
  dot = (b.z·a.z + b.y·a.y) + (b.x·a.x + b.w·a.w)       // 平面 6、5、4、3
  f' = (dot 的符号位) ^ f                              // andps −0；xorps：dot < 0 时取 −f（−0 也算负）
  q  = g·a + f'·b                                        // 每分量
  n2 = (q.z² + q.y²) + (q.x² + q.w²)
  r  = rsqrtps(n2)；k = (3 − r·r·n2) · (r · 0.5)        // 一次牛顿
  q  = k·q
  ```
- 首帧之前 / 末帧之后：时钟保证 `0 ≤ lo ≤ len−1`、`hi ≤ len`，文件存 0…length 共 length+1 帧，所以不存在越界；循环在 `t → D` 时 `lo = len−1、hi = len`，回绕后直接跳到第 0 帧（第 length 帧和第 0 帧之间不插值，同 P10）。
- 没有轨道的骨骼（mask 0）：**保持来源**——第一层的来源是静止姿势，之后是上一层的结果（`blendvps` 选旧值）。不是绑定姿势矩阵本身，而是它的 SoA 分解（第 7 节，旋转有快速倒数平方根的误差）。
- 语料：10 条动画有缺轨道（flags bit0），全部在用 mask。

## 5. 混合

### 5.1 权重（`FUN_14026c8b0`，静态确认）

```text
w = blend
if (flags & 4 /*blendin*/) {
    m = min(D, blendtime)
    k = (m > FLT_EPSILON) ? min(t / min(D·0.5, blendtime), 1) : 1      // 线性，秒
    w = k · blend
    if (!(K.flags & 2 /*single*/) && k ≥ 1) flags &= ~4                // 只淡入一次
}
if (flags & 8 /*blendout，只在 single 有*/) {
    m = min(D, blendtime)
    if (m > FLT_EPSILON) { g = (D − t) / min(D·0.5, blendtime)；if (g ≤ 1) w = w · g }
}
```
- `t`、`D` 是推进之后的时钟值。淡变曲线是线性，时长 `min(D/2, blendtime)` 秒。
- 不钳 `blend`，负数照用。语料：blendin / blendout 都没有为真的（165 项写了，全是 false），blendtime 全是缺省 0.5；`blend` 不是 1 的 9 项，绑用户属性 12 项、挂脚本 4 项。

### 5.2 三种叠法（静态确认；实测吻合）

逐层（`0x1401fee11` 起）：
```text
src  = (之前有可见层处理过) ? 当前 P+0x238 : 静止 P+0x230
rest = 静止 P+0x230
if (w == 1.0f（ucomiss 精确相等）&& !additive)   覆盖  FUN_1401f89a0
elif (!additive)                                 混合  FUN_1401f9020
else                                             加法  FUN_1401f9820
结果写 P+0x238；mask 为 0 的骨骼写 src
```
- **覆盖**：`out = s`（样本，4 节）。
- **混合**（`0x1401f9320` 循环）：
  ```text
  T = s.T·w + src.T·(1−w)；S 同
  d2 = (q.z·src.z + q.y·src.y) + (q.x·src.x + q.w·src.w)
  w' = (d2 的符号位) ^ w
  q2 = w'·s.q + src.q·(1−w)                         // 每分量
  out.q = q2 · rsqrt 牛顿(n2(q2))
  ```
  即 `nlerp(src, 样本, w)`，最短路径，**样本先归一化一次、结果再归一化一次**。
- **加法**（`0x1401f9bf0` 循环）：
  ```text
  T = (s.T − rest.T)·w + src.T；S = (s.S − rest.S)·w + src.S          // 缩放也是加的，不是乘的
  r* = (rest.w, −rest.x, −rest.y, −rest.z)                              // conj
  d  = r* ⊗ s.q   （Hamilton，各分量的运算顺序：
        dw = ((sw·rw − sx·rx*) − sy·ry*) − sz·rz*
        dx = ((sw·rx* + sx·rw) + sz·ry*) − sy·rz*
        dy = ((sw·ry* + sy·rw) + sx·rz*) − sz·rx*
        dz = ((sw·rz* + sz·rw) + sy·rx*) − sx·ry*）
  e  = (dy·0 + dz·0) + (dx·0 + dw·1)；w' = (e 的符号位) ^ w
  qa = (w'·dw + (1−w)·1, w'·dx + (1−w)·0, w'·dy + (1−w)·0, w'·dz + (1−w)·0) · rsqrt 牛顿
  out.q = src.q ⊗ qa（同样的 Hamilton 展开，src 在左，结果不再归一化）
  ```
- **权重和**：不归一化，也不和绑定姿势补足；第一层用静止姿势当来源，就是「和静止姿势混合」。两层都 `blend 0.5` 的非加法层结果是 `nlerp(nlerp(静止, A, 0.5), B, 0.5)`。
- **顺序**：只看 `P+0x3d0` 的顺序（语料 = JSON 顺序），不按加法 / 非加法重排（只有 `autosort` 插入时会）。
- 语料：加法层 73 项（很常见），实测 `3463520581` 的「两层加法叠在同一骨骼上」逐位对上（第 8 节）。

## 6. 蒙皮矩阵与上传

### 6.1 局部与模型空间（静态确认；实测吻合）

逐骨骼按下标（`0x1402006c0` 循环，`0x140200a58` 起是非物理骨骼）：
```text
q = (P+0x238 平面 3..6)；T = 平面 0..2；S = 平面 7..9
M = mat4_cast(q)（0x140215200）；M.c0 *= S.x；M.c1 *= S.y；M.c2 *= S.z（FUN_14005eb60，整列 4 分量乘）
M.c3 = (T, 1)
P+0x310[i] = M
B_i = parent < 0 ? M : B_parent · M          // 只用 M 每列的 xyz：
     列 j<3：(m.y·A1 + m.z·A2) + m.x·A0
     列 3  ：((m.z·A2 + A3) + m.y·A1) + m.x·A0
P+0x2c8[i] = B_i
```
- `mat4_cast`（内存 `w x y z`）：
  ```text
  c0 = (1 − 2(zz + yy), 2(zw + xy), 2(xz − yw), 0)
  c1 = (2(xy − zw), 1 − 2(zz + xx), 2(xw + yz), 0)
  c2 = (2(yw + xz), 2(yz − xw), 1 − 2(yy + xx), 0)
  ```
  括号就是运算顺序（`zz + yy` 先算 zz）。不归一化 q。
- 没有任何可见层被处理时（`r14 & 1 == 0`，`0x1402037ef`）：局部矩阵**直接取静止来源矩阵**（`P+0x50[i]`，空就是骨骼 `+0x20`），不经过分解；之后同样沿父链。
- 之后同一循环里还有：骨骼约束（`bone+0xd8`，`0x140200df2`–`0x1402011c8`）、`P+0x340[i] = W · B_i`（`0x1402011cb`）、物理（`bone+0x68 & 0x3000` 且 `P+0x348` 非空，`0x14020136e`；以及 `bone+0xd4 ≥ 0` 的 `0x140203657`）——都交给物理 / IK 代理（第 9 节）。语料没有约束（`constraints` 0 个）。

### 6.2 蒙皮矩阵（静态确认；实测吻合）

`0x140205360` 循环（所有骨骼处理完之后）：
```text
K_i = B_i · invBind_i        // 同 6.1 的仿射乘法，invBind 当右边
P+0x2f8[i] = K_i
```
- 逆绑定来自 MDLS 局部矩阵（1.1），与静止姿势的来源（`P+0x50`）不同。语料里 `P+0x50` 全空（`opt_bone_mats` 0 个），所以静止姿势和绑定姿势是同一组矩阵，没有动画层时 `K = 单位`（实测 `3811424158`、`3463520581` 的两个无层对象都是单位）。
- **MDLE（mdl+0x60）在这条路径里不读**：最初的模型把 MDLE 当静止姿势，`3463520581` 的 `asuna body`（两层加法）骨骼 6–14 差了 (215.6, 107.3) 像素；改用 MDLS 后逐位对上。rea-p5-mesh 1.7 的段表把 MDLE 记在 mdl+0x48，按 `0x1402658ee` 的寄存器看应是 mdl+0x60，mdl+0x48 是 MDLS v≥2 的可选骨骼矩阵（交 mdl 代理核）。

### 6.3 上传（静态确认；实测吻合）

图像层绘制 `FUN_140206430`（虚表 +0x50，渲染阶段）：
```text

                            //   ByteWidth = 历来最大的 n·0x30，DYNAMIC / CONSTANT_BUFFER / CPU_WRITE，WRITE_DISCARD
dev->writeBones(p, P+0x2f8, n)   // 0x14009b410
dev->unmap()                // 0x14009b730：Unmap，VSSetConstantBuffers(2, 1, &cb)

```
- `writeBones`：第 i 骨骼的 12 个 float = `K` 的前三行：
  ```text
  p[12i+0..3]  = (K.c0.x, K.c1.x, K.c2.x, K.c3.x)
  p[12i+4..7]  = (K.c0.y, K.c1.y, K.c2.y, K.c3.y)
  p[12i+8..11] = (K.c0.z, K.c1.z, K.c2.z, K.c3.z)
  ```
  着色器是 `const float4x3 g_Bones[BONECOUNT]`（b2，rea-p7-shader），HLSL 缺省列主序打包，三个寄存器就是 4×3 矩阵的三列，`mul(float4(pos,1), g_Bones[i]) = K·pos`。RenderDoc 按反射把每项展开成 `c0.xyz, c1.xyz, c2.xyz, c3.xyz`（实测文件就是这个顺序）。
- 多出来的槽（`n ≤ 槽 < BONECOUNT`）：缓冲只有 `历来最大 n·0x30` 字节，`WRITE_DISCARD` 之后内容未定义，网格只引用自己的骨骼，不影响画面【推断】。
- `g_BonesAlpha`：uniform 填写 `0x1400d9f25` 把 `ctx+0x11e0` 的 `ctx+0x12e8 × 4` 字节 memcpy 进去，紧排（float 数组在 cbuffer 里是打包形态，P7）。属于 `g_bufDynamic`（b1）。

## 7. 数值细节

### 结论（静态确认；实测吻合）

- **全 float32**，没有 double。CRT `sinf` / `cosf`（`0x14041a9c0` / `0x14041a2e0`）只在加载时用于欧拉转四元数。`fmodf` 是 `0x14041d0c0`。
- **静止姿势分解**（`0x1401fe2f2`–`0x1401fe65d`，每次重建时）：
  ```text
  M = P+0x50[i] 非空 ? 它 : bone[i]+0x20
  T = M.c3.xyz
  R = M；R.c0..c2 各自 = c · fastInvSqrt((w² + z²) + (y² + x²))     // FUN_140214eb0，vec4
        fastInvSqrt(n2)：y = asfloat(0x5f375a86 − (asuint(n2) >> 1))；y · (1.5 − (n2·0.5)·y·y)
  q = glm::quat_cast(R)              // FUN_140215730，标量 glm 实现（最大分量分支，0.25 / (sqrt(·+1)·0.5)）
  S = (len(M.c0), len(M.c1), len(M.c2))   // FUN_1401e24b0：sqrt((w² + z²) + (y² + x²))，用原矩阵
  ```
  - 单位旋转的列被归一化成 0.998308122 而不是 1（初稿误写成 0.99830717，P12a 步骤 1 的单测与 python 模型都算出 0.998308122），`quat_cast` 得到 `(0.99936533, 0, 0, 0)`，**不是单位四元数**。混合层 `nlerp(静止, 样本, w)` 里它的有效权重因此变小；`3203778110` 的 `blend 0.58` / `0.21` 两层逐位对上，说明 WPE 确实这样算。
  - 带旋转的静止骨骼在**覆盖层里缺轨道**时直接用这个不单位的 q 进 `mat4_cast`，会有约 0.2% 的缩放 / 剪切（推断；语料静止骨骼全是单位旋转）。没有可见层时不经过分解，没有这个误差。
- **归一化**：采样与混合的 nlerp 都是 `rsqrtps` + 一次牛顿：`(3 − r·r·n2)·(r·0.5)`。`rsqrtps` 是硬件近似（相对误差 ≤ 1.5·2⁻¹²，Intel / AMD 的表不同），模型用精确 `1/sqrt` 再做同一次牛顿，实测 55 次绘制里 45 次逐位相同、其余 ≤ 2 ulp。
- **四元数点积的加法顺序**是 `(z·z' + y·y') + (x·x' + w·w')`，模长平方同样。符号用 `andps −0 / xorps` 取，所以点积为 −0 时也取反。
- **矩阵乘法**：父链与蒙皮都是 6.1 的仿射乘法（只看右矩阵各列的 xyz、加法顺序固定）；只有加载时的绑定姿势用完整 4×4（`((A0·b0 + A1·b1) + A2·b2) + A3·b3`）；逆是 glm 标量 `compute_inverse`。
- 仿射乘法忽略右矩阵前三列的 w 和第四列的 w（当 0 / 1）；分解出来的局部矩阵本来就是仿射，没有影响。

## 对实现的含义

给 `src/puppet/`（纯 TS，float32 用 `Math.fround` 逐步舍入）：

1. **加载（编译期或主线程一次）**
   - 每条动画：每帧每骨骼 9 个 float → `T`、`S` 原样，`q = 欧拉转四元数`（1.3 的式子，半角、`Math.sin` / `Math.cos` 后 `fround`），存 `length+1` 帧；mask = 轨道 flags bit0 为 0。
   - 逆绑定：MDLS 局部矩阵按下标沿父链完整 4×4 相乘，再照 glm 标量 `compute_inverse` 求逆。
   - 静止姿势：来源矩阵 = mdl+0x48（MDLS v≥2 可选骨骼矩阵）有就用它、否则 MDLS 局部；按第 7 节分解，**必须用快速倒数平方根**。不用 MDLE。
   - 动画层：照 1.4 / 1.5，找不到 `animation` 就丢掉这一层（能力表可以报 `puppet:animation-missing` 之类的细分键，看子计划），层顺序 = JSON 顺序。
2. **每帧（对象更新那一步，和粒子同一循环，脚本之前；图层不可见也做）**
   ```ts
   let pose = null;
   for (const L of layers) {
     if (!L.visible) continue;
     const old = L.clock.flags, t0 = L.clock.t;
     L.clock.advance(fround(dt * L.rate));          // P10 的推进函数
     const { lo, hi, frac } = L.clock.frames();
     detectEnded(L, old, t0);                       // 3.1，事件与播完回调排到本 puppet 处理完之后
     const w = L.weight();                          // 5.1
     const src = pose ?? rest;
     pose = (w === 1 && !L.additive) ? override(...) : !L.additive ? blend(..., w) : additive(..., rest, w);
   }
   const local = pose ? pose.map(trsToMat) : restMatrices;   // 没有可见层：直接用来源矩阵
   model[i] = parent < 0 ? local[i] : mulAffine(model[parent], local[i]);
   skin[i]  = mulAffine(model[i], invBind[i]);
   ```
   - 采样 / 混合 / 加法照第 4、5 节的式子与加法顺序；`rsqrtps` 用 `1 / Math.sqrt` 再做一次牛顿（逐位误差 ≤ 2 ulp，和 P4 的「近似倒数不复刻」同一个处理）。
3. **上传**：`g_bufAnimation` 按 `float4x3` 列主序，每骨骼三个 vec4：`(c0.x, c1.x, c2.x, c3.x)`、`(… .y)`、`(… .z)`；WebGPU 侧和翻译器约定好同样的布局。只写前 `骨骼数` 个，其余随意（推荐清零）。
4. **重编译**：时钟、播放状态、`blendin` 已清位、层表（含脚本销毁过的层）都要保留，同 P10。
5. **确定性回放**：每帧喂同一个 dt 序列，从第 1 帧起推进；dt 下限 0.0001、上限 0.25 照帧循环。
6. **验收建议**：用 `posemodel.py check <id>` 的思路，逐帧比 `g_Bones`，目标是 ≤ 2 ulp（物理场景另算）。

- **IK / 约束**：骨骼约束循环 `0x140200df2`–`0x1402011c8`（`bone+0xd8` 表，每项 `+4` 权重下标进 `P+0x250`、`+8` 目标骨骼），MDLS v≥2 的记录（`P+0x80`）及其姿势 `P+0x240` / `P+0x248` → `P+0x2e0`（`0x140200520`，只有平移与旋转，没有缩放）。语料没有约束与记录。

- **脚本**（P12c）：方法表 `0x1404e8aa0` 与 3.3 的原生实现；播完回调 `AL+0x130`、`FUN_140177bf0`；`0x8000000` / `0x10000000` 销毁位（`0x140200296`、`0x14020035d`）；puppet 事件 `FUN_140177ad0(…, L, L, 6, json)`（`0x14020022e`）；`getAnimationLayer` 怎么按 `name` / 下标找没读。
- **mdl 格式**：本文 1.2 / 1.3 的内存布局只为讲清运行时；MDLE 写到 mdl+0x60 还是 mdl+0x48 请以 mdl 代理为准（本文证据：`0x14026588c` 前后 `r14 = mdl+0x60`，以及实测）；A 的 `flags & 0x401 == 1`（引用别的动画）没追。
- **模型对象**（P13）：`FUN_14021c480` 用同一组采样函数（`0x1401f89a0` / `0x1401f9020` / `0x1401f9820`）与权重、时钟函数，但不可见时直接返回、只有一套 SoA；没逐行核对。

## 没查清的

1. **REA 快照**：Ghidra 导入超时，没能做标注，也没有另存 `wallpaper64-2.8.42-p12-runtime.rea-snapshot`（收尾时 `close_binary` 报「没有打开的目标」，会话已被关掉）。全部结论来自 `wp.asm`，置信度不受影响，但地址没有在 REA 里命名。
2. `rsqrtps` 的硬件近似没有逐位复刻（模型用精确值，残差 ≤ 2 ulp）；AMD 与 Intel 的 WPE 结果本身就可能差 1 ulp。
3. `0x8000000`（播完即销毁）由谁置位；`AL+0x14c` 的单位矩阵与 `AL+0x48` 的用途。
4. `P+0x350` 的 16 个 float（MDLA v3 的一组标量轨道）是什么；`P+0x298` 绘制分段的建表（加载期）与排序比较器 `0x1401fac30` 的细节。
5. `autosort` 在没有非加法层时下标 −1 的后果（看起来是越界写），`index` 不能插到末尾，都没实测（语料 0 处）。
6. 带旋转的静止骨骼在覆盖层缺轨道时的 0.2% 误差只是推断（语料静止骨骼全是单位旋转，测不到）。
7. mirror / single 模式、`blendin` / `blendout`、`rate` 绑用户属性或脚本的生效帧都没有实测数据（时钟是 P10 已实测的同一函数；描述符无回调的结论是静态确认）。
8. 「补画帧」（只渲染不更新）是否存在、是否会重复上传旧的 `g_Bones`，没查。
9. `PUED0002`（`.json` 旁路，`ctx+0x3058` 门控）是什么，没读。
