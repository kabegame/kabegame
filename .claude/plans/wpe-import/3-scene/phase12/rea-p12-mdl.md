> 读码代理产出。只做静态分析，没有运行、附加或改动 WPE；语料只读。
> 置信度三档：
> - **静态确认**：反汇编或反编译直接看到。
> - **推断**：由代码推出，但缺一环（例如没逐个核对调用点、名字按行为起）。
> - **未知**：查到某处为止，没有结论。

> 另有 **语料吻合**：按读出的布局写的解析器在本机语料上逐段核对过（第 10 节）。

- **结构的叫法**（类没有 RTTI，名字按行为起）：
  - **mdl**：`FUN_140261880(data, size, out)` 的 `out`。模型对象里是资源 `+0x10`，图像层里是 **P+8**。
  - **P**：图像层 `L+0x4b8` 的 puppet 对象（0x448 字节，`FUN_1401fbae0` 里 `new`）。`P+0` 是文件数据指针，`P+8` 起是 mdl，`P+0x228` 起是 puppet 运行时字段。下文 `mdl+X` 在 puppet 里就是 `P+8+X`。
  - **L**：图像层对象，虚表 `0x1404911a8`（`+0x40` = `FUN_1401fbae0`）。P5 文档写的「虚函数 +0x40」与此一致；`ptr.py` 把表头回溯到 `0x1404910f8`，那是前面连着的另一张表。
  - **mesh**：mdl 的网格记录（每条 200 字节，`mdl+0x10` 向量）。
  - 读取原语同 rea-p5-mesh 1.1；补两条：`FUN_1400d3ef0(r, dst, max)` = 「u32 长度 L + 拷 min(L, max) 字节，只前进拷贝的字节数」，L 为负或剩余不足 `max+4` 时不读；`FUN_140261710(r, dst, n)` = 裸读 n 字节（不够时清零）。

## 1. `MDLS` 段

### 1.1 段头【静态确认】
- 识别（`0x1402624af`–`0x1402624ca`）：`strncmp(标签, "MDLS0004", 4)`，只比前 4 个字符；版本 = `atoi(标签 + 4)`（`0x1402624d9`）。段头 `FUN_140261770` 把「段末 = 文件起点 + min(u32, 文件长)」记在读取器 `+0x18`，下一个标签从那里读（`0x140265926`）。**读取上限仍是整个文件**（`[r+0x10]`），段内读多了会读到下一段里，不会出错。
- u32 骨骼数（`0x1402624f4`）。`> 0x80` 时 `int 0x29`（`0x14026250a`，`__fastfail`，进程直接终止，不是跳过）。然后按骨骼数 resize mdl+0x30（每骨骼 0xf0，`FUN_140269330`）。

### 1.2 每骨骼【静态确认】
| 顺序 | 读法 | 存到 bone+ | 地址 |
|---|---|---|---|
| 1 | 字符串 | `+0x00` 名字（std::string） | `0x140262545` |
| 2 | u32 | `+0x64` **文件 flags** | `0x140262564` |
| 3 | u32 | `+0x60` 父骨骼，`0xFFFFFFFF` 为根 | `0x140262570` |
| 4 | `FUN_1400d3ef0(r, +0x20, 0x40)`：u32 长度 L + min(L, 64) 字节 | `+0x20` 局部 4×4（行主序，行向量约定，平移在第 4 行） | `0x14026257e` |
| 5 | 字符串，交给 `FUN_140265c30(串, bone+0x68)` | `+0x68` 起的物理 / IK 参数（第 2 节） | `0x1402625a9` |

- 骨骼默认构造（`0x14026b860`）：`+0x20` 单位阵、`+0x60 = −1`、`+0x64 = 0`、`+0x68` 起见 2.2、`+0xd4 = −1`（链表反查，1.3 第 5 项）、`+0xd8` 约束向量为空。
- 长度前缀：语料 1245 根全是 64。L > 64 时只前进 64 字节，余下的字节会被当成 JSON 串读，WPE 没防这个（推断：编辑器只写 64）。
- **文件 flags**：
  - bit1（0x2）：加载 MDLA 时这类骨骼（且 `+0xd4 == −1`）的轨道被强制标成「不动画」（4.3），约束项改挂到同号的类型 0 记录上（1.3 第 3 项）；每帧更新在 `0x1402006d2` 测它走物理路径（运行时代理）。语料 0 根。【静态确认】
  - bit0（0x1）：语料 1168 根是 1、77 根是 0。在 `0x1401fd000`–`0x140212000`（图像层全部函数）里搜 `[+0x64]` 的位测试，只有 `0x1402006d2` 测 bit1，没有测 bit0 的。【静态确认，有界】推断是编辑器用的。

### 1.3 v≥2 的附加数据（`0x1402625c6` 起，`ver < 2` 时跳到 `0x140263813` → `0x1402637b2` 的 v≥3 判断）【静态确认】
按读取顺序：
1. **记录表**（`0x1402625d0`–`0x1402626fe`）：u16 个数 → mdl+0x78（每项 0x80）。每项：字符串名字（`+0`）、u32 id（`+0x60`）、u32 类型（`+0x64`）、裸 64 字节矩阵（`+0x20`）。类型 0 时登记到 mdl+0x120 的表（`id → 下标`），类型 1 时登记到 mdl+0x160 的表（`FUN_140268e80`）。
2. **可选矩阵**（`0x14026273b`–`0x14026284a`）：u8 为真时，骨骼数个裸 64 字节矩阵 → mdl+0x48，记录数个 → mdl+0x90（`FUN_14005f600` 只是取矩阵第 0 行的地址）。运行时代理称 mdl+0x48 有值时静止姿势用它代替 MDLS 局部矩阵。

4. **键表**（`0x140262a05`–`0x140262bd5`）：u16 个数 nk。mdl+0xd8 resize 成 nk 个 u32 并整块拷 `nk × 4` 字节；mdl+0xf0 resize 成 nk 个 0x40 字节元素（MSVC `unordered_map`）。然后 nk 次：u16 n，n 个 `{u32 键, 12 字节值}`，值写进第 i 张表节点的 `+0x14..+0x1f`（`FUN_140269400`）。
5. **链表**（`0x140262bea`–`0x140263418`）：u16 个数 → mdl+0x108（每项 0x40）。每项：
   - u32 骨骼下标 → `+0`，同时 `bone[下标]+0xd4 = 本项下标`（越界 `int 0x29`）；
   - u32 m，m 个 u32 记录下标（越界 `int 0x29`），只有该记录 `+0x68` 非空时才 push 进 `+0x20` 的 u32 向量；

   - 图像层加载时 mdl+0x108 非空就把绑定姿势世界矩阵另存一份到 `P+0x328`（`FUN_1401fbae0`）。
6. **命中盒**（`0x14026341e`–`0x1402635f5`）：u8 为真时，每骨骼 12 字节 vec3（`+0`）+ 64 字节矩阵（`+0xc`）→ mdl+0x1a0（每项 0x4c）。

v≥3（`0x1402637b2`）：
8. **绘制顺序**：u8 为真时，每骨骼一个 u32（按 i32 用）→ mdl+0x1e8。

## 3. `MDLE0002`

### 3.1 格式【静态确认】
- 识别：`FUN_14000d010(标签, "MDLE0002")` 全串比较（`0x1402658d0`）。
- `FUN_1401d9b80(mdl+0x60, 骨骼数)` 先 resize（`0x1402658f1`），再 `FUN_1400d3ef0(r, mdl+0x60 数据, 骨骼数 × 64)`：u32 字节数 L + min(L, 骨骼数 × 64) 字节（`0x140265909`）。没有 MDLS 时骨骼数为 0，只读一个 u32。
- **写到 mdl+0x60**（`0x140262413` `lea r14, [r15+0x60]`、`0x1402658ee` `mov rcx, r14`，大小取 `[r15+0x68] − [r14]`）。rea-p5-mesh 1.7 记成 mdl+0x48，应更正；mdl+0x48 是 1.3 第 2 项的可选骨骼矩阵。

### 3.2 和 MDLS 局部矩阵的关系【静态确认 + 语料】
- 绑定姿势的逆**不来自 MDLE**：`FUN_1401fbae0`（`f_1401fbae0.c` 第 380–450 行、508–530 行）对每根骨骼算 `world_i = local_i · world_parent`（行向量约定，父在前的下标顺序一遍过；根骨骼 `world = local`），存 `P+0x2b0`，再逐个 `FUN_14005f730` 求逆写回 `P+0x2b0`。`P+0x2f8` resize 成骨骼数个单位阵。
- MDLE 本身是另一套**局部**矩阵（`mdlecmp.py`，35 个文件、663 根骨骼）：与 MDLS 局部矩阵完全相同 408 根，只差平移 250 根（根骨骼 12 根、子骨骼 238 根），旋转也不同 5 根。例：`3276911872` 鼠标指针的根骨骼 MDLS 平移 (24.92, −41.71)、MDLE (−84.68, 96.81)，子骨骼相同。
- 运行时代理实测：把 MDLE 当静止姿势时 `3463520581` 的 `asuna body` 差约 216 像素，改用 MDLS 后逐位对上（rea-p12-runtime 6.2）。

### 3.3 唯一的读者【静态确认：读写；推断：用途】
- 在 `0x140100000`–`0x140300000` 里跟踪从 `[*+0x4b8]` 载入的寄存器（`pupfields.py`），只有 `0x1401d6d9f` / `0x1401d6dd8` 读 `P+0x68/+0x70`（= mdl+0x60）。
- 所在函数 `FUN_1401d6d30`（`asm\mdlepose_1401d6d30.asm`）：MDLE 非空时取它、否则取 `bone+0x20` 当局部矩阵，沿父链相乘、求逆存到任务对象 `+0x68`，之后遍历命中盒（mdl+0x1a0）。调用者 `0x1401d422c` 在一个任务函数里（`0x1401d3c92`–`0x1401d424c`），那里用 `WRITEALPHA`、`OPACITYMASK` 组合键和 `materials/util/downsample_quarter.json` 渲染，再逐像素比较 alpha > 0x7f（`0x1401d411d`）。推断：这是按不透明度判定光标命中的「渲染到纹理再读回」任务，puppet 在里面用 MDLE（编辑器姿势）画。图像层的加载、每帧、绘制都不读 MDLE。

  1. `P+0x390` = 第一个 bit1 网格（8.2）；
  2. 变形纹理（6.3）；
  3. `animationlayers` 里每个对象项交 `FUN_1401fcc20`（运行时代理）；
  4. 绑定姿势与其逆（3.2）、`P+0x2f8` 置单位阵、mdl+0x108 非空时 `P+0x328`；
  5. 文件读不到或网格为空时整个 P 销毁、`L+0x4b8 = 0`；
  6. 最后照常 `FUN_1401e6f50`（图像层基类加载）。

### 9.2 网格代替四边形（`L` 虚函数 `+0xb0` → `FUN_14020ae00`）【静态确认】
- `+0xb0` 建 `L+0x2e0` / `+0x2e8` 之后，P 有数据时调 `FUN_14020ae00(L, uScale, vScale)` 代替建 `L+0x490`（`0x1402068b4`）。`uScale = 图像宽 / 纹理宽`、`vScale = 图像高 / 纹理高`；有 effect、`L+0x304 & 0x10`、或纹理是精灵表（标志 bit2）且纹理 `+0xac ≥ 3`（推断：帧数）时，调用方传 (1, 1)（`FUN_140209360`，`0x14020948c`–`0x1402094d4`）。
- `FUN_14020ae00`（`asm\puppetgeo_14020ae00.asm`）：
  - 只用**网格 0**（`[P+0x18]`）。拷一份顶点字节。
  - 满足「没有 effect（`L+0x320 ≤ 0`）、没有 `0x304 & 0x10`、基础材质槽 0 纹理不是精灵表（纹理标志 bit2）、没有纹理通道网格」时，把每个顶点的 **`a_TexCoord`**（表序 7，偏移 = 前 7 种属性大小之和）乘 `(uScale, vScale)`；否则不动 UV，并置 `L+0x304 |= 0x10`（`0x14020b20d`）。
  - 位置不动，**不按 `size` 缩放**。语料顶点坐标就是图层局部像素：原点在图层中心、y 向上，范围约 `±size/2`（`posrange.py`，如 `2896608544` size 4577×2084、x −2271.5..2295.5、y −1051..1049）。
  - 设备 `+0x40` 建 GPU 网格：网格 0 的格式、u16 索引（数 = 字节数 / 2）、三角形列表、标志 `(bit3 ? 2 : 0)` → **`L+0x490`**。纹理通道网格另建 → `P+0x3f8`。
  - `L+0x120 &= ~0x20`，任何骨骼的 JSON flags（`bone+0x68`）非 0 时 `|= 0x20`（推断：有物理 / IK）。
  - 绘制组（7.2）。
- `alignment`、UV 内缩：P8 的对齐偏移进的是图层「画自己」的矩阵，puppet 网格走同一个绘制函数（9.4），推断对齐照样生效；直接上屏四边形的 0.15 texel 内缩（rea-p5-modelflags 5.2）**不作用于 puppet**：puppet 只乘比例、不内缩。`autosize` 只改 `size`，而 puppet 不用 `size`，推断不影响几何（合成 RT 的尺寸照旧按 `size` / 图像尺寸）。

### 9.4 绘制路径【静态确认】

### 9.6 `g_bufAnimation`（b2）与骨骼相关 uniform【静态确认】
- 上传在图像层的绘制入口 `L` 虚函数 `+0x50` = `FUN_140206430`（`asm\draw_bones_140206430.asm`），每次画这个图层都做：

## 11. 对实现的含义（推断，供 P12a / P12b 子计划）

### 11.1 `parseMdl` 扩展的布局清单
在 P5c 的 `parseMdl` 上改：
- 网格：可选块 1 先读 u32（丢弃）再读块，保留成 `imagePositions: Float32Array`（暂不用）；可选块 2 解析成 `drawGroups: {bone, order, start, count}[]`；v23 记录保留 `{id, name, flags, list1, list2}`；bit1 的 u32 保留成 `blendRowCount`。
- 段：按第 1、3–6 节逐段读，段末用段头偏移校验（不一致就报 `mdl:section-size` 之类的键退回，语料 0 处）。建议输出：
  - `skeleton`：`bones[{name, flags, parent, local: Float32Array(16), physics: 第 2 节的结构}]`、`hitBoxes?`、`hitOrder?`、`drawOrder?`、`restMatrices?`（mdl+0x48）、`records` / `constraints` / `keyMaps` / `chains`（语料 0 处，可先只记个数并报 `mdl:skeleton:constraints` 等键）。
  - `animations[{id: bigint 或 number（语料 < 2³²）, name, mode, fps, length, flags, tracks[{flags, frames: Float32Array(9 × (length+1))}], boneAlpha?, drawOrder?, channelWeights?, morph?, bounds?, events[{time, json}]}]`。`flags & 1`（引用别的动画）、记录轨道、约束轨道语料 0 处，报细分键。
  - `attachments[{bone, name, matrix}]`、`morph`（每网格 `{scale, count, targets[{id, name, position: Int16Array, normal?, tangent?, alpha?, modifier?}]}`）、`editPose?`（MDLE，运行时不用）。
- 骨骼数 > 128：WPE 直接崩溃，我们报 `mdl:skeleton:bones` 退回。
- 只认网格 0：puppet 的几何、组合键、变形纹理都只看网格 0。语料 puppet 都只有 1 个网格（纹理通道的 `3811424158` 是 2 个，网格 1 是通道网格）。
- 骨骼 JSON 照第 2 节逐键实现：门、换算、`ikrminl`/`ikrmaxl`、「不满足门时 flags 清 0」。这决定了哪些骨骼开物理（P12d 的范围是 4 张，不是 5 张）。

### 11.2 编译期（`compile/puppet.ts`）
- 欧拉 → 四元数照 4.5 的式子在编译期做（float32、`Math.fround` 逐步），SoA 不必照抄，按轨道存 `{t[3], q[4], s[3]}` 即可。
- 变形纹理照 6.3 打包：`side = ⌊√(n·nv+1)⌋` 不够再加 1，`rgba16snorm`，纹素 0 = (0,0,0,1)，**网格 0 没有 bit12 时只写纹素 0**。
- 组合键（图像层 puppet，只看网格 0）：
  - skinned（格式含 0x800000 且有骨骼）：`SKINNING=1`、`BONECOUNT=骨骼数`；
  - bit2：`SKINNING_ALPHA=1`；
  - 格式含 0x10000：`MORPHING=1`，槽 5 = 变形纹理；再有 bit13：`MORPHING_MODIFIERS=1`；
  - 有 v23 记录：另编 `CLIPPINGUVS`/`CLIPPINGTARGET` 变体与 `clippingmaskimage4`（P12b）；
  - 不加 `MORPHING_NORMALS`。
- 两种材质变体：直接上屏 = 图层基础材质 + 上述键；带 effect = `effectpassthrough_4.json` + 上述键（采样合成 RT）。

### 11.3 几何与绘制
- puppet 网格代替图层的直接上屏四边形；顶点坐标原样（图层局部像素），模型矩阵照图层「画自己」的矩阵（含对齐）。
- 直接上屏时 UV 乘 `(图像宽/纹理宽, 图像高/纹理高)`，不内缩；带 effect、精灵表、纹理通道时 UV 不动、走合成路径：基础 pass 仍画四边形，effect 照 P8，最后用 puppet 网格采样合成 RT 上屏。
- 索引一律 `uint16`；bit3 时索引缓冲要能按绘制组重写（P12a 可先报 `puppet:draworder` 退回，语料 1 张）。
- 纹理通道（bit1，语料 1 张）先报 `puppet:texturechannels`。

### 11.4 `g_bufAnimation`
- 单独一个 uniform 缓冲（翻译器出成 `@group(?) @binding(?)` 的独立 buffer，只顶点阶段用），大小 `BONECOUNT × 48` 字节；第 i 项 = 蒙皮矩阵（行主序、行向量约定）的第 0、1、2 列各一个 vec4。WGSL 里可声明成 `array<mat3x4<f32>, BONECOUNT>`（三列 vec4），着色器里 `mul(vec4(p,1), g_Bones[i])` 译成按列点乘。
- `g_BonesAlpha`、`g_Morph*` 走普通 uniform 块。
