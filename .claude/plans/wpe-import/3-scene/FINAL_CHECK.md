# 场景壁纸的最终走查

各阶段的验收只证明「这一阶段做的东西」和 WPE 一致。用的多是我们自己生成的测试工程，变换写死、只放被测特性。真实壁纸是很多阶段的特性叠在一起：文字挂在父对象下，父对象的缩放绑着滑块，背景是视频，时钟由脚本按当前时间算。阶段之间的缝隙要靠一次面向真实壁纸的最终走查来证明。

2026-11-13 的例子说明了这一点：一条 WPE 规则在 P3 读码时就记下了，后来在 4 个地方实现、对了 3 个。它不在 P6b 的范围里，而 P6b 的逐像素基线又都是生成的工程，于是第一次在真实场景里露出来，还被我按「看着一致」放过去了，直到用户在真机上看出来。

## 原则（2026-11-13 用户定）

> 走查的原则是先工具到位：确定性工程能够还原一个壁纸的所有状态，然后能够针对某个录制的 WPE 壁纸播放过程逐帧比较，做到逐像素一样，不一样的地方能够正确解释。

具体要求：

1. **工具先到位。** 下面「工具」一节的能力没齐，就不开始走查。比不了的地方不靠肉眼，「看着差不多」不是结论。
2. **确定性工程能还原一张壁纸的全部状态。** 读回的那一帧里，影响画面的每一个输入都要和 WPE 那一帧相同：
   - 用户属性；
   - 时间（`g_Time`、每帧的帧时间）；
   - 光标轨迹；
   - 脚本状态和脚本看到的外部值（`Date`、`engine.*`、随机数、音频缓冲、媒体信息）；
   - 粒子的随机数与模拟历史；
   - 视频时刻；
   - 音频频谱；
   - 窗口尺寸与铺放方式；
   - 后处理档位。
3. **对着一段录制的 WPE 播放过程逐帧比较。** 「录制」是 WPE 实际跑的一段：连续抓帧，加上每帧的输入。我们按同样的输入逐帧回放，每帧整帧逐像素比，目标是逐像素一样。
4. **不一样的地方要能正确解释。** 每一处差异都要定位到具体的 draw 和具体的值，然后归到两类之一：
   - **已知差异**：写明依据，并说明为什么不复刻；
   - **bug**：要修。

   「背景在动所以对不上」「像素差几级」不算解释；解释不了就是不通过。
5. **每个 phase 的会话走自己的那部分，用复制工程排除干扰。** 每个阶段的会话从真实壁纸里挑出用到本阶段特性的那些，各自走查。为了不让别的阶段的特性混进来（视频背景、粒子、没实现的脚本 API 等），像 `3836725625` 这次一样复制工程：只留和本阶段有关的对象，其余删掉，或把它们换成固定值。复制工程照样要按第 2–4 条还原状态、和录制的 WPE 帧逐像素比、解释每一处差异。WPE 那边录的是同一份复制工程，不是原壁纸。

   复制时，被测对象影响画面的东西一样都不能动：
   - 整条父链，以及父链上每一层的变换；
   - 绑定与属性；
   - 脚本；
   - effect。

   只删和它无关的对象。这次如果顺手把父对象「时钟」的 `scale` 绑定也换成固定值，bug 就会被一起删掉。

## 例子：`3836725625` 的时钟被纵向拉长（P6b 1e-3，2026-11-13）

**当时的验收。** 1e-3 解锁了 9 张时钟场景，我按 WPE 抓帧比了三张：
- `2391389126`：文字区域逐像素相同；
- `2903412088`：字形内部相同，边缘差（最大 19）归给了在动的背景；
- `3836725625`：背景是视频、盖着彩纸粒子，没逐像素比。我看了两张裁图就记成「三层文字的排版和 WPE 一致」，其实位置已经偏了。

**用户发现。** 真机上并排看，我们的字明显被拉长。

**补做的走查（复制工程，原则第 5 条的来历）。**
1. 复制工程，去掉视频图层，父对象的 `origin` 脚本换成固定值（它只决定整组的位置，两边各算各的会混进位置差），只留三层文字。父对象的 `scale` 绑定原样保留。做静态字符串、脚本返回同一串两版（`ignore/p6/b1e/make_e3text.mjs`），在纯色背景上和 WPE 按同尺寸整帧比。
2. 结果：两版在我们这边渲染逐像素相同，所以问题不在运行中重排。和 WPE 比都差 15631 个像素：x 方向完全一致，y 方向三层都被拉长约 1.4 倍。
3. 我们的排版 `size` 和合成 RT 尺寸三层都和 WPE 的 RT 相同（490×219、457×154、896×219），所以问题在上屏的矩阵。
4. WPE 事件 146（Day 上屏）的顶点：模型空间 ±228.5 × ±77，上屏高 125.5 = 154 × 1.13179 × 0.72。我们父对象「时钟」的 `scale` 是 `[0.72]`，只有一个分量，y、z 在建矩阵时补成 1，y 相对 x 放大 1 / 0.72 ≈ 1.39 倍。这一步没有逐 draw 的工具，是临时写了个单测在 Node 里算出来的。

**根因与来历。**
- WPE 的 `origin`、`scale`、图像层 `color`（vec3，`FUN_1401a4230`）与 `parallaxDepth`（vec2，`FUN_1401a3fc0`），和材质常量、general 字段是同一组 setter：数字铺满各分量，字符串按空格读、少写的分量为 0，布尔不写。
- **P1（2026-11-01）**：`916f5cf5` 用 `numbers()` 取图层字段，标量只得一个分量；`3780ab82` 的 `layerLocalMatrix` 按 `[sx = 1, sy = 1, sz = 1]` 补缺。
- **P3 读码**（`phase3/p3-script-REPORT.md`「属性写入」表）记下了「数字会铺满三个分量」，并且实测过。
- **P3a（2026-11-03）**：`8f5a44ac` 改走绑定表，新增运行中的 `writeLayer`，原样继承了 P1 的行为。
- **P3c**：给 general 字段的就地写照 `FUN_1401a4230` 做了铺满（`generalValue`），同一个 setter 管的图层字段没改。
- **2026-11-08**：`54ab0c08` 给材质常量做了铺满（`materialValues.ts`），也没改图层字段。
- 同一条规则另外还在粒子模块、文本字段各写过一份。

**为什么各阶段的验收没抓到。**
- 测试工程是生成的，变换写死，没有「标量属性绑向量字段」；
- 1c、1d 的逐像素基线证明的是文字本身；
- 能力表不检查「属性分量数和字段分量数对不上」，场景不会退回，而是静默画错；
- 真实场景比不了的时候退回了肉眼。

**影响面。** 本机语料有 34 张场景、245 个字段是「向量图层字段绑标量属性」（`ignore/p6/b1e/scalar_vec_scan.mjs`）。当时被判成能渲染的有 3 张，都是 1e-3 刚解锁的：`3836725625`、`3825103811`、`2903412088`。

**修复。** 图层的向量字段在编译期和运行中都改走材质常量那一份 setter（`compile/bindings.ts` 的 `layerVectorValue`）。之后两版纯文字工程和 WPE 整帧 0 差异。

**按本文的原则，这次本该怎样被抓到。** 工具能还原 `3836725625` 的全部状态：
- 时钟字符串由录制时刻决定；
- 视频帧由视频时刻决定；
- 彩纸粒子由随机数与模拟历史决定；
- 属性取缺省值。

和录制的 WPE 帧整帧逐像素比，第一帧就有一块 1.4 倍的差，必须解释。逐 draw 对齐后，直接落到父对象的 `scale`。

## 走查流程（工具齐了以后）

1. **分工与选场景**：每个阶段的会话负责自己的特性。
   - 从语料里按特性挑出用到它的真实壁纸，以语料扫描里判成能渲染的为主；
   - 再加上这个阶段的关键样本。
2. **复制工程**：每张壁纸复制一份，只留本阶段要看的对象（保留规则见原则第 5 条）。原壁纸整张的走查，等各阶段都走完后再整体做一遍。
3. **每张复制工程**：
   - 录制 WPE N 帧，带全部输入；
   - 确定性回放同样的 N 帧；
   - 每帧整帧逐像素比；
   - 差异逐处解释；
   - 记一行。
4. **判定**，三种结果：
   - **逐像素相同**；
   - **差异已解释**：引用已知差异的条目与依据；
   - **未解释**：不通过，查到能解释为止。
5. **记录**，每张一行：
   - 阶段、原壁纸、复制工程里留了哪些对象、换了哪些字段；
   - 帧数、窗口尺寸、档位；
   - 结果；
   - 每处差异与解释；
   - 依据（抓帧路径、比较图、draw 对照）。
6. **已知差异集中登记**。每条写：
   - 现象、范围；
   - 原因与依据；
   - 为什么不复刻。

   目前散在 `cocs/wpe/WPE_SCENE.md` 各节的「已知差异」里，走查时汇总引用。例：WPE 场景比窗口大时按窗口分辨率直接画字形，我们先按场景分辨率画再缩（`2391389126` 在 1600×900 窗口下文字区域差 805 个像素，按场景尺寸比则为 0）。
