# WPE 组里的模型对象（P14b 读码）

wallpaper64.exe（sha256 `40e2ce02…3b0`，md5 `438cb215…a588`，与安装目录的同一份），Ghidra 12.1.4（REA）。前置：rea-p5-modelflags §2.2、§2.5
（组画子树），rea-p5-mesh 2.6、3.1、4.4（网格绘制、深度目标、视锥剔除）。

## 1. 网格绘制 `FUN_1402222a0`【确】

1. `ctx+0x11c & 1` 时视锥剔除：
   - 包围盒两角 `obj+0x2f8..0x300`（min）、`obj+0x304..0x30c`（max）用 `vfunc+0x80` 的矩阵变换；
   - 球心取两点中点，半径取半对角线长；
   - `ctx+0x1c8 == 0` 时 `FUN_1401e5a10(ctx+0xec0, 球心, 半径)` 在平面外就 `return`；否则逐视图测 `ctx+0xf20 + 0x60·i` 的六个平面，只给可见视图发实例（阴影多视图）。
2. `obj+0x120 & 0x80`（`perspective`）时复制并压投影栈（`ctx+0x40`）、视图栈（`ctx+0x38`），再调 `FUN_1401e5b60`。
3. 写 `g_Color4`（`ctx+0x120..0x12c`）= 1。
4. 压模型栈：`ctx+0x30` 栈顶复制到下一格，再 `栈顶 = FUN_14005ecb0(旧栈顶, vfunc+0x80())`。即 **M = 栈顶 · W**。
5. 逐绘制记录绑材质、画、解绑（含变形、骨骼，见 P12b2）。
6. 弹模型栈（`ctx+0x30 −= 0x40`），透视时再弹视图、投影栈。

- `vfunc+0x80` 同时用于剔除和 M，是对象的世界矩阵 `W`（场景空间，含父链）。组画子树时栈顶是 `inverse(W_组)`（§2.5），所以组里 **M = inverse(W_组) · W**，剔除仍用 **W**。
- 【推】`g_ModelMatrix` 取模型栈顶 M，`g_ModelViewProjectionMatrix` 由投影、视图、模型栈拼出。图像层在组里的结合顺序已由 P8 步骤 7 抓帧确认（`groupMvpParts`）；网格的结合顺序与 `g_ModelMatrix` 要点 0 抓帧定。

## 2. 剔除平面在组里不重算【确，有界】

- 平面由 `FUN_1401849e0(ctx+0xec0, ctx+0x930)` 从视图投影算。它的直接调用方只有三个（REA `procedure_callers`）：
  - `FUN_14018aac0`（场景绘制）；
  - `0x140196530`、`0x140196ce0`（【推】阴影或反射的视图函数）。
- 组画子树的 `FUN_140207b50`、`FUN_1401ecb20`、`FUN_1401eca70` 都不在其中，也不调 `FUN_14018aac0`（§2.2：直接调子层的 `vfunc+0x50`）。
- 所以组里的模型照样用**本次场景绘制的场景相机平面**，测**场景空间**的外接球。
- 结果：
  - 组在画面里时，和顶层一样；
  - 组在画面外、它的 RT 又被别的图层读时，组里的模型会被剔掉。
- 有界：只看了已解析的直接调用；间接调用（虚函数表）没穷举。
- 处理（P14b D1）：组里的模型画进组 RT、用组的局部正交，按场景相机剔除在上面第二种情况下是错剔，判为缺陷、不复现，没有实测。

## 3. 深度【确，引 rea-p5-mesh 3.1】

组的合成 RT 深度格式 0x1b，不挂 DSV。D3D11 下深度测试与写入都不生效，组里网格的 `depthtest` / `depthwrite` 不起作用。

## 4. 阴影 pass 不画组里的模型【确，有界】

- 阴影 pass `FUN_140196530`（rea-p13-passes 2.6）调 `FUN_14018aac0(G, 2)`，名单是 `G+0x158`（全部对象）。函数里四个循环（`0x108` 抖动分支、
  `0x1000` 透明排序的两遍、普通分支）对每个对象的判定都是同一句：
  `(obj+0x120 & 2) == 0 && (模式 != 2 || (obj+0x120 & 0xc00) == 0xc00)` 才调绘制虚函数 `+0x50`。
- 组里的模型带 `0x2`（§2.2：组合层的子孙任意深度都带），在阴影 pass 顶层被跳过。
- 组本身是图像对象（组合层），不透明位 `0x400` 只有模型置（rea-p13-passes 2.7，有界：`or … +0x120` 的写点），所以组在阴影 pass 里不画、
  它的 `+0x50`（画子树进组 RT）不会以阴影模式被调。图像对象 JSON 写 `castshadow: true` 只置 `0x800`，仍不满足 `0xc00`。
- 结论：**组里的模型在 WPE 里不投射阴影**，不管 `castshadow`。反射 pass（模式 1，名单 `G+0x1c8`）同样先判 `0x2`，组里的对象不进反射。
- 实测：`p14b-gm-shadow`（点 0）。

## 5. 顺带

- `FUN_1401849e0`（算视锥平面）的另两个调用方：`0x140196530` 是阴影 pass（每个视图一组平面进 `ctx+0xf20 + 0x60·i`），`0x140196ce0` 是
  一盏灯的体积光绘制（rea-p13-passes 3.2）。两者都不在组画子树的路径上，§2 的结论不变。
