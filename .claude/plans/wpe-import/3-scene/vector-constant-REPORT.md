# 材质常量的分量数与 uniform 类型不一致：WPE 与我们的填法

**结论**
- 能渲染的 18 张场景**没有一处踩到**。它们的材质常量都是数字进 float，或段数正好的字符串；用户属性只有滑块→float、颜色→vec3。唯一的结构性分歧（2418800402 foliagesway 顶点半边的 `g_Phase`）没被着色器引用，画面不变。
- 全语料 152 张里，分量数对不上的 70 处，全在不能渲染的场景：数字进 vec2 20 处（14 处会画错，blur_gaussian / scroll 的 `g_Scale.y` 变成 0），逗号分隔的字符串 47 处（被引用的 10 处会画错），数字字符串缺省进 float 3 处（两边相同）。
- WPE 的规则（读码【确】）：类型按声明行（含注释）的子串定；数字进向量铺满；字符串进向量先清零、按空格切、逐段 `atof`；float 只收数字；布尔、数组一律不写；缺省值先转成字符串，所以**数字缺省不铺满**；带 condition 的值变成布尔，材质常量收不到。
- 与我们的分歧：数字铺满；字符串、布尔进 float；condition；分隔符（逗号、前导空格、tab）；数组；就地写保留旧分量；两阶段同键取片元缺省；同阶段同键只留后一个。按影响排，先对齐「数字铺满」和「就地写整体重写」，再对齐逗号解析；其余在语料里没出现。

**元数据**
- 目标 `wallpaper64.exe` 2.8.42，SHA-256 前缀 `40e2ce021e935232`，开工核对一致。只分析 scratchpad 副本，未运行 WPE。

## 1. 我们现在的规则

### 1.1 编译期

- 入口 `compile/shader.ts` `shaderUniforms`。来源优先级：
  - `usershadervalues` 绑定的属性（属性有值时）；
  - `constantshadervalues`：`{user}` 取属性当前值，没有时取 `value`，带 condition 换成布尔；`{script}` 取 `value`（同时有 `user` 时忽略 `user`）；`{animation}`、数组、其它对象解析成 undefined，退回缺省；
  - 注解 `default`。
  - 同一个材质键的多个 uniform 写同一个值；被翻译器拆开的两半（两阶段同名）只取缺省时各按自己的注解。
- 换算 `compile/model.ts` `numbers()`：数字 → `[v]`；布尔 → `[1]` / `[0]`；字符串按 `/\s+/`（含 tab）切，全是有限数才用，否则 `[]`；其它 → `[]`。
- 写缓冲 `render/uniforms.ts` `UniformBlock.set`：写 min(声明分量数, 值长度) 个分量，新建的块其余为 0。

| 值 | 进 float | 进 vecN |
|---|---|---|
| 数字 0.4 | 0.4 | (0.4, 0, …) |
| `"0.4"` | 0.4 | (0.4, 0, …) |
| `"a b"`（少于 N） | a | (a, b, 0, …) |
| 段数多于 N | 第一段 | 截断 |
| 布尔 | 1 / 0 | (1 或 0, 0, …) |
| `"a, b"`、`"a,b"` | 0（解析失败） | 全 0 |
| `" a b c"`（前导空格） | a | (a, b, c) |
| `"a\tb"` | a | (a, b) |
| JSON 数组 | 缺省值 | 缺省值 |
| 数字缺省 0.3 | 0.3 | (0.3, 0, …) |

### 1.2 就地写（属性运行中改值）

- `compile/bindings.ts` `bindingValue` → `render/state.ts:317`（`constant` 目标）→ `render/scene.ts` `refreshPass`。
- 换算与编译期相同（单测保证），condition 换成布尔再 `numbers` 成 `[1]` / `[0]`。
- **差在写缓冲**：`refreshPass` 在已有的块上 `set`，没给到的分量**保留上一次的值**，不是 0。滑块绑 vec3 改值只动 x；颜色改成一段字符串也只动 x。

### 1.3 脚本写回

- `script/runtime.ts` `writeReturn`、`script/api.ts` `write`。目标类型取 uniform 反射（`compile/bundle.ts:760` 回填）。
- 数字按类型铺满；对象要类型内的 x…w 全是数字，否则不写；拼成字符串再走 `state.write`。与 WPE 一致（p3 L6）。

### 1.4 结构

- effect 实例的 pass 只合并 `combos`、`constantshadervalues`、`textures`（`compile/bundle.ts:858`），实例里的 `usershadervalues` 丢了。
- 同一个材质键的多个 uniform 都填同一个值。

## 2. WPE 的规则

### 2.1 着色器常量表【确】

- 逐行解析 `FUN_1401636a0`，由 `FUN_1400dab40` 对每条 `uniform` 行调用：
  - 行里有 `sampler` 跳过。注解要有字符串 `material`，否则不是材质常量。
  - 名字取第一个 `;` 往回到空格。必须在本阶段编译结果的反射里（`FUN_1400dfa90` 按名字查，标志 `&2`、位置 ≠ −1），否则丢弃。【推】`&2` 是「被使用」。
  - **类型按整行子串判断，注释也算**：含 `vec3` → 3（先查），否则含 `vec4` → 4，否则含 `vec2` → 2，否则 1（float）。三个串在 `0x14048744c`、`0x14048747c`、`0x14048745c`。`int`、`bool`、`mat*` 都当 float。
  - `default` 一律存成字符串：字符串原样；整数（rapidjson `kIntFlag` 0x20）转十进制；其它数取 float 的最短表示；布尔、数组、null 不存（空串）。
  - `"type": "color"` 只在 vec3 时打颜色标记。`conversion` 为 `rad2deg` / `startdelta` 时打标志位，前者让描述符 `+0x60 |= 4`。
- 每个阶段一张表，**按材质键存**（`FUN_1400ddb60`，即 `operator[]`）。同一阶段两个 uniform 同键，后解析的覆盖先解析的。
- 合并：`FUN_1400d5070` 对顶点、几何、片元各调一次 `FUN_1400dab40`，再用 `FUN_1400d39f0` 合并（顶点 ∪ 几何，再 ∪ 片元）。同键时**后者整条覆盖**，所以片元赢。合并表就是程序的常量表（程序 `+0x20`）。
- 槽位：`FUN_1400d5070` 尾部按材质键顺序累加类型（1–4 个 float），`+0x45` = 起始 float 下标，累计到 48（0x30）为止。

### 2.2 上传【确】

- 每个阶段一份指令表（`FUN_1400dccd0`）。每个条目三个 ushort：`(id, 位置, 槽位)`。
  - id 按**本阶段条目自己的类型**：float 0x8c、vec2 0x8d、vec3 0x8e、vec4 0x8f。
  - 槽位按材质键查合并表。
- 执行在 `FUN_1400d8300` 的 switch（字节表 `0x1400daaac`，RVA 表 `0x1400da984`），源是 pass 的 float 存储 + 4×槽位：

| id | 落点 | 拷贝 |
|---|---|---|
| 0x8c | `0x1400da87c` | 4 字节 |
| 0x8d | `0x1400da895` | 8 字节 |
| 0x8e | `0x1400da8af` | 12 字节 |
| 0x8f | `0x1400da8d5` | 16 字节 |

- 推论【推】：本阶段类型比合并类型大时（两阶段同键不同类型），会多读下一个材质常量的存储。这就是现在报 `constant:mixed-type` 的情况。

### 2.3 材质 pass 的取值【确】

- pass 对象在 `FUN_1401515b0` 分配（0x318 字节），`+0x120` 起 48 个 float 先清零：`FUN_1404217a0(+0x120, 0, 0xc0)`。
- effect 实例的 pass JSON 用 `FUN_140153200` **深合并**进材质 pass：对象逐键递归，包括 `usershadervalues`。
- `FUN_140154480` 的顺序：
  1. `constantshadervalues` 拷到 `+0x248`。
  2. 合并表里每个材质键，`+0x248` **没有这个键时**插入缺省：float 插 `atof(缺省串)`（实数）；向量插缺省串本身（字符串）。**有键时不补缺省**，哪怕那个值后面写不进去。
  3. `usershadervalues`（`{属性名: 材质键}`）：把 `+0x248[材质键]` 改写成 `{value: 原值（是 {value} 就取里面）或第 2 步的缺省, user: 属性名}`。
  4. 每个材质键建一个描述符（`0x1401553cb`–`0x1401554fc`）。偏移 `0x120 + 4×槽位`；setter 按合并类型：1 `FUN_1401a4b00`、2 `FUN_1401a3fc0`、3 `FUN_1401a4230`、4 `FUN_1401a4580`；改值回调 `0x1401538c0`（`+0x1f8 |= 3`，标脏重传）。
  5. `FUN_1401730d0` 用描述符逐键套用 `+0x248`（调用点 `0x1401555d0`），开着「解析绑定」。表里没有的键（着色器没有，或被反射丢弃）忽略。

### 2.4 setter【确】

jsoncpp 类型：1 int、2 uint、3 real、4 string、5 bool、6 array、7 object。

- float（`FUN_1401a4b00`）：只收 1–3，用 `asFloat`（`FUN_140086220`）写一个分量。字符串、布尔、null、数组**都不写**。
- vec2 / vec3 / vec4（`FUN_1401a3fc0` / `FUN_1401a4230` / `FUN_1401a4580`）：
  - 1–3（数字）：**铺满全部分量**。
  - 4（字符串）：**先把 N 个分量清零**；`atof`（`FUN_1402d06ac` = `common_atof_l`）读第一段；往后找第一个空格（只认 0x20），跳过连续空格，再 `atof`；最多 N 段。少的为 0，多的忽略。
  - 布尔、null、数组：不写。
- 对象（7）：开着解析绑定时取 `value`，按同样的规则写，再交给 `FUN_1401a4db0` 登记 `user` / `script` / `animation` 绑定。
- 写完都调描述符的改值回调。

由此直接得到：

| 值 | 进 float | 进 vecN |
|---|---|---|
| 数字 0.4 | 0.4 | 铺满 (0.4, 0.4, …) |
| `"0.4"` | **不写** → 0 | (0.4, 0, …) |
| `"a b"`（少于 N） | 不写 | (a, b, 0, …) |
| 段数多于 N | 不写 | 截断 |
| 布尔 | 不写 | 不写 |
| `"a, b"` | 不写 | (a, b) |
| `"a,b"` | 不写 | (a, 0, …) |
| `" a b c"` | 不写 | (a, a, b) |
| `"a\tb"` | 不写 | (a, 0, …) |
| JSON 数组 | 不写 | 不写 |
| 数字缺省 0.3 | 0.3 | (0.3, 0, …)，**不铺满** |

「不写」时存储是初值 0；同一个键之前写过（比如加载时的 `value`）就保留那次的值。

### 2.5 用户属性

- 加载【确】：2.3 第 5 步套用时，`{user, value}` 写 JSON 的 `value`。场景构造完，再以属性全集为增量走一次运行时路径（p3 I1）。
- 运行时【确】：`FUN_1401731d0` 对增量里每个键、每个绑定：
  - 没有 condition：原值交给 setter；
  - 有 condition、值不是数组 / 对象：`字符串(值) == condition` 换成 **JSON 布尔**再交给 setter。【推】参数次序从伪代码推出，Ghidra 丢了第三个实参。
- 由 2.4 得到：
  - 滑块（数字）绑向量 → 铺满；颜色（字符串）绑 vec3 → 正常；颜色绑 vec4 → w 清零。
  - **布尔属性、字符串属性（下拉的字符串值、颜色）绑 float → 不写**，留着加载时的 `value`。
  - **带 condition 的材质常量运行中永远不变**：布尔进哪个 setter 都不写。
- `usershadervalues` 走同一条路（2.3 第 3 步）。
- 加载与运行用同一个 setter，每次都整体重写（数字铺满，字符串先清零），没有「保留旧分量」。

### 2.6 脚本写回

- 描述符 `+0x48` 的类型化 setter 只拷指针给的 N 个 float【确】：`0x1401a49f0` 4 字节、`0x1401a4200` 8、`0x1401a4530` 12、`0x1401a4900` 16。
- 数字铺满、对象缺分量就放弃，这两条在脚本 DLL 里（p3 L6，读的是 vec3 分支）。float / vec2 / vec4 分支没读【推，同理】。

### 2.7 与翻译器 README 的出入

- `src-tauri/wpesl2wgsl/README.md`「两阶段同名 uniform」说两个阶段各按自己的注解取值。它的实测依据是 `foliagesway` 的 `g_Speed`：顶点键 `speed`、片元键 `speeduv`，**两个不同的材质键**。读码与它一致。
- **同键不同缺省**（`foliagesway` 的 `g_Phase`、旧 `perspective` 的 `g_Top` 等）：合并表里片元覆盖顶点，缺省只插一份，两个阶段读同一个槽，**都是片元的缺省**【确，代码路径；没实测】。我们给两半各自的缺省。
