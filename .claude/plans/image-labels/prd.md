## 1. 背景与目标

现在图片的归类手段只有两种：画册（用户手动整理）和插件写的 metadata（只能看，不能用来筛选或整理）。
插件其实掌握大量结构化信息（作品、角色、画师、tag），但用户拿不到；用户自己想给图片打个「角色 / 作品」
这样的轻量标记，也只能建一堆普通画册。

目标：

1. 用户能**看见**每张图片带了哪些标签，并能**增删、复制**。
2. 用户能**按标签找图**，包括按一整个标签目录找。
3. 用户**不需要学新界面**：标签就是一种画册，沿用画册页的树、拖放、加入画册、右键菜单这些已有操作。
4. 插件能**自动**给新下载的图片打标签，也能给历史图片**补**标签，用户什么都不用做。

## 2. 用户视角的概念

- **标签**：挂在图片上的一个标记，有两样东西：
  - **标识（key）**：必填，只能用英文字母、数字、`_`、`-`，不超过 64 字节，之后可以修改。
    搜索和复制用的都是它。
  - **名称**：可选，显示给人看的文字，可以随便写（中文、空格、符号都行），随时可改；不填时等于 key。
- **标签画册**：标签在画册页里的样子。一个标签画册 = 一个标签，里面是直接打了这个标签的图片，子标签以
  子画册的形式出现——和文件夹画册（里面是这个文件夹的文件，子文件夹是子画册）完全同一套逻辑。
  想一次看一整个目录下的图片，用「标签」搜索并勾选「包含子标签」。
- **标签目录**：标签画册在树里的父级链。例如 `pixiv › 角色 › 初音ミク`（key 分别是 `pixiv`、`character`、
  `hatsune`）。父级本身也是标签画册，也可以直接用来打标签、搜索。目录层数和总长度不限。
- **标签森林**：标签画册和文件夹画册一样**单独成一片森林**：在画册树里有自己的「标签」分区，
  只能挂在别的标签画册下或标签分区顶层；普通画册、文件夹画册与标签画册之间不能互相嵌套。
- **图片上显示直接打上的标签**：图片上显示的是它被直接打上的标签。插件打的是最具体的那个（如
  `初音ミク`），不会把 `pixiv`、`角色` 也列出来——叶子已经隐含了整条目录，信息没有丢失，按目录搜索时这些
  上级照样能命中。用户如果又把同一张图加进了上级 `角色`，图片上就显示两个标签，不做合并或去重。
- **插件标签**：插件自动打的标签放在以插件为根的一支标签画册下（如 `pixiv › …`），中间目录自动建出。
  它们和用户自己建的标签用法完全一样，用户同样可以增删、改名、移动。

## 3. 用户操作

### 3.1 在图片预览里查看、编辑、复制标签

入口：打开任意图片的预览弹窗（`ImagePreviewDialog`，桌面和紧凑布局都要有）。

| 用户操作 | 结果 |
|---|---|
| 打开预览 | 在图片信息区看到这张图片的全部标签，每个显示名称 |
| 点标签上的删除 | 这张图片不再带这个标签；标签本身和其他图片不受影响 |
| 点「添加标签」，从已有标签里选 | 输入时按名称或 key 联想已有标签，选中后立即加到图片上 |
| 点「添加标签」，输入一个不存在的 | 当场创建：填 key（必填）、名称（可选），选放在哪个标签画册下（默认标签分区顶层），确认后建好并加到图片上 |
| 点「复制标签」 | 把这张图片全部标签的 **key** 用 `, `（英文逗号 + 空格）连接后复制到剪贴板，如 `hatsune, vocaloid` |
| 切换到上一张 / 下一张 | 标签区跟着切换 |
| 点某个标签 | 跳到画册页的这个标签画册 |

「复制标签」同时出现在图片右键菜单里，行为相同；图片没有标签时该项不可用。复制出来的文本可以
直接粘进「标签」搜索框。

约束：

- key 不合规（有中文、空格、`.`、`/` 等，或超过 64 字节）时，输入框直接提示原因，不能提交，也不会自动改写。
- 同一目录下 key 不能重复；重复时提示「该标签已存在」，并允许直接选用已有的那个。

### 3.2 按标签搜索

入口：画廊、画册、任务详情、畅游详情页的查询条，搜索目标里新增一个 **「标签」** tab，与现有的
「显示名 / 路径 / 链接 / 元数据 / 原生元数据」并列。搜索框下方有一个勾选项 **「包含子标签」**。

| 用户操作 | 结果 |
|---|---|
| 输入 `hatsune` | 带有 key 为 `hatsune` 的标签的图片 |
| 输入 `hatsune, vocaloid` | 英文逗号分隔多个标签，**同时带有全部这些标签**的图片 |
| 输入 `character`，勾选「包含子标签」 | 带有 `character` 或它下面任一子标签（如 `hatsune`）的图片 |
| 输入 `character`，不勾选 | 只匹配直接打了 `character` 这个标签的图片 |
| 输入 `pixiv/character/hatsune` | 用完整目录 + key 精确指定某一个标签（同名 key 在不同目录下时用） |
| 与其他过滤、排序、高级查询组合 | 和现有搜索维度一样叠加，URL / 查询 chip 能保存、能回退 |

约束：

- 分隔符只认英文逗号 `,`，逗号两边的空格忽略（所以复制出来的 `a, b` 可以直接粘贴）。
- 多个标签之间是「且」；要「或」用已有的高级查询组合器。
- 「包含子标签」对输入里的每个标签分别生效。
- 输入不存在的标签不报错，结果为空。

### 3.3 在画册页管理标签画册

入口：画册页左侧画册树（及紧凑布局的画册抽屉）新增「标签」分区。所有操作尽量复用普通画册已有的入口和交互。

| 用户操作 | 结果 |
|---|---|
| 新建画册时选择类型「标签」，填 **key**（必填）和 **名称**（可选），选父级 | 在标签森林里创建一个标签画册；父级只能是标签分区顶层或另一个标签画册 |
| 在树里点开标签画册 | 中栏显示直接打了这个标签的图片，子标签画册在树里展开查看；可用查询条筛选、排序、翻页，和普通画册一样 |
| 看树里的计数 | 与文件夹画册相同：自身图片数加上全部子标签画册的图片数（同一张图同时在上级和子级时会算两次） |
| 把图片「加入画册」到标签画册（右键 / 批量操作 / 加入画册对话框） | 这些图片被打上该标签 |
| 从外部把文件拖进当前打开的标签画册 | 文件照常导入，导入的图片自动带上该标签 |
| 在标签画册里「从画册移除」图片 | 这些图片去掉该标签，子标签不受影响；图片本身不删 |
| 重命名标签画册 | 改名称；插件不会再改动它 |
| 修改标签画册的 key | 改完立即生效，搜索、复制都用新 key；同一目录下不能与已有 key 重复 |
| 拖动标签画册到另一个标签画册下 / 标签分区顶层 | 换目录；图片上的标签不受影响。拖进普通画册或文件夹画册被拒绝 |
| 删除标签画册 | 它和它的**全部子标签画册**一起删除，这些标签从所有图片上移除，图片本身不删 |
| 用标签画册做壁纸轮播、在虚拟磁盘 / MCP 里浏览、web 只读模式、Android | 与普通画册一致，复用现有能力，不单独做（轮播只用直接打了该标签的图片，与文件夹画册一致） |

与普通画册的区别，用户能感知到的只有：树里有单独的「标签」分区和图标；新建时多一个 key 输入框；
画册详情里显示 key。内容与计数的口径和文件夹画册一致。

### 3.4 插件自动打标签（用户无需操作）

| 场景 | 用户看到的结果 |
|---|---|
| 插件下载到新图片 | 新图片带上插件给的标签；树里自动出现 / 补齐以插件为根的标签目录 |
| 插件下载到图库里已有的图片（去重命中） | 若开启了已有的「去重时更新元数据」设置，已有图片补上新标签，原有标签不动；关闭则不补 |
| 插件升级后首次启动 | 该插件以前下载的图片在后台自动补上标签，完成后标签画册和计数刷新 |
| 用户删掉了插件打的某个标签 | 插件再次下载到这张图时会重新打上（去重命中时同样受上面的设置控制） |
| 用户删掉了插件建的整个标签画册 | 插件再次打这个标签时会重新建出来 |
| 插件给已存在的标签换了名称 | 插件给的名称只在第一次创建标签时使用；已存在的标签永远不会被插件改名，用户起的名称因此始终保留 |
| 用户改过插件标签的 key，或把它移到了别的目录 | 插件按「目录 + key」认标签，找不到原位置时会在原位置重新建一个；用户改过的那个保持不变 |

插件给的标签只增不减：插件永远不会移除图片上已有的标签。

## 4. 规则汇总

- key：`[a-zA-Z0-9_-]`，必填，不超过 64 字节，可修改。
- 名称：可选，任意文本，可改；没填时等于 key。插件只在创建标签时设置名称，之后永不改动。
- 目录：由标签画册在标签森林里的位置决定，层数、总长度不限；同一目录下 key 唯一，不同目录下可重复。
- 标签画册只在标签森林里嵌套；删除时连同全部子级。
- 图片上只记录、显示被直接打上的标签；上级目录隐含其中，可被「包含子标签」搜索命中。
- 标签画册的内容只含直接打上该标签的图片；计数含子级（逐级加总，不去重），与文件夹画册一致。
- 一张图片可以有任意多个标签，同一标签不会重复出现。
- 标签不影响图片的收藏、隐藏、所属普通画册 / 文件夹画册。
- 插件 id 收紧为同一字符集（不允许 `.`），保证插件根标签画册的 key 合法。

## 5. 不做

- 标签的颜色、图标、描述等附加属性。
- 标签之间的同义 / 合并关系（「合并两个标签」可作为后续需求）。
- iOS。

## 6. 已关闭的问题

- 冗余的上级标签：图片同时在 `character` 和 `hatsune` 里就显示两个标签，不做合并或替换。
- 在上级标签画册里「从画册移除」只来自子标签的图片：标签画册只显示直接成员，这种情况不存在。
- 「标签」搜索框的输入联想：暂不做（预览里「添加标签」选已有标签时的联想仍需要）。
