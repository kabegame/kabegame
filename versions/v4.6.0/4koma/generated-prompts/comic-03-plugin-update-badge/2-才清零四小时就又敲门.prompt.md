# Kabegame 发布日志漫画

## Kabegame 世界观

一个魔法异世界，Kabegame 应用界面像一座“壁纸魔法工坊”，左侧导航是通往不同房间的传送门，画廊是壁纸陈列大厅，画册是分类收集仓库，「源」页是召唤新壁纸的插件魔法小店，任务抽屉是远征委托板，设置弹窗是魔法调律室（从 kamechan 的工具箱里打开）。

看板娘kamechan(かめちゃん)是 Kabegame 的桌面守护者，也像工坊里的小管理员。她不会战斗，不会魔法，而是用温柔、实用、带一点俏皮的方式整理壁纸收藏。

她有一个小乌龟壳背包精灵搭档。它有两个形态，独立的小乌龟和背在背上的两种形态。平时它被背在看板娘背上，是可爱的小乌龟壳背包；需要帮忙时，它可以从背包形态化为小乌龟助手，拿路牌、盖章、推小车、举检查表、搬相册盒子、压住乱飞的刷新纸条。它的存在是治愈和轻松。

PathQL 魔女是 Kabegame 工坊里的“路径魔女”，是一个可爱、聪明、稍微有点小得意的魔女。她负责把复杂的壁纸数据变成可以走的路径，把画廊、画册、任务详情、插件和虚拟磁盘连接到同一套路径规则里。她会施展路径おまじない，让 Provider 过滤树发光、分页轨道对齐、插件入口自动接到正确房间。 她手里拿着路径魔法书、卷轴或发光路标，身边漂浮着 `/gallery`、`/albums`、`/plugins`、`fetch`、`count`、`children` 这类短路径符号。她的魔法特效应该是细细的路径线、发光节点、目录树、书签和小型传送门。

PathQL 魔女和 kamechan 的关系是帮忙整理工坊的伙伴。kamechan 负责整理壁纸收藏并可爱地展示它们，PathQL 魔女负责让背后的路径和规则稳定运转。两人同框时，看板娘更元气治愈，PathQL 魔女更理性、俏皮、像在说“路径已经安排好了”。

异世界魔法元素要轻量：

- Provider 过滤树可以像发光的魔法路径树。
- PathQL / DSL 可以像工坊里的路径咒文或目录魔法书。
- Provider 路径则像咒语。
- 插件是一个个呆萌可爱的小精灵，不同网站的插件有不同的配色。
- 画册可以像收纳宝箱、相册房间或轮播舞台。
- 任务可以像远征委托，进度条像魔法能量槽。
- 应用内背景图可以像把壁纸铺成舞台幕布。
- 设置项可以像调律仪表、滑杆和开关咒具。

现代软件 UI 占主体，魔法元素作为装饰和视觉隐喻。UI 结构必须清楚，不能被魔法特效遮住。整体氛围是“二次元开源壁纸工坊的一天”，轻松、治愈、带一点小コント。

## 页面布局设定

### Kabegame 桌面主框架布局

用途：

当漫画里需要表现“这是 Kabegame 应用本体”时使用。适合任何页面的背景，也适合让看板娘站在左侧导航栏前做导游。

整体布局：

桌面端是现代应用窗口。左侧是一条窄窄的图标导航栏，右侧是主内容区。整体底色是很淡的粉紫渐变，主内容区顶部通常是一张圆角白色标题卡片。主内容区可以叠加柔和的应用内壁纸背景，背景经过透明度和模糊处理，不喧宾夺主。

左侧导航细节：

导航栏很窄，只有图标、没有文字。最上面是一个圆形的看板娘头像，下面是一条细分隔线，再往下竖排五个图标：画廊（图片框）、画册（书本）、源（拼图）、畅游（指南针）、运行配置（闹钟）。当前页面的图标块是粉紫渐变的圆角方块高亮。导航里没有「设置」「帮助」页——这两个页面已经不存在。如果漫画需要让读者看懂，可以在图标旁加极短的气泡文字，但不要把导航画成带文字的宽列表。

侧栏底部是 kamechan 的全身立绘，她站在侧栏和主内容区的交界处，身体一半压在侧栏上。点她会在旁边弹出一个圆角白色工具箱气泡：标题「你要做点什么？」，右上角一个「⚙ 设置」小按钮；下面分「维护」（整理、清理隐藏图片、检查更新）和「显示」（不显示画册图片、不显示隐藏图片两个开关）两组。设置就是从这里（或快捷键 ⌘,）打开的弹窗。

主内容区细节：

右侧主内容区占据大部分空间，页面顶部通常是标题卡片（左侧粉紫大标题，右侧几个白色小圆形按钮 + 一个紫色实心的任务抽屉按钮 + 可能有的粉紫主按钮），下面是主要内容。内容可能是画廊缩略图网格、画册树加图片网格、插件卡片网格、任务详情等。视觉上不要像浏览器网页，也不要像传统文件管理器，要像专门为二次元壁纸收藏设计的应用。画廊的图片为纯图，并没有什么额外的指示标志。

全局浮层：

可以出现半透明抽屉、弹窗或悬浮层，例如设置弹窗（大圆角弹窗，左侧分类、右侧设置行）、任务抽屉（从右侧滑出）、kamechan 工具箱气泡、收集弹窗、导入确认弹窗。按钮、开关、单选分段控件都是粉紫色的圆角风格。不要画「帮助抽屉」或「快速设置抽屉」，它们已经不存在。

看板娘互动建议：

看板娘可以站在左侧导航旁拿导游旗；可以从导航栏把用户带到画廊；也可以坐在主内容区边缘整理缩略图；也可以像真实应用里一样站在侧栏底部，抬手递出工具箱气泡。小乌龟壳背包精灵如果化为小乌龟助手，可以趴在左侧导航顶部的头像旁，像应用守护者；如果它仍是背包形态，就不要再画独立小乌龟。

避免：

不要把主框架画成网站 landing page。不要出现大面积营销 hero。不要让左侧导航消失，也不要把它画成带文字的宽导航。不要画出「设置」「帮助」导航项。不要把主内容区画成纯空白。

### Kabegame 源管理（插件）页布局

用途：

当漫画主题与插件商店、插件安装、插件自带 Provider 树、爬虫配置、插件源管理相关时使用。注意：主导航里这一页的名字是「源」，页面标题是「源管理」；「插件」这个词仍可在台词和插件小精灵的设定里使用。

源管理页结构：

左侧是窄图标主导航，「源」（拼图图标）高亮。右侧顶部是圆角白色标题卡片：左侧粉紫大标题「源管理」；右侧两个小圆形按钮：刷新、导入源（向上箭头）。

标题卡片下方一行：左侧是一组胶囊切换标签「已安装源 23」「官方 GitHub Releases 源 22」，末尾一个「+」（添加源）；选中的标签是粉紫渐变实心胶囊，数字是半透明小字。同一行最右侧是圆角搜索框「搜索源名称或站点」。

主体是六列的插件卡片网格。每张卡片是白底、粉色细描边的圆角方卡，内容居中、非常简洁：上方一个方形站点图标，下面是插件名（如「Pixiv」「konachan动漫壁纸」「米游社」「bilibili专栏」），再下面一行浅紫色等宽小字版本号（如「v1.3.2」）。卡片上没有简介、没有状态标签、也没有安装按钮——点卡片才进入详情。

插件 Provider 树视觉：

如果主题是插件自带 Provider 树，可以在「PathQL Provider」标签页里，或者在插件卡片背后画出自己的小路径树或小房间。插件们把“按标签、按角色、按站点、按排行”等路径挂到 Kabegame 的画廊和虚拟磁盘入口下。

看板娘互动建议：

看板娘可以像店长一样站在插件卡片之间；在「官方 GitHub Releases 源」里挑一张卡片点开；给插件盖“已安装”印章；把插件小工具包插入 Kabegame。小乌龟壳背包精灵如果化为小乌龟助手，可以拿着“配置项”表单或“插件源”地图。

# 才清零四小时就又敲门
漫画主题：插件更新会自己敲门

候选类型：有笑点小コント

为什么适合画：「图标上冒出小数字」是所有人都熟悉的更新提醒，配上「不兼容的插件乖乖不吵」「返回还在原地」这两个小体贴，适合画成插件小精灵排队敲门的轻松故事。

剧情角度：有笑点/小コント。kamechan 先去已安装 tab 找不到红点，又挡住插队的不兼容插件，好不容易清零角标，4 小时后挂钟一响，新数字又冒出来。

对应更新点：
- 插件商店在启动时刷新并每 4 小时自动更新；桌面侧栏的「源」拼图图标（紧凑端底部同样）显示可更新插件数量
- 源管理页商店源的 tab 上显示该源可更新的数量；已安装 tab 的卡片不再显示更新红点，更新提示统一到商店源 tab
- 不兼容当前应用版本的商店插件不再显示更新提示，导入或安装时后端也会在写入插件目录前拒绝
- 插件页当前所在的商店 tab 记录在地址栏，从插件详情返回时停留在原商店 tab，商店列表与图标不再重新加载

出场角色参考图（角色外观以参考图为准）：
- kamechan：4koma/chara/kamechan-sette.png
- 插件小精灵：4koma/chara/plugins-sette.png

```text
Kabegame 是基于 Tauri 的二次元壁纸爬取、管理、设置和轮播客户端，通过插件从 Pixiv、Konachan 等壁纸站点收集图片，插件在左侧导航「源」（拼图图标）里的源管理页安装和更新。本漫画主题：v4.6.0 的插件商店会在启动时和每 4 小时自动刷新，侧栏「源」图标直接显示可更新数量，商店源 tab 上也显示数量；更新提示只出现在商店源 tab，已安装 tab 不再挂红点；不兼容当前应用版本的插件不再提示更新、安装时也会被拒绝；从插件详情返回时还停在原来的商店 tab。

第 1 格，左上（开场）：Kabegame 桌面应用窗口，左侧窄图标导航（头像、画廊、画册、源、畅游、运行配置），主内容区是简化的画廊网格。窗口右上方悬着一个小圆形挂钟，表盘只写「4h」。侧栏「源」拼图图标右上角「啵」地弹出小红色数字角标「3」，样式和失败图片按钮的角标一致。kamechan 站在侧栏底部，双手握拳、眼睛闪亮，干劲十足。她背着乌龟壳背包，本格不出现独立小乌龟。

第 2 格，右上（展开）：源管理页，「已安装源」胶囊被选中，下面六列插件卡片（只有方形图标、短插件名、浅紫版本号）上一个红点都没有。kamechan 拿着放大镜趴在卡片上一张张找红点，满头问号。背包精灵化为小乌龟助手（kamechan 背上不再有壳），站在胶囊标签那一行，用小指挥棒指向旁边的「官方 GitHub Releases 源」胶囊——那个胶囊右上角正挂着角标「3」。乌龟表情无奈。

第 3 格，左下（转折）：切到商店源 tab，三张带红点的卡片后面的插件小精灵正排队往一个小门（视觉隐喻：插件目录）里走。队伍末尾，一只戴睡帽、抱着「向上箭头 + 应用小图标」牌子的插件小精灵（视觉隐喻：需要更新版的应用）也想偷偷插队；小乌龟助手戴着门卫帽，伸出小手掌拦住它，手里一枚印章刚盖在它的牌子上，印章图案是一个小叉。kamechan 在一旁流汗苦笑。

第 4 格，右下（オチ）：kamechan 刚从插件详情点「‹」返回，画面仍停在「官方 GitHub Releases 源」tab，卡片原地没动、没有加载转圈，所有红点都消失了，侧栏「源」图标的角标没有了。她坐在卡片网格边，捧着一杯热茶长舒一口气。可就在同一画面上方，「4h」挂钟的指针刚走过一圈、叮铃作响，侧栏「源」图标上又弹出一个新的角标「1」。kamechan 茶杯僵在嘴边、眼神呆滞；小乌龟助手在她身后憋笑。反差笑点：好不容易清零，商店自动刷新又把新更新送上门。

版本更新点必须画清楚：①商店启动时刷新并每 4 小时自动更新，侧栏「源」图标显示可更新数量；②商店源 tab 显示该源可更新数量，已安装 tab 不再挂更新红点；③不兼容当前应用版本的插件不显示更新提示，安装时被拒绝；④从插件详情返回时停留在原商店 tab，列表不重新加载。

避免项：不要把源管理页画成浏览器扩展商店；卡片上不要画简介、状态标签或安装按钮；不要在主导航画「插件」「设置」「帮助」文字项；挂钟、门卫、小门、印章、插件小精灵都是视觉隐喻，不要画成真实按钮；被拦下的插件小精灵要委屈可爱，不要画成坏蛋；角标数字要清楚，其余小字尽量少；同一格里不要同时出现乌龟壳背包和独立小乌龟。
```

整体目标：

生成日系二次元应用宣传四格漫画的单格画面。最终四格会被组装成 2x2 漫画，阅读顺序是左上、右上、左下、右下。每次只生成其中一格，画面要像画师为开源壁纸管理工具画的轻量更新公告，不要像 AI 自动堆满细节的插画。重点是角色表情、清楚的 UI 结构、短小的剧情推进、舒服的留白和可读的对白。

最终四格版式：

- 最终成品是 2x2 四格漫画，不是竖向长图。
- 阅读顺序固定为：第 1 格左上，第 2 格右上，第 3 格左下，第 4 格右下。
- 每格固定为横向 3:2，推荐生成尺寸为 1536x1024 px。
- 四张单格拼成最终 2x2 成品时，推荐总尺寸为 3072x2048 px，仍然保持 3:2。
- 四格尺寸必须一致，不要混用不同分辨率或不同裁切比例。
- 格子边框由拼图模板统一提供：单格画面本身不要画边框、圆角外框或白边，画面铺满到图片边缘。
- 每格只讲一个动作或一个小变化，不要在同一格塞多个时间点。
- 每格都要留出对白框位置，避免角色、UI、对白互相遮挡。

单格生成：

- 每次只生成一张单格画面，不要一次生成 2x2 四格。
- 单格画面本身使用 1536x1024 px，保持 3:2 横向比例，方便后期拼成 2x2。
- 单格不要画任何边框、圆角外框或白边（拼图模板会统一加上），也不要画出其他三格、草图或占位格。
- 当前要生成哪一格，以上方剧情里写明的「第 N 格，位置」为准，只画那一格的内容。
- 每一格单独生成时，都要保持同一套角色设计、色调、线稿和 UI 简化程度，让四张图拼在一起仍然像同一篇漫画。

基础视觉风格：

- 高质量日系 anime mascot comic。
- 干净线稿，线条有轻微手绘感，不要像矢量贴纸一样完全机械。
- 柔和 cel shading，阴影块面简单，最多两层阴影。
- 配色以粉紫、浅紫、淡奶油色为主，粉色和紫色都要出现。
- 因为主角偏紫，背景可以多放一点粉色，让画面更轻。
- 少量绿色作为乌龟主题点缀，不要把绿色变成主色。
- 整体清爽、明亮、轻松搞笑、治愈。
- 像软件更新公告小漫画，不像大型商业海报、游戏卡面、插画集封面。

绘画感控制：

画面要有真实绘画的取舍：

- 每格只保留 1 个主动作、1 个主要 UI 区域、1 到 3 个辅助小物。
- 背景允许有大块干净色面，不需要每个角落都有图标、粒子、花纹或光效。
- UI 图标只画关键图标，例如画廊、画册、插件、路径树、下载、收藏、缩略图、分页器。
- 缩略图网格可以概括成整齐小色块，不要每张缩略图都画成完整插画。
- 魔法特效只用细线、发光节点、小星点，数量少而清楚。
- 线稿可以有轻微粗细变化和少量不完全对称，保持自然手绘感。
- 不要过度锐化，不要超高密度装饰，不要满屏发光，不要把背景画成复杂机械城市。
- 不要让衣服、头发、UI、背景都同时有复杂渐变和复杂纹样。
- 画面应该像“画师画得很干净”，不是“模型不知道停在哪里”。

构图原则：

- 主角通常占每格高度的 45% 到 70%，不要被 UI 淹没。
- UI 是背景和剧情道具，不是完整截图。结构要清楚，但细节要简化。
- 应用窗口可以占画面后方或一侧，保留左侧导航、主内容区、工具栏或卡片网格的基本轮廓。
- 至少有一格让角色和 UI 产生明确互动，例如点开查询 chip、把缩略图放进画册树、给插件卡盖章。

对白和文字：

- 中文对白放在圆形或椭圆形对白框中。
- 字数要短，像四格漫画台词，不要长说明。
- 不要出现乱码、伪中文、密密麻麻的小字、长代码块、长 URL。

应用 UI 元素：

可以出现可爱的简化软件元素：

- 壁纸缩略图网格。
- 画册卡片、封面拼贴、小相册盒。
- 插件卡片、拼图图标、小工具包。
- Provider 路径树、查询 chip 条、翻页条、画册树。
- 下载进度、任务进度条、成功/失败小徽章。
- 收藏星标、导入按钮、设置滑杆、开关。

这些元素要像漫画道具，而不是完整真实截图。每格最多选择其中一到两类作为主视觉。

轻量魔法世界观：

Kabegame 应用可以像一座“壁纸魔法工坊”。魔法只是软件功能的可爱隐喻：

- 查询 chip 弹出的选项像发光路径节点。
- 画册像收纳盒或小房间。
- 插件像小工具包或插件小精灵。
- 任务像远征委托板。
- 设置像调律仪表。

避免项：

- 单格生成，不要一次生成 2x2 版式。
- 不要把阴影和高光做成厚重 3D 渲染。
- 不要画成过度精修的插画封面，保持轻松的漫画公告感。
- 不要在每张图角落里画序号，稍后会统一添加
- 不要给单格画边框、圆角外框或白边，边框由拼图模板统一添加。

最终输出要求：

1536x1024 px 单格横向漫画画面，最终可拼成 3072x2048 px 的 2x2 四格宣传漫画。柔和粉紫色调，画面铺满不带边框，干净线稿，轻量手绘感，应用 UI 简化可读，角色表情丰富，信息量适中，有留白，有短对白框。整体像 Kabegame 插件 provider trees 漫画的同系列作品。
