# Kabegame 发布日志漫画

## Kabegame 世界观

一个魔法异世界，Kabegame 应用界面像一座“壁纸魔法工坊”，左侧导航是通往不同房间的传送门，画廊是壁纸陈列大厅，画册是分类收集仓库，「源」页是召唤新壁纸的插件魔法小店，任务抽屉是远征委托板，设置弹窗是魔法调律室（从 kamechan 的工具箱里打开）。

看板娘kamechan(かめちゃん)是 Kabegame 的桌面守护者，也像工坊里的小管理员。她不会战斗，不会魔法，而是用温柔、实用、带一点俏皮的方式整理壁纸收藏。

她有一个小乌龟壳背包精灵搭档。它有两个形态，独立的小乌龟和背在背上的两种形态。平时它被背在看板娘背上，是可爱的小乌龟壳背包；需要帮忙时，它可以从背包形态化为小乌龟助手，拿路牌、盖章、推小车、举检查表、搬相册盒子、压住乱飞的刷新纸条。它的存在是治愈和轻松。

PathQL 魔女是 Kabegame 工坊里的“路径魔女”，是一个可爱、聪明、稍微有点小得意的魔女。她负责把复杂的壁纸数据变成可以走的路径，把画廊、画册、任务详情、插件和虚拟磁盘连接到同一套路径规则里。她会施展路径おまじない，让 Provider 过滤树发光、分页轨道对齐、插件入口自动接到正确房间。 她手里拿着路径魔法书、卷轴或发光路标，身边漂浮着 `/gallery`、`/albums`、`/plugins`、`fetch`、`count`、`children` 这类短路径符号。她的魔法特效应该是细细的路径线、发光节点、目录树、书签和小型传送门。

PathQL 魔女和 kamechan 的关系是帮忙整理工坊的伙伴。kamechan 负责整理壁纸收藏并可爱地展示它们，PathQL 魔女负责让背后的路径和规则稳定运转。两人同框时，看板娘更元气治愈，PathQL 魔女更理性、俏皮、像在说“路径已经安排好了”。

异世界魔法元素要轻量：

- Provider 过滤树可以像发光的魔法路径树。
- PathQL / DSL 可以像工坊里的路径咒文或目录魔法书。
- Provider 路径则像咒语。
- 插件是一个个呆萌可爱的小精灵，不同网站的插件有不同的配色。
- 画册可以像收纳宝箱、相册房间或轮播舞台。
- 任务可以像远征委托，进度条像魔法能量槽。
- 应用内背景图可以像把壁纸铺成舞台幕布。
- 设置项可以像调律仪表、滑杆和开关咒具。

现代软件 UI 占主体，魔法元素作为装饰和视觉隐喻。UI 结构必须清楚，不能被魔法特效遮住。整体氛围是“二次元开源壁纸工坊的一天”，轻松、治愈、带一点小コント。

## 页面布局设定

### Kabegame 移动端 / 紧凑布局

用途：

当漫画需要表现 Android 预览版、手机界面、窄屏窗口或移动端操作时使用。

整体结构：

移动端不使用左侧导航栏，而是在底部使用 Tab 栏。主内容区从顶部到下方铺满屏幕，底部 Tab 固定。顶部工具栏更紧凑，很多操作会变成图标按钮或抽屉。

底部 Tab：

底部 Tab 包含画廊、画册、插件、运行配置、设置等入口。图标在上，文字在下。当前 Tab 用紫色高亮。由于空间有限，帮助可能通过顶部问号按钮或抽屉进入。

移动端画廊：

画廊网格通常是两列或三列。搜索、筛选、排序、收集等按钮更紧凑，可能换行排列。点击收集时出现底部选择器，让用户选择本地导入或网络收集。图片预览占满屏幕，左右滑动切换。

移动端画册：

画册卡片更小，通常两列。新建画册、刷新、快速设置可以放在顶部图标按钮中。画册详情仍有图片 / 子画册标签页，但更紧凑。

移动端插件：

插件卡片以图标为主，名称短，版本和状态标签可能横向滚动或简化显示。安装按钮在卡片底部。插件详情像手机设置页一样纵向滚动。

移动端抽屉：

快速设置、帮助、收集配置、任务信息经常使用底部抽屉或全屏弹窗。底部抽屉有圆角顶部，内容是表单、按钮和列表。

看板娘互动建议：

看板娘可以变成小尺寸 chibi 形象，坐在手机屏幕边缘；小乌龟壳背包精灵如果化为小乌龟助手，可以趴在底部 Tab 上，指向当前页面。不要让角色遮挡底部 Tab 和核心网格。

避免：

不要在移动端画左侧导航。不要把底部 Tab 漏掉。不要让按钮文字过长挤出屏幕。不要把移动端画成桌面窗口缩小版。

### Kabegame 任务与运行配置布局

用途：

当漫画主题与爬虫任务、下载进度、失败重试、任务详情、自动运行配置、定时收集相关时使用。

任务抽屉结构：

任务抽屉是全局浮层，点任意页面标题卡片右侧那个紫色实心的清单板圆形按钮打开，从右侧滑出，背后页面被压暗。抽屉顶部标题「任务列表」。里面是两块圆角卡片分区：

- 「正在下载」：右上角黄色数字徽章；没有下载时中间是一个淡灰色空盒子图标和「暂无下载任务」；有下载时是一条条带进度条的下载项。
- 「任务列表」：右上角蓝色数字徽章；下面一行「共 40 个任务」和右侧「清除所有任务 (40)」；再下面是一张张任务卡片。

每张任务卡片：左侧插件方形图标，中间插件名（如「e-shuushuu」），名字下面一排图标计数（绿勾 成功数、红色感叹号 失败数、垃圾桶 删除数、叠层 去重数）；右上角状态胶囊（绿色「完成」或运行中）和一个圆形 ✕；底部左侧三个小标签按钮「参数」「图片」「日志」，右侧是时间（如「10/6 00:43」）。运行中的任务卡片会多一条进度条。

# 地板下的舞台升上来又降下去
漫画主题：主界面下层的小爬虫

候选类型：无笑点说明型短故事

为什么适合画：「看不见但一直在干活、需要时才浮上来」的上下两层结构，很适合画成主界面地板下的小舞台，用户一眼就能懂安卓也能跑 JS 插件了。

剧情角度：无笑点/说明型短故事。从选中 JS 插件开跑，到插件在主界面下层工作、浮上来过验证、收起后继续收集，完整讲清上下两层的运行方式。

对应更新点：
- Android 支持 JS（WebView）爬虫插件与网页收集的 WebView 后端：插件页面在应用内运行，停在主界面下层时照常执行定时器与滚动
- 插件调用 Kabegame.requestShowWebview() 或任务抽屉「打开窗口」可把插件页面从底部滑出到最上层手动操作（登录、过验证都可用），「收起」或返回键让它滑回下层，任务不中断
- Android 不再拒绝 JS 插件：插件选择器不再显示「需桌面浏览器 / 安卓不支持」警告，网页收集弹窗在安卓上恢复 WebView 后端

出场角色参考图（角色外观以参考图为准）：
- kamechan：4koma/chara/kamechan-sette.png
- 插件小精灵：4koma/chara/plugins-sette.png

```text
Kabegame 是基于 Tauri 的二次元壁纸爬取、管理、设置和轮播客户端，用插件从二次元壁纸站点收集图片。v4.6.0 起 Android 版不再拒绝 JS（WebView）爬虫插件：插件的网页在应用内运行，平时垫在主界面下层照常滚动、计时；需要登录或过验证时，插件自己请求或在任务抽屉点「打开窗口」，网页就从底部滑到最上层让人手动操作，按「收起」或返回键再滑回下层，任务不中断。本漫画主题就是这座「主界面下层的小舞台」。

本篇的画面通用设定：主要 UI 是一部竖握的 Android 手机，Kabegame 主界面是紧凑布局——顶部短标题栏，中间两列壁纸缩略图网格，底部固定 Tab 栏（图标在上、短字在下，当前 Tab 紫色高亮）。插件网页层用视觉隐喻表现：把手机画成略带透视的剖面，主界面是一块半透明的玻璃地板，地板下面还有一层舞台，舞台上是插件正在运行的网页（简化色块网页），由一只插件小精灵操作。插件小精灵是戴着彩色兜帽的圆滚滚小生物，兜帽颜色代表站点配色。

第 1 格，左上（开场）：kamechan 站在画格左侧，捧着手机。屏幕里是 Android 收集表单的底部圆角面板：顶部一个插件下拉框，显示一个拼图图标和短短的插件名，下方是一个粉紫渐变的「开始收集」按钮。下拉框旁边，一张写着「安卓不支持」的旧红色小贴纸正被剥落、飘出屏幕（视觉隐喻：本版移除了这条警告）。kamechan 手指按向「开始收集」，表情期待。她背着乌龟壳背包，本格不出现独立小乌龟。

第 2 格，右上（展开）：手机剖面图占画面中央偏右。上层玻璃地板是主界面画廊，两列缩略图和底部 Tab 都清楚；玻璃下面一层的小舞台上，插件小精灵正踩着一个小滚轮把网页往下滚，旁边一个小闹钟在滴答走（视觉隐喻：定时器与滚动照常执行），几张缩略图从舞台向上穿过玻璃，轻轻落进上层网格。kamechan 坐在手机边缘，弯腰透过玻璃往下看，惊讶又好奇。背包仍是背包形态。

第 3 格，左下（转折 / 进一步演示）：插件网页层像升降舞台一样从屏幕底部滑上来，盖到主界面最上层，网页中间是一个简化的验证框（一个勾选框轮廓和短字「验证」），网页顶部有一个小小的胶囊按钮「收起」。kamechan 伸出食指点勾选框，认真的表情。背包精灵此时化为小乌龟助手（kamechan 背上不再有壳），站在旁边举着一张任务卡片：卡片左侧插件图标、中间插件名和一条进度条、底部一个发光的小按钮「打开窗口」，表示是从任务抽屉把它叫上来的。插件小精灵在网页角落朝 kamechan 鞠躬。
```

整体目标：

生成日系二次元应用宣传四格漫画的单格画面。最终四格会被组装成 2x2 漫画，阅读顺序是左上、右上、左下、右下。每次只生成其中一格，画面要像画师为开源壁纸管理工具画的轻量更新公告，不要像 AI 自动堆满细节的插画。重点是角色表情、清楚的 UI 结构、短小的剧情推进、舒服的留白和可读的对白。

最终四格版式：

- 最终成品是 2x2 四格漫画，不是竖向长图。
- 阅读顺序固定为：第 1 格左上，第 2 格右上，第 3 格左下，第 4 格右下。
- 每格固定为横向 3:2，推荐生成尺寸为 1536x1024 px。
- 四张单格拼成最终 2x2 成品时，推荐总尺寸为 3072x2048 px，仍然保持 3:2。
- 四格尺寸必须一致，不要混用不同分辨率或不同裁切比例。
- 格子边框由拼图模板统一提供：单格画面本身不要画边框、圆角外框或白边，画面铺满到图片边缘。
- 每格只讲一个动作或一个小变化，不要在同一格塞多个时间点。
- 每格都要留出对白框位置，避免角色、UI、对白互相遮挡。

单格生成：

- 每次只生成一张单格画面，不要一次生成 2x2 四格。
- 单格画面本身使用 1536x1024 px，保持 3:2 横向比例，方便后期拼成 2x2。
- 单格不要画任何边框、圆角外框或白边（拼图模板会统一加上），也不要画出其他三格、草图或占位格。
- 当前要生成哪一格，以上方剧情里写明的「第 N 格，位置」为准，只画那一格的内容。
- 每一格单独生成时，都要保持同一套角色设计、色调、线稿和 UI 简化程度，让四张图拼在一起仍然像同一篇漫画。

基础视觉风格：

- 高质量日系 anime mascot comic。
- 干净线稿，线条有轻微手绘感，不要像矢量贴纸一样完全机械。
- 柔和 cel shading，阴影块面简单，最多两层阴影。
- 配色以粉紫、浅紫、淡奶油色为主，粉色和紫色都要出现。
- 因为主角偏紫，背景可以多放一点粉色，让画面更轻。
- 少量绿色作为乌龟主题点缀，不要把绿色变成主色。
- 整体清爽、明亮、轻松搞笑、治愈。
- 像软件更新公告小漫画，不像大型商业海报、游戏卡面、插画集封面。

绘画感控制：

画面要有真实绘画的取舍：

- 每格只保留 1 个主动作、1 个主要 UI 区域、1 到 3 个辅助小物。
- 背景允许有大块干净色面，不需要每个角落都有图标、粒子、花纹或光效。
- UI 图标只画关键图标，例如画廊、画册、插件、路径树、下载、收藏、缩略图、分页器。
- 缩略图网格可以概括成整齐小色块，不要每张缩略图都画成完整插画。
- 魔法特效只用细线、发光节点、小星点，数量少而清楚。
- 线稿可以有轻微粗细变化和少量不完全对称，保持自然手绘感。
- 不要过度锐化，不要超高密度装饰，不要满屏发光，不要把背景画成复杂机械城市。
- 不要让衣服、头发、UI、背景都同时有复杂渐变和复杂纹样。
- 画面应该像“画师画得很干净”，不是“模型不知道停在哪里”。

构图原则：

- 主角通常占每格高度的 45% 到 70%，不要被 UI 淹没。
- UI 是背景和剧情道具，不是完整截图。结构要清楚，但细节要简化。
- 应用窗口可以占画面后方或一侧，保留左侧导航、主内容区、工具栏或卡片网格的基本轮廓。
- 至少有一格让角色和 UI 产生明确互动，例如点开查询 chip、把缩略图放进画册树、给插件卡盖章。

对白和文字：

- 中文对白放在圆形或椭圆形对白框中。
- 字数要短，像四格漫画台词，不要长说明。
- 不要出现乱码、伪中文、密密麻麻的小字、长代码块、长 URL。

应用 UI 元素：

可以出现可爱的简化软件元素：

- 壁纸缩略图网格。
- 画册卡片、封面拼贴、小相册盒。
- 插件卡片、拼图图标、小工具包。
- Provider 路径树、查询 chip 条、翻页条、画册树。
- 下载进度、任务进度条、成功/失败小徽章。
- 收藏星标、导入按钮、设置滑杆、开关。

这些元素要像漫画道具，而不是完整真实截图。每格最多选择其中一到两类作为主视觉。

轻量魔法世界观：

Kabegame 应用可以像一座“壁纸魔法工坊”。魔法只是软件功能的可爱隐喻：

- 查询 chip 弹出的选项像发光路径节点。
- 画册像收纳盒或小房间。
- 插件像小工具包或插件小精灵。
- 任务像远征委托板。
- 设置像调律仪表。

避免项：

- 单格生成，不要一次生成 2x2 版式。
- 不要把阴影和高光做成厚重 3D 渲染。
- 不要画成过度精修的插画封面，保持轻松的漫画公告感。
- 不要在每张图角落里画序号，稍后会统一添加
- 不要给单格画边框、圆角外框或白边，边框由拼图模板统一添加。
